# 자동 벡터화 보고서 읽기

`saxpy`는 각 인덱스의 계산이 서로 독립적입니다. `recurrence`는 다음 반복이 이전 결과를 사용합니다. 두 반복문을 같은 파일에서 컴파일하고, 컴파일러가 어떤 판단을 내렸는지 진단 보고서와 어셈블리로 확인합니다.

```sh
make check
make report
make assembly
```

이 예제는 선택 학습 문서인 [SIMD, 벡터화와 데이터 배치](../../docs/04-parallel-execution/09-simd-vectorization-and-data-layout.md)와 함께 사용합니다.

## 구현 순서

| 순서 | 구현 단계 | 주요 위치 |
| ---: | --- | --- |
| 1 | 원소별 독립 연산 | `vector_sum.c::saxpy` |
| 2 | 반복 간 의존성 | `vector_sum.c::recurrence` |
| 3 | 최적화 뒤 결과 검사 | `vector_sum.c::main` |
| 4 | 컴파일러별 벡터화 근거 수집 | `report.sh::macros` |
| 5 | 동일한 최적화 조건 | `Makefile::$(TARGET)` |

`restrict`는 세 포인터로 접근하는 메모리 범위가 서로 겹치지 않는다는 규칙입니다. 호출자가 이 규칙을 어기면 동작이 정의되지 않으므로 단순한 성능 힌트처럼 추가해서는 안 됩니다.

보고서에서 `vectorized`라는 문장만 확인하지 않습니다. 대상 반복문, 사용한 벡터 폭, 남은 원소 처리, 정렬 조건, 실행 중 별칭 검사와 부동소수점 연산 순서 변경 여부를 어셈블리와 함께 확인해야 합니다.

검사 합계는 결과의 정확성을 확인하고, 컴파일러 보고서는 어떤 변환을 시도했는지 보여 줍니다. 두 근거는 서로 대신할 수 없습니다.
