# 점화식과 분할 정복

## 학습 목표

이 문서를 읽고 나면 다음을 할 수 있어야 합니다.

- 재귀 호출의 비용과 현재 호출이 수행하는 비재귀 작업을 분리해 점화식을 세웁니다.
- 재귀 호출 수, 각 하위 문제의 크기, 현재 호출의 작업량을 구분합니다.
- 전개, 재귀 tree, 치환, 마스터 정리를 적용 조건에 맞게 사용합니다.
- 분할·정복·결합 단계의 정확성과 비용을 각각 설명합니다.
- 불균형한 분할이 시간 복잡도와 재귀 깊이에 미치는 영향을 설명합니다.
- 모든 재귀 경로에서 문제가 실제로 작아지고 base case에 도달하는지 확인합니다.

## 선행지식

[점근 분석](02-asymptotic-analysis.md)에서 다음 내용을 이해해야 합니다.

- `O`, `Ω`, `Θ`의 의미
- `log n`, `n log n`, `n²` 등의 증가율 비교
- 재귀 호출이 더 작은 입력으로 진행되는 과정
- 재귀 stack도 공간 비용에 포함된다는 점

## 핵심 관점

재귀 알고리즘의 시간 비용은 다음처럼 나누어 생각합니다.

```text
T(현재 문제 크기)
=
하위 문제들을 푸는 총비용
+
현재 호출에서 수행하는 비재귀 작업
```

예를 들어 현재 문제 크기가 `n`이고, 크기 `n/2`인 하위 문제 두 개를 풀며 현재 호출에서 `Θ(n)`의 병합 작업을 한다면 다음과 같이 씁니다.

```text
T(n) = 2T(n/2) + Θ(n)
```

점화식(recurrence)은 코드의 재귀 호출 줄을 그대로 복사한 식이 아닙니다. 다음 세 가지를 정확히 표현해야 합니다.

```text
재귀 호출이 몇 개입니까?
각 하위 문제의 크기는 얼마입니까?
현재 호출 자체에서 얼마나 많은 작업을 합니까?
```

이 세 요소 중 하나라도 빠지면 실제 비용과 다른 점화식이 만들어질 수 있습니다.

## 1. 점화식의 구성 요소를 분리합니다

대표적인 형태는 다음과 같습니다.

```text
T(n) = a · T(n/b) + f(n)
```

각 항의 의미는 다음과 같습니다.

```text
n      : 현재 문제의 크기
a      : 생성하는 하위 문제의 개수
n / b  : 각 하위 문제의 크기
f(n)   : 현재 호출에서 수행하는 비재귀 작업의 비용
```

예를 들어 병합 정렬에서는

```text
a = 2
b = 2
f(n) = Θ(n)
```

이므로

```text
T(n) = 2T(n/2) + Θ(n)
```

입니다.

### base case도 점화식의 일부입니다

점화식은 재귀식만으로 완전하지 않습니다.

예를 들어 다음처럼 종료 조건도 함께 있어야 합니다.

```text
T(1) = Θ(1)
T(n) = 2T(n/2) + Θ(n),  n > 1
```

실제 구현에서는 `n`이 항상 정확히 2의 거듭제곱이 아닐 수 있습니다. 이런 경우 하위 문제 크기가 `⌊n/2⌋`, `⌈n/2⌉`가 될 수 있지만, 두 크기가 같은 차수라면 점근 분석에서는 보통 다음처럼 단순화할 수 있습니다.

```text
2T(n/2) + Θ(n)
```

단, 하위 문제 크기가 크게 불균형하다면 이렇게 단순화해서는 안 됩니다.

## 2. 대표적인 점화식

다음 표의 결과는 현재 호출의 작업과 하위 문제 구조를 함께 고려한 것입니다.

| 점화식 | 결과 | 대표 형태 |
| --- | --- | --- |
| `T(n)=T(n-1)+Θ(1)` | `Θ(n)` | 한 원소씩 줄어드는 재귀 |
| `T(n)=T(n/2)+Θ(1)` | `Θ(log n)` | 이분 탐색 |
| `T(n)=2T(n/2)+Θ(1)` | `Θ(n)` | 완전 이진 재귀 |
| `T(n)=2T(n/2)+Θ(n)` | `Θ(n log n)` | 병합 정렬 |
| `T(n)=T(n-1)+Θ(n)` | `Θ(n²)` | 매우 불균형한 분할 |
| `T(n)=T(n-1)+T(n-2)+Θ(1)` | 지수 증가 | naive Fibonacci 형태 |

### `2T(n/2)+Θ(1)`이 `Θ(n)`인 이유

각 level의 호출 수는 다음처럼 증가합니다.

```text
level 0: 1
level 1: 2
level 2: 4
...
```

재귀 깊이는 `Θ(log n)`이지만 leaf 수가 `Θ(n)`개입니다.

각 호출이 상수 시간 작업을 하므로 전체 호출 수에 비례해

```text
Θ(n)
```

이 됩니다.

따라서 재귀 깊이만 보고 시간 복잡도를 결정해서는 안 됩니다.

## 3. 전개로 점화식을 풉니다

전개(expansion)는 점화식을 반복해서 대입해 전체 패턴을 확인하는 방법입니다.

### 예제: `T(n)=T(n/2)+c`

다음과 같이 펼칩니다.

```text
T(n)
= T(n/2) + c

= T(n/4) + 2c

= T(n/8) + 3c

...

= T(n/2^k) + kc
```

재귀가 끝나는 시점은 문제 크기가 1이 되는 때입니다.

```text
n / 2^k = 1
```

따라서

```text
2^k = n
k = log₂ n
```

입니다.

결국

```text
T(n) = Θ(log n)
```

입니다.

### 예제: `T(n)=T(n-1)+Θ(n)`

다음처럼 펼칩니다.

```text
T(n)
= T(n-1) + cn

= T(n-2) + c(n-1) + cn

...

= T(1) + c(2 + 3 + ... + n)
```

합은

```text
Θ(n²)
```

이므로

```text
T(n)=Θ(n²)
```

입니다.

전개는 특히 `T(n-1)`처럼 마스터 정리를 바로 적용할 수 없는 점화식에 유용합니다.

## 4. 재귀 tree로 각 level의 총비용을 봅니다

재귀 tree는 각 재귀 호출을 tree의 node로 표현하고, 같은 깊이의 호출 비용을 합산하는 방법입니다.

예를 들어

```text
T(n)=2T(n/2)+cn
```

을 생각해 봅시다.

### level 0

호출은 하나입니다.

```text
문제 크기: n
비재귀 작업: cn
level 비용: cn
```

### level 1

크기 `n/2`인 호출이 두 개입니다.

각 호출의 비재귀 작업은

```text
c(n/2)
```

이고 두 호출의 합은

```text
2 · c(n/2) = cn
```

입니다.

### level 2

크기 `n/4`인 호출이 네 개입니다.

```text
4 · c(n/4) = cn
```

역시 level 전체 비용은 `cn`입니다.

따라서 각 level의 비용은 모두

```text
Θ(n)
```

입니다.

재귀 깊이는

```text
Θ(log n)
```

이므로 전체 비용은

```text
Θ(n) × Θ(log n)
= Θ(n log n)
```

입니다.

### 재귀 tree에서 확인할 세 가지

항상 다음을 확인합니다.

1. 재귀 깊이는 몇 단계입니까?
2. 각 level에 호출이 몇 개 있습니까?
3. 각 호출의 작업량을 합치면 level 전체 비용은 얼마입니까?

"깊이가 `log n`이므로 `O(log n)`"이라고 바로 결론 내리면 전체 호출 수나 각 level의 작업량을 놓칠 수 있습니다.

## 5. 치환으로 결과를 검증합니다

치환(substitution)은 예상한 복잡도 경계를 점화식에 대입해 실제로 성립하는지 확인하는 방법입니다.

예를 들어

```text
T(n)=2T(n/2)+cn
```

에 대해

```text
T(n)=O(n log n)
```

이라고 예상했다고 합시다.

충분히 큰 `n`에서 어떤 상수 `C`에 대해

```text
T(n) <= Cn log n
```

이라고 가정합니다.

그러면

```text
T(n)
<= 2 · C(n/2) log(n/2) + cn
```

이고,

```text
= Cn(log n - 1) + cn
= Cn log n - Cn + cn
```

입니다.

`C >= c`가 되도록 선택하면

```text
-Cn + cn <= 0
```

이므로

```text
T(n) <= Cn log n
```

을 유지할 수 있습니다.

실제 엄밀한 증명에서는 base case와 충분히 큰 `n`의 범위를 함께 확인해야 하지만, 핵심 목적은 **추측한 경계가 재귀식과 모순되지 않는지 확인하는 것**입니다.

## 6. 마스터 정리는 적용 조건을 먼저 확인합니다

마스터 정리는 흔히 다음 형태의 점화식에 사용합니다.

```text
T(n) = aT(n/b) + f(n)
```

여기서

```text
a >= 1
b > 1
```

이고 하위 문제 크기가 대체로 균등하게 줄어드는 구조를 가정합니다.

핵심 비교 대상은 다음입니다.

```text
n^(log_b a)
```

이 값은 재귀 tree에서 leaf 쪽으로 내려갈 때 생기는 재귀 호출 구조의 기준 증가율입니다.

### 마스터 정리를 쓰기 전에 확인할 것

다음을 먼저 확인합니다.

- 하위 문제 크기가 실제로 거의 균등합니까?
- 하위 문제 개수 `a`가 입력 크기에 따라 달라지지 않습니까?
- 축소 비율 `b`가 일정한 형태입니까?
- `f(n)`에 분할·전처리·결합 등 현재 호출의 비재귀 작업이 모두 포함되어 있습니까?
- 점화식이 정말 `aT(n/b)+f(n)` 형태입니까?

다음과 같은 식에는 기본적인 마스터 정리를 그대로 적용하면 안 됩니다.

```text
T(n)=T(n-1)+Θ(n)
```

또는

```text
T(n)=T(n/3)+T(2n/3)+Θ(n)
```

처럼 하위 문제 크기가 서로 다른 경우도 기본 형태와 다릅니다.

이런 경우 전개, 재귀 tree, 치환 또는 다른 정리를 사용합니다.

### 공식을 적용한 뒤 직관과 비교합니다

공식을 사용한 뒤에는 간단한 전개나 재귀 tree로 결과가 자연스러운지 확인하는 것이 좋습니다.

예를 들어

```text
T(n)=2T(n/2)+Θ(n)
```

에서는

```text
각 level 비용: Θ(n)
level 수: Θ(log n)
```

이므로 `Θ(n log n)`이라는 결과와 일치합니다.

## 7. 분할 정복은 세 단계로 나눠 봅니다

분할 정복(divide and conquer)은 큰 문제를 작은 같은 형태의 문제로 나누어 푸는 설계 방식입니다.

보통 다음 세 단계로 설명합니다.

```text
분할(divide)
원래 문제를 더 작은 하위 문제로 나눕니다.

정복(conquer)
각 하위 문제를 재귀적으로 풉니다.

결합(combine)
하위 문제의 결과를 이용해 원래 문제의 결과를 만듭니다.
```

### 좋은 분할이 만족해야 하는 조건

다음을 확인합니다.

- 각 하위 문제는 원래 문제와 같은 종류의 문제입니까?
- 모든 재귀 호출에서 문제 크기가 엄격히 줄어듭니까?
- 하위 문제들이 원래 문제의 필요한 경우를 빠짐없이 포함합니까?
- 같은 경우를 불필요하게 여러 번 계산하지 않습니까?
- 하위 결과만으로 원래 결과를 올바르게 만들 수 있습니까?
- 분할과 결합 비용이 지나치게 커서 재귀 분할의 이점을 없애지 않습니까?

분할 정복의 정확성은 단순히 "재귀 호출이 있다"로 설명되지 않습니다.

다음 두 가지를 모두 설명해야 합니다.

```text
하위 문제를 올바르게 풀었다고 가정하면
→ 결합 단계가 원래 문제의 올바른 답을 만드는가?

재귀 호출은
→ 결국 더 작은 문제를 거쳐 base case에 도달하는가?
```

## 8. 예제: inversion 개수

정수 배열 `A`에서 다음 조건을 만족하는 index 쌍 `(i, j)`를 inversion이라고 합니다.

```text
i < j
A[i] > A[j]
```

예를 들어

```text
A = [3, 1, 2]
```

에서는 다음 두 inversion이 있습니다.

```text
(0, 1): 3 > 1
(0, 2): 3 > 2
```

따라서 inversion 개수는 `2`입니다.

### 단순 방법

모든 index 쌍을 직접 비교하면

```text
Θ(n²)
```

입니다.

### 분할 정복 방법

배열을 왼쪽 절반과 오른쪽 절반으로 나누면 inversion은 정확히 다음 세 종류 중 하나에 속합니다.

1. 두 index가 모두 왼쪽 절반에 있음
2. 두 index가 모두 오른쪽 절반에 있음
3. `i`는 왼쪽 절반, `j`는 오른쪽 절반에 있음

첫 번째와 두 번째는 재귀 호출이 셉니다.

세 번째는 두 절반을 정렬된 상태로 병합하면서 셉니다.

### 가로지르는 inversion을 세는 이유

정렬된 두 절반이 다음과 같다고 합시다.

```text
left  = [2, 5, 8]
right = [1, 6]
```

병합 중 현재 값이

```text
left[i] = 2
right[j] = 1
```

이라면 `1`은 `2`보다 작습니다.

왼쪽 배열은 정렬되어 있으므로 `2` 뒤에 남아 있는 값들도 모두 `1`보다 큽니다.

```text
2 > 1
5 > 1
8 > 1
```

따라서 오른쪽의 현재 값 `1`은 왼쪽에 남은 모든 원소와 inversion을 만듭니다.

왼쪽에 남은 원소 수를 한 번에 더하면 각 쌍을 개별적으로 비교할 필요가 없습니다.

### 정확성

각 inversion은 위치 관계에 따라 정확히 다음 중 하나입니다.

```text
왼쪽 내부
오른쪽 내부
두 절반을 가로지름
```

이 세 경우는 서로 겹치지 않고 모든 inversion을 포함합니다.

따라서 각 범주를 정확히 세면 전체 inversion도 정확히 한 번씩 셀 수 있습니다.

### 비용

두 절반의 inversion을 재귀적으로 계산하고, 병합하면서 가로지르는 inversion을 `Θ(n)`에 셉니다.

```text
T(n)=2T(n/2)+Θ(n)
```

따라서

```text
T(n)=Θ(n log n)
```

입니다.

## 9. 분할 비용과 결합 비용을 빠뜨리지 않습니다

재귀 호출 자체만 세면 실제 비용을 과소평가할 수 있습니다.

예를 들어 다음과 같은 분할 정복 알고리즘이 있다고 합시다.

```text
배열을 절반으로 복사해 두 새 배열 생성
왼쪽 재귀 호출
오른쪽 재귀 호출
두 결과를 병합
```

하위 문제는 두 개지만, 현재 호출에서 배열을 복사하고 병합하는 작업도 발생합니다.

따라서 단순히

```text
T(n)=2T(n/2)
```

라고 쓰면 잘못입니다.

실제 현재 호출 작업이 선형이라면

```text
T(n)=2T(n/2)+Θ(n)
```

이 됩니다.

다음 작업을 놓치기 쉽습니다.

- 하위 배열 복사
- pivot 선택과 partition
- 두 결과 merge
- 결과 배열 생성
- 문자열 연결
- 하위 결과 전체 순회
- 보조 배열 초기화

---

## 10. 불균형한 분할은 시간과 stack 깊이를 악화시킬 수 있습니다

모든 분할 정복 알고리즘이 균형 있게 나뉘는 것은 아닙니다.

quicksort를 예로 들어 봅시다.

### 균형 잡힌 분할

partition 결과가 대략

```text
n/2
n/2
```

로 나뉜다면 점화식은 대략

```text
T(n)=2T(n/2)+Θ(n)
```

이고

```text
Θ(n log n)
```

입니다.

재귀 깊이도 대략

```text
Θ(log n)
```

입니다.

### 극단적으로 불균형한 분할

매번 다음처럼 나뉜다면

```text
0
n-1
```

실제로 의미 있는 재귀 호출은 크기 `n-1` 하나입니다.

점화식은

```text
T(n)=T(n-1)+Θ(n)
```

이고 전개하면

```text
Θ(n²)
```

입니다.

재귀 깊이도

```text
Θ(n)
```

까지 커질 수 있습니다.

따라서 불균형한 분할은 시간뿐 아니라 재귀 stack 공간도 악화시킬 수 있습니다.

---

## 11. 평균·기대·최악 분할을 구분합니다

quicksort에 대해 흔히 다음과 같은 설명을 볼 수 있습니다.

```text
평균 O(n log n)
최악 O(n²)
```

하지만 "평균"이라는 표현은 어떤 확률을 기준으로 하는지 명확히 해야 합니다.

### 입력 분포에 대한 평균

입력이 어떤 확률 분포에서 주어진다고 가정하고 비용의 평균을 구하는 경우입니다.

예를 들어 모든 permutation이 같은 확률로 들어온다고 가정할 수 있습니다.

### 알고리즘 내부 무작위성에 대한 기대

randomized quicksort처럼 pivot을 무작위로 고르는 경우에는 고정된 입력에 대해서도 알고리즘 자체의 난수 선택에 따라 실행 시간이 달라집니다.

이때

```text
기대 O(n log n)
```

은 입력이 랜덤하다는 뜻이 아니라 **알고리즘 내부 무작위성에 대한 기댓값**일 수 있습니다.

따라서 다음 두 문장을 구분해야 합니다.

```text
랜덤 입력에서의 평균 비용
무작위 pivot 선택에 대한 기대 비용
```

최악 비용이 `O(n²)`이라는 사실도 별도로 유지해야 합니다.

## 12. 종료 조건을 비용 분석과 별도로 확인합니다

재귀 함수에 base case가 존재한다는 사실만으로는 종료가 보장되지 않습니다.

예를 들어 다음 코드를 생각해 봅시다.

```text
f(n):
    if n == 0:
        return
    f(n + 1)
```

base case는 있지만 `n > 0`에서 문제 크기가 오히려 증가하므로 `n == 0`에 도달하지 않습니다.

### 감소하는 값(variant)을 찾습니다

모든 재귀 호출에서 줄어드는 음이 아닌 정수값을 찾으면 종료를 설명하기 쉽습니다.

예를 들면 다음과 같습니다.

- 배열 길이
- 처리할 구간 길이
- 남은 원소 수
- 아직 처리하지 않은 정점 수
- 남은 문자열 길이
- 아직 확장하지 않은 유한 상태 수

다음 두 조건을 모두 확인합니다.

```text
모든 재귀 호출에서 값이 엄격히 감소합니다.
값은 음수가 될 수 없으므로 유한 번 후 최소값에 도달합니다.
```

이 최소값에서 base case가 실행되어야 합니다.

### 여러 재귀 호출이 있으면 모든 경로를 확인합니다

다음과 같은 코드가 있다고 합시다.

```text
solve(n):
    solve(n - 1)
    solve(n)
```

첫 번째 호출은 작아지지만 두 번째 호출은 문제 크기가 줄지 않습니다.

따라서 일부 경로에서 감소한다는 사실만으로는 충분하지 않습니다.

**모든 재귀 호출**에서 종료를 보장하는 감소 조건이 필요합니다.

---

## 13. 종료와 정확성을 분리해서 설명합니다

재귀 알고리즘을 검증할 때 다음 두 질문은 서로 다릅니다.

### 종료

```text
재귀 호출이 유한 번 안에 끝나는가?
```

### 부분 정확성

```text
재귀 호출들이 올바른 결과를 반환한다고 가정했을 때
현재 호출도 올바른 결과를 만드는가?
```

두 조건을 합치면 전체 알고리즘의 정확성을 설명할 수 있습니다.

분할 정복에서는 보통 다음 구조로 설명합니다.

```text
base case:
가장 작은 문제에서 결과가 직접 올바릅니다.

귀납 가정:
더 작은 하위 문제의 재귀 호출은 올바른 결과를 반환한다고 가정합니다.

결합:
하위 결과를 이용해 현재 문제의 모든 경우를
빠짐없이, 중복 없이, 올바르게 계산합니다.

종료:
각 하위 문제 크기가 엄격히 줄어들어 결국 base case에 도달합니다.
```

이 구조는 inversion 개수, merge sort, binary search 등 많은 재귀 알고리즘의 설명에 사용할 수 있습니다.

## 14. 같은 하위 문제를 반복 계산하는지 확인합니다

분할 정복처럼 보여도 서로 독립적인 하위 문제로 잘 나뉘지 않는 경우가 있습니다.

대표적인 예가 naive Fibonacci입니다.

```text
F(n) = F(n-1) + F(n-2)
```

재귀 호출 tree를 보면 같은 값이 여러 번 계산됩니다.

예를 들어 `F(5)`를 계산할 때

```text
F(3)
F(2)
```

같은 하위 문제가 서로 다른 경로에서 반복해서 등장합니다.

점화식은 대략

```text
T(n)=T(n-1)+T(n-2)+Θ(1)
```

형태이며 실행 시간은 지수적으로 증가합니다.

여기서는 하위 문제들이 서로 겹치므로, 결과를 저장하는 memoization이나 bottom-up dynamic programming으로 반복 계산을 제거할 수 있습니다.

이 문서의 핵심은 동적 계획법 자체가 아니라, **재귀 tree를 통해 같은 하위 문제를 반복 계산하고 있는지 확인하는 것**입니다.

## 연결 구현

[`verified-algorithms`](../../exercises/verified-algorithms/)에서 재귀와 하위 문제 결합을 다음과 같이 확인합니다.

### `red_black_height`

왼쪽 subtree와 오른쪽 subtree의 검증 결과를 재귀적으로 구한 뒤 현재 node에서 결합합니다.

확인할 핵심은 다음과 같습니다.

```text
각 subtree 결과가 무엇을 보장하는가?
현재 node가 두 결과를 어떻게 결합하는가?
모든 재귀 호출에서 subtree 크기가 줄어드는가?
```

### `lcs_length`

두 문자열 prefix에 대한 더 작은 하위 문제 결과를 이용해 현재 값을 계산합니다.

여기서는 하위 문제 크기가 두 변수로 표현됩니다.

```text
i = 첫 번째 문자열의 prefix 길이
j = 두 번째 문자열의 prefix 길이
```

따라서 분석할 때 무조건 하나의 `n`으로 합치기보다 두 입력 크기의 관계를 유지하는 것이 좋습니다.

### 테스트의 `brute_lcs_length`

부분수열 상태 공간을 직접 탐색하는 brute-force 기준 계산은 작은 입력에서만 사용합니다.

부분수열 수가 길이 `n`에 대해

```text
2^n
```

까지 증가할 수 있기 때문입니다.

이는 점화식이나 재귀 tree에서 지수적으로 커지는 상태 공간이 실제 입력 제한에 어떤 영향을 주는지 확인하는 예입니다.

exercise에는 merge sort가 포함되어 있지 않으므로 inversion 개수 세기는 별도의 작은 구현으로 확인하는 편이 좋습니다.

재귀 알고리즘을 분석할 때 다음 순서로 확인합니다.

```text
1. 현재 문제의 크기를 정의합니다.

3. 각 하위 문제의 크기를 적습니다.
4. 현재 호출의 비재귀 작업 비용을 계산합니다.

6. 점화식을 세웁니다.
7. 전개·재귀 tree·치환·마스터 정리 중 적절한 방법을 선택합니다.
8. 선택한 방법의 적용 전제를 확인합니다.
9. 최악의 재귀 깊이를 계산합니다.
10. 모든 재귀 경로에서 문제가 실제로 작아지는지 확인합니다.
11. 하위 결과가 원래 문제의 모든 경우를 빠짐없이 포함하는지 확인합니다.

```

## 완료 기준

다음을 모두 설명할 수 있으면 이 문서의 핵심을 이해한 것입니다.

- 재귀 호출 수, 하위 문제 크기, 현재 호출의 비재귀 작업을 따로 적습니다.
- base case를 포함한 점화식을 작성합니다.
- 전개, 재귀 tree, 치환, 마스터 정리 중 적절한 방법을 선택합니다.
- 마스터 정리를 적용할 수 있는 형태인지 먼저 확인합니다.
- 분할·정복·결합 단계 각각의 역할과 비용을 설명합니다.
- 균형 분할과 불균형 분할의 시간 및 stack 깊이 차이를 설명합니다.
- 평균 비용과 알고리즘 내부 무작위성에 대한 기대 비용을 구분합니다.
- 모든 재귀 경로에서 감소하는 음이 아닌 정수값을 찾고 base case 도달을 설명합니다.
- 하위 결과가 원래 문제의 모든 경우를 빠짐없이 한 번씩 포함하는지 설명합니다.

## 실패 신호

다음 중 하나라도 해당하면 분석을 다시 확인해야 합니다.

- 하위 문제의 크기를 쓰지 않고 재귀 호출 횟수만 셉니다.
- 현재 호출의 분할·복사·결합 비용을 누락합니다.
- base case 없이 재귀식만 적습니다.
- 재귀 깊이만 보고 전체 시간 복잡도를 결정합니다.
- 마스터 정리를 `T(n-1)`에 적용합니다.
- 서로 다른 크기의 하위 문제를 억지로 `aT(n/b)` 형태로 바꿉니다.
- 평균적으로 균형 잡힌 분할을 최악 보장처럼 표현합니다.
- randomized 알고리즘의 기대 비용과 입력 분포에 대한 평균 비용을 같은 뜻으로 사용합니다.
- base case는 있지만 일부 재귀 호출에서 문제 크기가 줄지 않습니다.
- 분할된 경우들이 원래 문제의 모든 경우를 포함하는지 설명하지 못합니다.
- 같은 경우를 여러 하위 문제에서 중복 계산하고도 이를 인식하지 못합니다.
