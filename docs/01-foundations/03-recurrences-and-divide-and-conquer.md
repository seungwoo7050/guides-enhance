# 점화식과 분할 정복

## 학습 목표

- 재귀 호출의 비용과 현재 호출이 수행하는 작업을 분리해 점화식을 세웁니다.
- 전개, 재귀 tree, 치환, 마스터 정리를 적용 조건에 맞게 사용합니다.
- 분할·재귀 호출·결합의 정확성과 비용을 각각 설명합니다.
- 불균형한 분할과 최악의 재귀 깊이를 식별합니다.

## 선행지식

[점근 분석](02-asymptotic-analysis.md)의 증가율 비교와 재귀 호출이 더 작은 입력으로 진행되는 과정을 설명할 수 있어야 합니다.

## 핵심 관점

재귀 비용은 다음 형태로 나눕니다.

```text
T(현재 문제 크기) = 하위 문제의 총비용 + 현재 호출의 비재귀 작업
```

점화식은 코드 모양을 그대로 옮긴 식이 아닙니다. 입력 크기가 어떻게 줄고 어떤 작업이 각 단계에서 반복되는지를 나타냅니다.

## 1. 대표적인 점화식

| 점화식 | 결과 | 대표 형태 |
| --- | --- | --- |
| `T(n)=T(n-1)+Θ(1)` | `Θ(n)` | 한 원소씩 줄어듭니다. |
| `T(n)=T(n/2)+Θ(1)` | `Θ(log n)` | 이분 탐색 |
| `T(n)=2T(n/2)+Θ(1)` | `Θ(n)` | 완전 이진 재귀 |
| `T(n)=2T(n/2)+Θ(n)` | `Θ(n log n)` | 병합 정렬 |
| `T(n)=T(n-1)+T(n-2)+Θ(1)` | 지수 증가 | 같은 하위 문제를 반복 계산합니다. |

## 2. 전개와 재귀 tree

`T(n)=T(n/2)+c`를 반복해서 펼치면 문제 크기가 1이 될 때까지 약 `log₂ n`단계가 필요하므로 `Θ(log n)`입니다.

`T(n)=2T(n/2)+cn`에서는 각 단계의 비재귀 작업 합이 `cn`이고 단계 수가 `Θ(log n)`이므로 전체는 `Θ(n log n)`입니다.

재귀 tree를 그릴 때는 다음 세 가지를 확인합니다.

1. 단계 수
2. 각 단계의 호출 수
3. 각 호출의 작업량과 단계 전체의 합

## 3. 마스터 정리를 억지로 적용하지 않습니다

`T(n)=aT(n/b)+f(n)` 형태처럼 보여도 다음을 먼저 확인합니다.

- 하위 문제 크기가 실제로 거의 균등합니까?
- `a`와 `b`가 입력에 따라 달라지지 않습니까?
- `f(n)`에 분할과 결합의 모든 작업이 포함되어 있습니까?
- `T(n-1)`이나 서로 다른 크기의 하위 문제를 억지로 같은 식에 넣고 있지 않습니까?

공식을 적용한 뒤에는 간단한 전개나 재귀 tree로 증가율이 맞는지 다시 확인합니다.

## 4. 분할 정복의 세 단계

```text
분할: 원래 문제를 더 작은 하위 문제로 나눕니다.
정복: 각 하위 문제를 재귀적으로 풉니다.
결합: 하위 문제의 결과로 원래 문제의 결과를 만듭니다.
```

좋은 분할은 다음 조건을 만족해야 합니다.

- 각 하위 문제가 원래 문제와 같은 형태의 입력을 받습니다.
- 모든 재귀 호출에서 문제 크기가 엄격히 줄어듭니다.
- 하위 결과만으로 원래 결과를 계산할 수 있습니다.
- 분할과 결합 비용이 재귀 호출로 얻는 이점을 없애지 않습니다.

## 5. 예제: inversion 개수

정수 배열에서 `i < j`이면서 `A[i] > A[j]`인 쌍을 셉니다.

모든 쌍을 비교하면 `Θ(n²)`입니다. 병합 정렬을 사용하면 다음 세 종류의 쌍을 따로 셀 수 있습니다.

1. 왼쪽 절반 안의 inversion
2. 오른쪽 절반 안의 inversion
3. 두 절반을 가로지르는 inversion

정렬된 두 절반을 병합할 때 오른쪽 현재 값이 왼쪽 현재 값보다 작다면, 왼쪽에 남은 모든 값과 inversion을 만듭니다.

```text
T(n)=2T(n/2)+Θ(n)=Θ(n log n)
```

각 inversion은 위 세 분류 중 정확히 하나에 속하므로 중복 없이 셀 수 있습니다.

## 6. 불균형한 분할

quicksort의 partition이 매번 크기 `0`과 `n-1`로 나뉘면 다음과 같습니다.

```text
T(n)=T(n-1)+Θ(n)=Θ(n²)
```

평균 또는 기대 `O(n log n)`이라는 주장과 최악 `O(n²)`이라는 주장을 구분합니다. pivot을 무작위로 고를 때의 기대 비용은 입력 분포가 아니라 알고리즘 내부 무작위성에 대한 값일 수 있습니다.

## 7. 종료도 별도로 확인합니다

재귀 함수에 base case가 있다는 사실만으로는 종료를 보장하지 않습니다. 모든 호출에서 음이 아닌 정수값이 줄어드는지 확인합니다.

- 배열 길이가 줄어듭니다.
- 구간 길이가 줄어듭니다.
- 아직 처리하지 않은 정점 수가 줄어듭니다.
- 유한한 상태 중 이미 방문한 상태를 다시 확장하지 않습니다.

감소량이 음수가 되지 않고 결국 base case에 도달하는지도 설명해야 합니다.

## 연결 구현

[`verified-algorithms`](../../exercises/verified-algorithms/)에서 재귀와 하위 문제 결합을 다음과 같이 확인합니다.

- `red_black_height`: 왼쪽과 오른쪽 subtree의 검증 결과를 결합합니다.
- `lcs_length`: 두 prefix의 하위 문제 결과로 현재 값을 계산합니다.
- 테스트의 `brute_lcs_length`: 부분수열 상태 공간의 크기를 `2^n`으로 제한해 작은 입력에만 사용합니다.

exercise에는 merge sort가 포함되어 있지 않으므로 inversion 개수 세기는 별도 작은 구현으로 확인하는 편이 좋습니다.

## 완료 기준

- 재귀 호출 수, 하위 문제 크기, 결합 비용을 따로 적습니다.
- 선택한 방법으로 점근 비용을 계산하고 적용 전제를 확인합니다.
- 모든 재귀 경로에서 감소하는 정수값과 base case 도달을 설명합니다.
- 하위 결과가 원래 문제의 모든 경우를 빠짐없이 한 번씩 포함하는지 설명합니다.

## 실패 신호

- 하위 문제의 크기를 쓰지 않고 호출 횟수만 셉니다.
- 결합 비용을 누락합니다.
- 마스터 정리를 `T(n-1)`에 적용합니다.
- 평균적으로 균형 잡힌 분할을 최악 보장처럼 표현합니다.
- base case는 있지만 문제 크기가 줄지 않습니다.
