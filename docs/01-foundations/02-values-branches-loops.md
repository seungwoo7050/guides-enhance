# 값·분기·반복

프로그램은 입력을 값으로 바꾸고, 조건에 따라 다른 코드를 실행하며, 같은 작업을 여러 번 반복합니다. 이 과정에서 중요한 것은 문법을 외우는 것보다 **각 값이 어떤 타입과 범위를 가지는지, 조건이 무엇을 검사하는지, 반복할 때 어떤 조건이 계속 유지되어야 하는지** 이해하는 것입니다.

C의 정수 연산에서는 타입에 따라 표현 가능한 범위와 변환 규칙이 달라집니다. 특히 부호 있는 정수와 부호 없는 정수를 섞어 사용하면 소스 코드만 보고 예상한 것과 다른 비교 결과가 나올 수 있습니다. 반복문에서는 배열 인덱스의 유효 범위와 종료 조건을 함께 생각해야 합니다.

## 정수 타입과 범위

```c
int count = 0;
long total = 0;
size_t length = 0;
```

각 타입은 보통 다음 용도로 사용합니다.

- `int`: 일반적인 정수 계산, 상태 값, 함수 반환값 등에 자주 사용합니다.
- `long`: `int`보다 작지 않은 정수 변환 순위를 가지며 최소 표현 범위도 `int`보다 작지 않습니다. 그러나 **모든 환경에서 `int`보다 실제 비트 폭이 더 넓다는 보장은 없습니다**.
- `size_t`: `sizeof` 연산 결과의 타입이며, 객체의 크기와 배열·버퍼의 원소 개수처럼 음수가 될 수 없는 크기 값을 표현할 때 사용합니다. 부호 없는 정수 타입입니다.

C는 `int`, `long` 등의 정확한 비트 수를 고정하지 않습니다. 따라서 같은 C 프로그램이라도 환경에 따라 타입의 폭이 다를 수 있습니다.

예를 들어 다음과 같은 관계는 일반적이지만 모든 환경에서 동일하지는 않습니다.

```text
int   → 흔히 32비트
long  → 어떤 환경에서는 32비트, 어떤 환경에서는 64비트
```

정확한 범위가 필요하면 표준 헤더가 제공하는 매크로를 사용합니다.

```c
#include <limits.h>
#include <stdint.h>
```

대표적인 매크로는 다음과 같습니다.

```text
INT_MIN
INT_MAX
LONG_MIN
LONG_MAX
SIZE_MAX
```

예를 들어 `long`의 최댓값을 코드에 직접 숫자로 적기보다 다음처럼 사용합니다.

```c
if (value > LONG_MAX) {
    /* ... */
}
```

다만 `value`의 타입이 이미 `long`이라면 `LONG_MAX`보다 큰 값을 가질 수 없으므로, 실제 범위 검사는 보통 **더 넓은 타입의 값이나 문자열 입력을 `long`으로 변환하는 과정**에서 필요합니다.

정확히 32비트 또는 64비트인 정수 타입이 필요한 경우에는 `<stdint.h>`의 `int32_t`, `uint64_t` 같은 고정 폭 타입을 사용할 수 있습니다. 이러한 타입은 해당 폭을 정확히 지원하는 구현에서 제공됩니다.

## 부호 있는 값과 부호 없는 값

C에서는 서로 다른 정수 타입끼리 연산하거나 비교할 때 **일반적인 산술 변환(usual arithmetic conversions)**이 적용됩니다. 이 과정에서 한쪽 값의 타입이 다른 쪽에 맞게 변환될 수 있습니다.

특히 부호 있는 정수와 부호 없는 정수를 비교하면, 부호 있는 값이 부호 없는 타입으로 변환되는 경우가 있습니다.

```c
int index = -1;
size_t length = 10;

if (index < length) {
    /* 예상과 다른 결과가 나올 수 있습니다. */
}
```

많은 환경에서 이 비교를 수행할 때 `index`의 `-1`이 `size_t`와 호환되는 부호 없는 값으로 변환됩니다. 부호 없는 타입으로 변환된 `-1`은 매우 큰 양수 값이 되므로, 사람이 수학적으로 생각한 다음 관계:

```text
-1 < 10
```

와 달리 조건이 거짓이 될 수 있습니다.

따라서 음수가 가능한 인덱스를 `size_t` 길이와 비교할 때는 **음수 여부를 먼저 검사한 뒤** 안전하게 변환합니다.

```c
if (index >= 0 && (size_t)index < length) {
    /* 유효한 범위입니다. */
}
```

이 조건은 왼쪽에서 오른쪽으로 평가됩니다.

1. `index >= 0`인지 검사합니다.
2. 음수가 아닐 때만 `(size_t)index`로 변환합니다.
3. 변환한 값이 `length`보다 작은지 검사합니다.

캐스트 자체가 값을 안전하게 만드는 것은 아닙니다.

```c
(size_t)index
```

이 표현은 단지 `index`를 `size_t`로 변환합니다. `index`가 음수라면 큰 부호 없는 값으로 변환될 수 있습니다.

따라서 경고를 없애기 위해 다음처럼 무조건 캐스트하는 것은 올바른 해결책이 아닙니다.

```c
if ((size_t)index < length) {
    /* index가 음수일 가능성을 무시하고 있습니다. */
}
```

변환하기 전에 **원래 값이 대상 타입으로 사용하기에 유효한지** 먼저 확인해야 합니다.

가능하다면 같은 의미의 값에는 같은 종류의 타입을 사용하는 것도 중요합니다. 예를 들어 배열 길이와 배열 인덱스가 애초에 음수가 될 수 없다면 둘 다 `size_t`로 표현하면 불필요한 부호 혼합을 줄일 수 있습니다.

```c
size_t index = 0;
size_t length = 10;

if (index < length) {
    /* 두 값 모두 size_t입니다. */
}
```

반대로 `-1` 같은 특별한 음수 상태를 인덱스 변수에 저장해야 한다면 부호 있는 타입을 유지하고, `size_t`와 섞어 사용할 때 범위를 명시적으로 확인해야 합니다.

## 조건문

`if`는 조건식의 값이 참인지 거짓인지에 따라 실행할 코드를 선택합니다.

C에서 정수 조건은 다음처럼 해석됩니다.

```text
0          → 거짓
0이 아닌 값 → 참
```

예를 들어:

```c
if (value < 0) {
    fprintf(stderr, "음수는 허용하지 않습니다.\n");
    return -1;
} else if (value == 0) {
    puts("zero");
} else {
    puts("positive");
}
```

조건은 위에서부터 검사합니다.

- `value < 0`이면 첫 번째 블록을 실행합니다.
- 그렇지 않고 `value == 0`이면 두 번째 블록을 실행합니다.
- 두 조건이 모두 거짓이면 `else` 블록을 실행합니다.

따라서 세 블록 중 하나만 실행됩니다.

포인터도 조건식에서 사용할 수 있습니다. 널 포인터는 거짓으로, 널 포인터가 아닌 값은 참으로 취급됩니다.

다음 두 코드는 모두 널 포인터를 검사합니다.

```c
if (pointer == NULL) {
    return -1;
}
```

```c
if (!pointer) {
    return -1;
}
```

첫 번째 표현은 `NULL`과 비교한다는 의도가 직접 드러나고, 두 번째 표현은 C 코드에서 흔히 사용하는 간결한 형태입니다. 프로젝트의 스타일을 일관되게 따르는 것이 중요합니다.

정수에서도 다음과 같이 쓸 수 있습니다.

```c
if (count != 0) {
    /* ... */
}
```

또는:

```c
if (count) {
    /* ... */
}
```

다만 값 자체가 아니라 특정 의미를 검사하는 경우에는 비교 대상을 명시하면 조건의 의도가 더 분명해질 수 있습니다.

```c
if (count > 0) {
    /* 양수인지 검사 */
}
```

## 논리 연산자의 짧은 평가

논리 AND 연산자 `&&`와 논리 OR 연산자 `||`는 **왼쪽 피연산자를 먼저 평가**합니다. 그리고 왼쪽 결과만으로 전체 결과가 결정되면 오른쪽 피연산자를 평가하지 않습니다. 이를 단락 평가(short-circuit evaluation)라고 합니다.

### `&&`

`A && B`에서 `A`가 거짓이면 전체 결과는 이미 거짓입니다. 따라서 `B`는 평가하지 않습니다.

```c
if (text != NULL && text[0] != '\0') {
    /* text가 NULL이 아닐 때만 text[0]을 읽습니다. */
}
```

평가 순서는 다음과 같습니다.

```text
text != NULL 검사
→ 거짓이면 종료
→ 참일 때만 text[0] != '\0' 검사
```

따라서 `text == NULL`일 때 `text[0]`을 읽지 않습니다.

조건의 순서를 반대로 쓰면 안전하지 않습니다.

```c
if (text[0] != '\0' && text != NULL) {
    /* text[0]을 먼저 읽으므로 text가 NULL일 수 있습니다. */
}
```

### `||`

`A || B`에서 `A`가 참이면 전체 결과는 이미 참입니다. 따라서 `B`는 평가하지 않습니다.

예를 들어:

```c
if (text == NULL || text[0] == '\0') {
    return -1;
}
```

`text == NULL`이면 오른쪽의 `text[0]`을 평가하지 않으므로 널 포인터를 역참조하지 않습니다.

### 범위 검사와 함께 사용하기

배열을 읽기 전에 인덱스가 유효한지 먼저 검사할 수 있습니다.

```c
if (index < length && values[index] == target) {
    /* index가 유효할 때만 values[index]를 읽습니다. */
}
```

이 예제는 다음 전제를 가집니다.

- `index`는 음수가 될 수 없는 타입입니다. 예를 들어 `size_t`입니다.
- `values`는 적어도 `length`개의 원소를 가진 유효한 배열을 가리킵니다.

만약 `index`가 `int`처럼 음수가 될 수 있는 타입이라면 음수 검사도 필요합니다.

```c
if (index >= 0 &&
    (size_t)index < length &&
    values[index] == target) {
    /* index가 유효할 때만 배열을 읽습니다. */
}
```

`&&`가 왼쪽부터 단락 평가되므로 각 검사가 다음 검사를 안전하게 만들어 줍니다.

## 반복문과 유지해야 할 조건

반복문은 같은 형태의 작업을 여러 번 수행합니다. 반복문을 이해할 때는 단순히 "몇 번 반복하는가"만 보는 것이 아니라 **반복이 시작될 때 무엇이 참이어야 하고, 한 번 실행한 뒤에도 무엇이 유지되는가**를 확인해야 합니다.

다음 코드를 봅시다.

```c
size_t index = 0;

while (index < length) {
    process(values[index]);
    index++;
}
```

이 코드는 `values[0]`부터 `values[length - 1]`까지 차례로 처리합니다. 단, `values`가 적어도 `length`개의 원소를 가진 유효한 배열을 가리킨다는 전제가 필요합니다.

반복문을 읽을 때는 다음을 확인합니다.

- 반복을 시작하기 전에 어떤 값이 준비되어 있습니까?
- 본문에 들어올 때 항상 참이어야 하는 조건은 무엇입니까?
- 본문이 안전하게 실행되기 위해 필요한 전제는 무엇입니까?
- 한 번 실행한 뒤 어떤 값이 바뀝니까?
- 변경된 뒤에도 다음 반복에 필요한 조건이 유지됩니까?
- 언젠가 종료 조건에 도달합니까?

위 예제를 단계별로 보면 다음과 같습니다.

### 초기 상태

```c
size_t index = 0;
```

첫 번째로 처리할 원소의 인덱스는 `0`입니다.

### 반복 조건

```c
index < length
```

본문에 들어왔다는 것은 이 조건이 참이라는 뜻입니다. 따라서 `index`는 현재 처리할 원소의 유효한 인덱스 범위에 있습니다.

```text
0 <= index < length
```

`index`가 `size_t`이므로 음수는 될 수 없습니다.

### 본문

```c
process(values[index]);
```

`index < length`이므로, `values`가 `length`개의 원소를 가진 유효한 배열이라는 전제 아래 `values[index]`를 읽을 수 있습니다.

### 갱신

```c
index++;
```

현재 원소를 처리한 뒤 다음 원소를 가리키도록 `index`를 1 증가시킵니다.

### 종료

결국 `index == length`가 되면:

```c
index < length
```

가 거짓이 되어 반복이 끝납니다.

이처럼 반복문에서 각 반복의 시작 시점에 계속 성립해야 하는 성질을 **반복 불변식(loop invariant)**이라고 부릅니다.

이 예제에서는 다음과 같은 성질을 생각할 수 있습니다.

```text
반복 시작 시점에는 0 <= index <= length이다.
index보다 작은 위치의 원소들은 이미 처리되었다.
```

본문에 실제로 들어갈 때는 조건식까지 참이므로 더 강하게:

```text
0 <= index < length
```

가 성립합니다.

이 관점으로 반복문을 읽으면 배열 범위 오류나 종료되지 않는 반복을 찾기 쉬워집니다.

## `for` 반복문

초기화, 반복 조건, 갱신이 하나의 제어 변수에 모여 있으면 `for` 문이 더 읽기 쉬운 경우가 많습니다.

```c
for (size_t index = 0; index < length; index++) {
    process(values[index]);
}
```

구조는 다음과 같습니다.

```c
for (초기화; 조건; 갱신) {
    본문
}
```

실행 순서는 개념적으로 다음과 같습니다.

```text
초기화
→ 조건 검사
→ 본문
→ 갱신
→ 조건 검사
→ 본문
→ 갱신
→ ...
```

조건이 거짓이 되면 반복을 종료합니다.

다음 코드는 배열의 값을 누적합니다.

```c
long total = 0;

for (size_t index = 0; index < length; index++) {
    total += values[index];
}
```

여기서 반복이 진행되는 동안 다음 상태를 생각할 수 있습니다.

```text
index보다 앞에 있는 원소들은 이미 total에 더해졌다.
index부터 뒤의 원소들은 아직 더하지 않았다.
```

단, `total`이 `long`이고 합이 `LONG_MIN`부터 `LONG_MAX` 사이를 벗어날 수 있다면 `total += values[index]`에서 부호 있는 정수 overflow가 발생할 수 있습니다. 실제 입력 범위가 안전하다는 보장이 없다면 뒤에서 설명하는 방식처럼 연산 전에 overflow를 검사해야 합니다.

## 누적 상태

여러 입력을 차례로 처리하면서 통계를 계산하려면 **지금까지 처리한 입력에서 무엇을 기억해야 하는지** 먼저 정합니다.

예를 들어 개수, 최솟값, 최댓값, 합계를 유지할 수 있습니다.

```c
struct statistics {
    size_t count;
    long minimum;
    long maximum;
    long sum;
};
```

각 필드의 의미를 명확히 정하면 다음과 같습니다.

```text
count   → 지금까지 처리한 값의 개수
minimum → 지금까지 처리한 값 중 최솟값
maximum → 지금까지 처리한 값 중 최댓값
sum     → 지금까지 처리한 값의 합
```

### 최솟값과 최댓값의 초기화

값을 하나도 처리하지 않은 상태에서는 실제 최솟값과 최댓값이 아직 존재하지 않습니다.

따라서 임의의 숫자를 최솟값이나 최댓값으로 두기보다 **첫 번째 입력값을 기준으로 초기화**할 수 있습니다.

```c
if (stats->count == 0) {
    stats->minimum = value;
    stats->maximum = value;
} else {
    if (value < stats->minimum) {
        stats->minimum = value;
    }

    if (value > stats->maximum) {
        stats->maximum = value;
    }
}
```

예를 들어 다음 입력을 처리한다고 가정합니다.

```text
5, 8, 12
```

`minimum`을 처음부터 `0`으로 초기화하면:

```text
minimum = 0
```

이 되고, 모든 실제 입력이 `0`보다 크기 때문에 이후에도 `0`이 남습니다.

결과적으로 실제 입력에는 존재하지 않는 값이 최솟값이 됩니다.

반면 첫 입력인 `5`로 초기화하면:

```text
minimum = 5
maximum = 5
```

가 되고 이후 입력을 비교하여 올바른 통계를 만들 수 있습니다.

### 상태를 갱신하는 순서

값 하나를 정상적으로 처리했다면 개수도 함께 갱신해야 합니다.

```c
if (stats->count == 0) {
    stats->minimum = value;
    stats->maximum = value;
} else {
    if (value < stats->minimum) {
        stats->minimum = value;
    }

    if (value > stats->maximum) {
        stats->maximum = value;
    }
}

stats->count++;
```

합계도 유지한다면 `stats->sum`을 갱신해야 합니다.

```c
stats->sum += value;
```

다만 `long` 합계가 표현 범위를 벗어날 가능성이 있다면 이 연산도 overflow 검사가 필요합니다.

또한 `count`가 `size_t`이므로 이론적으로 `SIZE_MAX`에서 다시 증가시키면 부호 없는 정수 연산의 모듈러 규칙에 따라 값이 돌아갑니다. 실제 프로그램에서는 그만큼 많은 값을 처리할 가능성이 있는지에 따라 필요한 범위 검사를 설계해야 합니다.

핵심은 **누적 상태의 각 필드가 언제부터 유효하며, 새 값을 처리한 뒤 어떤 관계가 유지되어야 하는지** 명확히 하는 것입니다.

## overflow를 계산 전에 검사하기

정수 타입은 표현할 수 있는 범위가 제한되어 있습니다.

`long`의 범위는 다음 매크로로 확인합니다.

```c
LONG_MIN
LONG_MAX
```

부호 있는 정수에서 계산 결과가 이 범위를 벗어나면 **부호 있는 정수 overflow**가 발생하며, C에서는 정의되지 않은 동작(undefined behavior)입니다.

예를 들어 다음 방식은 안전하지 않습니다.

```c
long result = left + right;

if (result < left) {
    /* overflow 검사라고 생각했지만 이미 늦었습니다. */
}
```

`left + right` 자체가 표현 범위를 벗어났다면 이미 정의되지 않은 동작이 발생했기 때문입니다.

따라서 **위험한 연산을 수행하기 전에** 그 결과가 범위 안에 들어오는지 확인해야 합니다.

```c
#include <limits.h>

int add_long(long left, long right, long *out) {
    if (out == NULL) {
        return -1;
    }

    if ((right > 0 && left > LONG_MAX - right) ||
        (right < 0 && left < LONG_MIN - right)) {
        return -1;
    }

    *out = left + right;
    return 0;
}
```

검사의 의미를 나누어 보면 다음과 같습니다.

### `right > 0`

양수를 더할 때는 최댓값을 넘는지 확인합니다.

```c
left > LONG_MAX - right
```

이 조건이 참이면:

```text
left + right > LONG_MAX
```

가 되므로 덧셈을 수행해서는 안 됩니다.

### `right < 0`

음수를 더할 때는 최솟값보다 작아지는지 확인합니다.

```c
left < LONG_MIN - right
```

이 조건이 참이면:

```text
left + right < LONG_MIN
```

가 되므로 덧셈을 수행해서는 안 됩니다.

### 안전한 경우에만 계산

두 overflow 조건에 해당하지 않을 때만 실제 덧셈을 수행합니다.

```c
*out = left + right;
```

따라서 위험한 연산이 먼저 실행되지 않습니다.

함수 사용 예시는 다음과 같습니다.

```c
long result;

if (add_long(a, b, &result) != 0) {
    fprintf(stderr, "합계를 표현할 수 없습니다.\n");
    return -1;
}
```

### 부호 없는 정수 overflow와의 차이

부호 없는 정수 연산은 표현 범위를 넘으면 정의되지 않은 동작이 되는 것이 아니라 **해당 타입의 범위에 맞춰 모듈러 방식으로 돌아갑니다**.

예를 들어 최댓값에서 1을 더하면 다시 0으로 돌아갈 수 있습니다.

그러나 이것이 항상 원하는 결과라는 뜻은 아닙니다. 크기나 개수를 계산할 때 값이 돌아가면 논리 오류나 잘못된 메모리 크기 계산으로 이어질 수 있으므로, 필요하다면 부호 없는 연산도 계산 전에 범위를 검사해야 합니다.

뺄셈과 곱셈도 같은 원칙을 적용합니다.

```text
먼저 결과가 표현 가능한지 검사
→ 안전한 경우에만 실제 연산
```

## `switch`

`switch`는 하나의 정수형 또는 열거형 값에 따라 여러 실행 경로 중 하나를 선택할 때 사용할 수 있습니다.

```c
switch (command) {
case COMMAND_START:
    start();
    break;

case COMMAND_STOP:
    stop();
    break;

default:
    return -1;
}
```

실행할 `case`를 찾으면 그 위치부터 문장을 실행합니다.

중요한 점은 `case` 자체가 실행을 자동으로 끝내지 않는다는 것입니다.

```c
switch (command) {
case COMMAND_START:
    start();

case COMMAND_STOP:
    stop();
    break;
}
```

`command == COMMAND_START`라면 `start()`를 실행한 뒤 다음 `case`의 `stop()`까지 계속 실행됩니다.

이 동작을 **fallthrough**라고 합니다.

따라서 다음 `case`까지 실행하는 것이 목적이 아니라면 `break`나 `return` 등으로 현재 경로를 끝내야 합니다.

```c
case COMMAND_START:
    start();
    break;
```

fallthrough를 의도적으로 사용할 수도 있지만, 읽는 사람이 실수로 `break`를 빠뜨린 것과 구분할 수 있도록 명확히 표시하는 것이 좋습니다.

```c
case COMMAND_START:
    prepare();
    /* fall through */

case COMMAND_RUN:
    run();
    break;
```

`default`는 어떤 `case`에도 일치하지 않을 때 실행됩니다.

```c
default:
    return -1;
```

예상하지 못한 값이 들어오는 것을 오류로 처리해야 하는 프로그램에서는 `default`를 이용해 명시적으로 실패시키는 방식이 유용합니다.

## 완료 기준

다음을 직접 설명하고 작성할 수 있어야 합니다.

1. `int`, `long`, `size_t`의 용도와 실제 비트 폭이 구현 환경에 따라 달라질 수 있다는 점을 설명합니다.
2. 부호 있는 타입과 부호 없는 타입을 비교할 때 일어나는 정수 변환 때문에 음수가 큰 부호 없는 값으로 해석될 수 있음을 설명합니다.
3. 음수가 가능한 값을 `size_t`로 변환하기 전에 범위를 검사합니다.
4. `&&`와 `||`의 단락 평가를 이용하여 포인터나 배열을 접근하기 전에 안전 조건을 검사합니다.
5. 배열을 읽기 전에 인덱스가 유효한 범위인지 확인합니다.
6. 반복문에서 초기 상태, 반복 조건, 갱신, 종료 조건을 설명합니다.
7. 반복 불변식이 무엇인지 설명하고, 반복 시작 시점에 유지되어야 하는 조건을 찾습니다.
8. 첫 번째 입력값으로 최솟값과 최댓값을 초기화해야 하는 이유를 설명합니다.
9. 누적 상태에서 `count`, `minimum`, `maximum`, `sum`이 각각 무엇을 의미하는지 설명합니다.
10. 부호 있는 덧셈의 overflow를 실제 연산 전에 검사합니다.
11. 부호 있는 정수 overflow와 부호 없는 정수의 모듈러 연산 차이를 설명합니다.
12. `switch`에서 `break`를 생략하면 fallthrough가 발생한다는 점을 설명합니다.
