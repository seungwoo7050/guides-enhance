# 문제 조건과 반례

## 학습 목표

- 자연어로 주어진 문제를 검증 가능한 입력·출력 조건으로 바꿉니다.
- 입력 제한을 알고리즘 선택의 근거로 사용합니다.
- 단순하지만 후보 구현과 독립적인 기준 계산을 만듭니다.
- 구현의 가정을 직접 깨는 최소 반례를 설계합니다.

## 선행지식

함수의 매개변수와 반환값, 조건문, 작은 입력의 실행 상태를 손으로 추적하는 방법을 알고 있어야 합니다.

## 핵심 관점

알고리즘 문제는 정답 코드를 떠올리는 작업이 아닙니다. 구현 전에 다음 네 가지를 먼저 정해야 합니다.

```text
조건: 어떤 입력을 받고 어떤 결과를 반환합니까?
기준: 가장 단순하게 정답을 계산하는 방법은 무엇입니까?
비용: 입력이 커질 때 시간과 메모리가 얼마나 필요합니까?
증거: 구현이 조건을 지켰다는 사실을 어떻게 확인합니까?
```

## 1. 문제를 입력·출력 조건으로 정리합니다

다음 항목을 구현 전에 작성합니다.

```text
입력으로 허용하는 값:
반환값의 의미:
정상 결과의 조건:
답이 여러 개일 때의 선택 순서:
답이 없을 때의 결과:
잘못된 입력을 처리하는 위치:
입력 크기와 값의 범위:
허용 시간과 메모리:
```

예를 들어 “목표 합을 만드는 두 원소를 찾습니다”라는 문장만으로는 함수의 동작이 정해지지 않습니다.

- 같은 위치를 두 번 사용할 수 있습니까?
- 같은 값이 여러 번 있으면 어느 index를 반환합니까?
- 답이 여러 개면 처음 발견한 쌍, index가 가장 작은 쌍, 사전순으로 가장 작은 쌍 중 무엇을 반환합니까?
- 답이 없으면 빈 값, `None`, `-1`, 예외 중 무엇을 사용합니까?
- 두 값을 더할 때 정수 범위를 넘을 수 있습니까?

이 조건이 달라지면 올바른 알고리즘과 테스트도 달라집니다.

## 2. 입력 제한을 목표 비용으로 바꿉니다

다음 표는 절대적인 기준이 아니라 첫 후보를 고르기 위한 신호입니다.

| 입력 크기 | 먼저 검토할 비용 |
| ---: | --- |
| `n <= 20` | 부분집합, 순열, 백트래킹 |
| `n <= 2,000` | `O(n²)` |
| `n <= 200,000` | `O(n log n)` 또는 `O(n)` |
| 큰 희소 그래프 | `O(V+E)` 또는 `O((V+E) log V)` |

반복문 개수만 세면 실제 비용을 놓칠 수 있습니다. 다음 항목도 포함합니다.

- 반복문 안의 정렬, 복사, 문자열 slice
- 동적 배열 앞쪽 원소 삭제
- 비교 함수 자체의 비용
- hash key 계산 비용
- 재귀 호출 깊이
- 결과를 출력하거나 저장하는 비용

## 3. 느리더라도 독립적인 기준 계산을 먼저 만듭니다

기준 계산은 작은 입력에서만 실행해도 됩니다. 중요한 점은 후보 구현과 다른 계산 방법을 사용한다는 것입니다.

| 후보 구현 | 독립적인 기준 계산 |
| --- | --- |
| 누적 합 | 질의할 때마다 직접 더합니다. |
| 이분 탐색 | 앞에서부터 선형 탐색합니다. |
| Dijkstra | 작은 그래프에서 Floyd–Warshall을 사용합니다. |
| 구간 선택 greedy | 모든 부분집합을 검사합니다. |
| KMP | 각 시작 위치에서 직접 비교하거나 표준 문자열 검색을 사용합니다. |
| 최대 유량 | 가능한 모든 source-side cut을 열거합니다. |

후보와 기준 계산이 같은 parser, 정렬 순서, helper를 공유하면 같은 결함이 두 구현에 함께 들어갈 수 있습니다.

## 4. 반례는 구현의 가정을 하나씩 깨야 합니다

무작위 입력을 많이 만들기 전에 구현이 기대하는 조건을 적습니다.

```text
입력이 비어 있지 않습니다.
모든 값이 서로 다릅니다.
간선 가중치는 음수가 아닙니다.
그래프가 연결되어 있습니다.
답이 하나뿐입니다.
합이 정수 범위를 넘지 않습니다.
재귀 깊이가 충분히 작습니다.
```

그다음 각 가정을 하나씩 깨는 입력을 만듭니다.

### 자주 확인할 입력

- 빈 입력과 최소 크기
- 같은 값의 반복
- 이미 정렬된 입력과 역순 입력
- 답이 첫 위치나 마지막 위치에 있는 경우
- 답이 없는 경우
- 여러 최적해와 동점
- 연결되지 않은 그래프
- 자기 loop와 중복 간선
- 0, 음수, 매우 큰 값
- 긴 공통 prefix와 반복 문자열

## 5. 실패 입력을 최소화합니다

실패 입력이 크면 원인과 무관한 상태가 함께 섞입니다. 다음 변환을 반복하며 같은 실패가 유지되는지 확인합니다.

1. 원소, 정점, 간선을 줄입니다.
2. 값의 절댓값을 줄입니다.
3. 실패와 무관한 중복을 제거합니다.
4. 문자열의 앞뒤를 줄입니다.
5. 실패와 관계없는 연산을 삭제합니다.

최종 반례에서는 어떤 가정이 깨졌는지 바로 확인할 수 있어야 합니다.

## 6. 무작위 검사는 재현할 수 있어야 합니다

무작위 검사를 사용할 때는 다음 규칙을 지킵니다.

- seed를 고정합니다.
- 작은 입력부터 시작합니다.
- 실패한 실제 입력과 seed를 함께 출력합니다.
- 후보와 기준 계산에 같은 값의 독립 복사본을 전달합니다.
- 발견한 실패 입력을 고정 회귀 테스트로 추가합니다.

무작위 검사는 증명이 아닙니다. 사람이 예상하지 못한 반례를 찾는 도구입니다.

## 연결 구현

[`verified-algorithms`](../../exercises/verified-algorithms/)의 다음 API에서 이 과정을 확인합니다.

- `lower_bound`: 중복 값에서 임의의 일치 위치가 아니라 첫 삽입 위치를 반환해야 합니다.
- `select_intervals`: 시작 시간이 빠른 구간부터 고르는 잘못된 규칙을 부분집합 기준 계산으로 검출합니다.
- `bellman_ford`: 시작점에서 도달 가능한 음수 cycle과 도달할 수 없는 음수 cycle을 구분합니다.

## 완료 기준

- 빈 입력, 답 없음, 잘못된 입력을 서로 다른 결과로 표현합니다.
- 후보 구현과 핵심 로직을 공유하지 않는 기준 계산을 작성합니다.
- 구현의 특정 가정 하나를 깨는 최소 반례를 남깁니다.
- 실패 입력과 seed를 다시 실행할 수 있게 보존합니다.

## 실패 신호

다음 중 하나라도 해당하면 구현을 시작하기 이릅니다.

- 답이 없을 때의 결과를 설명하지 못합니다.
- 입력 제한에서 단순 풀이가 왜 부족한지 계산하지 못합니다.
- 후보 구현과 기준 계산이 같은 핵심 알고리즘을 사용합니다.
- 샘플 외의 실패 입력을 하나도 만들지 못합니다.
- 무작위 검사에 고정 seed와 실패 입력 보존이 없습니다.
