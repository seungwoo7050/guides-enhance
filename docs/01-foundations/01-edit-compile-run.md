# 편집·컴파일·실행

C 프로그램을 작성할 때 가장 먼저 익혀야 할 것은 문법보다 **소스 파일을 실행 가능한 프로그램으로 만드는 과정**입니다. 코드를 수정한 뒤 다시 컴파일하지 않으면 실행 파일에는 변경 내용이 반영되지 않습니다. 또한 컴파일에 성공했다는 사실과 프로그램이 올바르게 동작한다는 사실은 서로 다릅니다.

## 가장 작은 프로그램

```c
#include <stdio.h>

int main(void) {
    puts("hello");
    return 0;
}
```

파일 이름을 `hello.c`로 저장했다면 다음과 같이 컴파일합니다.

```sh
cc -std=c11 -Wall -Wextra -Wpedantic hello.c -o hello
./hello
```

현재 디렉터리의 실행 파일은 `./hello`처럼 경로를 직접 적습니다. 셸은 보안상 현재 디렉터리를 명령 검색 경로에 자동으로 포함하지 않는 경우가 많습니다.

## 컴파일 명령 읽기

```sh
cc -std=c11 -Wall -Wextra -Wpedantic hello.c -o hello
```

- `cc`: 시스템의 C 컴파일러 드라이버를 실행합니다.
- `-std=c11`: C11 언어 규칙으로 컴파일합니다.
- `-Wall -Wextra -Wpedantic`: 흔한 문제를 경고로 출력합니다.
- `hello.c`: 입력 소스 파일입니다.
- `-o hello`: 결과 실행 파일의 이름을 지정합니다.

경고는 실행을 막지 않을 수 있지만 무시해서는 안 됩니다. 경고가 왜 발생했는지 이해하고 원인을 수정한 뒤 다음 단계로 넘어갑니다.

## 종료 상태 확인하기

`main`의 반환값은 프로세스의 종료 상태가 됩니다.

```c
int main(void) {
    return 7;
}
```

실행한 뒤 셸에서 종료 상태를 확인할 수 있습니다.

```sh
./program
printf '%s\n' "$?"
```

Unix 계열 프로그램은 일반적으로 성공 시 `0`, 실패 시 `0`이 아닌 값을 반환합니다. 구체적인 실패 값은 프로그램이 정합니다.

## stdout과 stderr

일반 결과는 표준 출력에, 오류 메시지는 표준 오류에 씁니다.

```c
#include <stdio.h>

int main(int argc, char *argv[]) {
    if (argc != 2) {
        fprintf(stderr, "사용법: %s <이름>\n", argv[0]);
        return 2;
    }
    printf("안녕하세요, %s\n", argv[1]);
    return 0;
}
```

두 출력은 별도로 저장할 수 있습니다.

```sh
./greet Alice >out.txt 2>err.txt
```

오류가 발생했을 때 정상 결과 파일에 부분 출력이 남으면 호출자가 성공과 실패를 구분하기 어렵습니다. 가능한 경우 입력을 먼저 검증한 뒤 결과를 출력합니다.

## 셸 인자와 `argc`, `argv`

```sh
./program one "two three"
```

위 명령을 실행하면 프로그램은 다음 값을 받습니다.

```text
argc == 3
argv[0] == "./program"
argv[1] == "one"
argv[2] == "two three"
argv[3] == NULL
```

따옴표는 셸이 인자 경계를 정할 때 사용하며, 보통 프로그램에는 전달되지 않습니다. 프로그램은 이미 나뉜 문자열 배열을 받습니다.

## 수정과 실행 사이의 확인 순서

```text
소스 저장
→ 컴파일
→ 경고 확인
→ 실행
→ stdout 확인
→ stderr 확인
→ 종료 상태 확인
```

실행 결과가 바뀌지 않는다면 먼저 다음을 확인합니다.

- 수정한 파일을 저장했습니까?
- 실제로 다시 컴파일했습니까?
- 다른 경로에 있는 실행 파일을 실행한 것은 아닙니까?
- 빌드 명령이 수정한 소스 파일을 포함합니까?

## 실패 단계 구분하기

### 전처리 오류

헤더를 찾지 못하거나 전처리 지시문이 잘못된 경우입니다. `#include` 경로와 `-I` 옵션을 확인합니다.

### 컴파일 오류

C 문법이나 타입 사용이 잘못되어 오브젝트 파일을 만들지 못한 경우입니다. 오류 메시지의 첫 번째 원인을 먼저 수정합니다. 한 문법 오류 때문에 뒤쪽에서 연쇄 오류가 많이 나올 수 있습니다.

### 링크 오류

함수를 선언하고 호출했지만 실제 정의가 최종 링크 입력에 없는 경우입니다.

```text
undefined reference to `parse_input`
```

소스 파일이나 라이브러리가 링크 명령에 포함되었는지 확인합니다.

### 실행 오류

실행 파일은 만들어졌지만 잘못된 결과를 출력하거나 비정상 종료한 경우입니다. 입력값, 배열 범위, 포인터와 시스템 호출 반환값을 확인해야 합니다.

## 기본 개발 습관

- 한 번에 큰 코드를 작성하기보다 작은 상태에서 자주 컴파일합니다.
- 경고를 읽지 않고 캐스트로 덮지 않습니다.
- 정상 입력뿐 아니라 인자 누락과 잘못된 입력도 실행합니다.
- 오류 메시지와 종료 상태를 함께 확인합니다.
- 실행 파일과 빌드 산출물은 소스와 분리해 관리합니다.

## 완료 기준

다음을 직접 수행할 수 있어야 합니다.

1. 새 `.c` 파일을 만들고 경고 옵션을 켜서 컴파일합니다.
2. 명령행 인자 개수를 검사합니다.
3. 정상 결과와 오류 메시지를 서로 다른 출력으로 보냅니다.
4. 성공과 실패에 다른 종료 상태를 반환합니다.
5. 전처리, 컴파일, 링크와 실행 오류를 구분합니다.
