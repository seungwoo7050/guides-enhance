# 정확성, 불변식과 종료

- 반복 불변식(loop invariant)과 귀납법으로 부분 정확성을 설명합니다.
- 종료성(termination)을 반환값의 정확성과 별도로 증명합니다.
- 최적화 문제에서 실행 가능성(feasibility)과 최적성(optimality)을 구분합니다.
- greedy 알고리즘의 선택이 전체 최적해를 보존하는 이유를 교환 논리로 설명합니다.
- 그래프 알고리즘마다 필요한 전조건과 핵심 불변식을 식별합니다.
- 테스트와 증명이 서로 보완 관계이며 서로를 대신할 수 없음을 설명합니다.

## 핵심 관점

알고리즘이 "정확하다"는 말에는 서로 다른 두 주장이 들어 있습니다.

```text
부분 정확성(partial correctness):
함수가 종료한다면 반환값이 문제의 조건을 만족합니다.

종료성(termination):
모든 허용 입력에서 함수가 유한한 단계 안에 종료합니다.
```

두 조건을 모두 만족할 때 알고리즘의 **완전한 정확성(total correctness)** 을 주장할 수 있습니다.

```text
부분 정확성 + 종료성 = 완전한 정확성
```

예를 들어 어떤 반복문이 종료했을 때는 항상 올바른 답을 반환하더라도 특정 입력에서 무한 반복한다면 완전히 정확한 알고리즘은 아닙니다.

최적화 문제에서는 정확성 안에서도 다음 두 가지를 추가로 구분해야 합니다.

```text
실행 가능성(feasibility):
반환한 답이 문제의 모든 제약을 만족합니다.

최적성(optimality):
반환한 실행 가능한 답보다 더 좋은 실행 가능한 답이 존재하지 않습니다.
```

예를 들어 서로 겹치지 않는 구간을 몇 개 선택하는 문제에서 구간 하나만 반환하면 실행 가능할 수는 있지만, 더 많은 구간을 선택할 수 있다면 최적해는 아닙니다.

## 1. 입력·출력 계약과 실행 중 상태를 구분합니다

함수의 계약은 **호출 전과 호출 후**에 관한 조건입니다.

예를 들어 `lower_bound(A, target)`의 계약을 다음처럼 정할 수 있습니다.

```text
전조건:
A는 오름차순으로 정렬되어 있습니다.

반환값:
0 <= i <= len(A)를 만족하는 index i를 반환합니다.

정상 결과:
A[i] >= target인 첫 index를 반환합니다.
그런 index가 없으면 len(A)를 반환합니다.
```

반면 알고리즘의 `low`, `high`, `mid` 같은 값은 실행 중에만 존재하는 **내부 상태**입니다.

이 내부 상태에 대해 "현재까지 무엇이 확정되었는가?"를 표현하는 문장이 불변식입니다.

따라서 다음 두 문장은 역할이 다릅니다.

```text
계약:
반환값은 target 이상인 첫 위치입니다.

불변식:
low 앞의 값은 모두 target보다 작고,
high 이후의 값은 모두 target 이상입니다.
```

좋은 불변식은 최종 결과 자체를 반복해서 말하지 않고, **반복이 진행되는 동안 이미 확인된 정보와 아직 확인하지 않은 영역을 구분**합니다.

## 2. 반복 불변식이란 무엇입니까?

반복 불변식(loop invariant)은 반복문의 특정한 동일 위치에서 매번 참인 명제입니다.

보통 다음 위치를 기준으로 삼습니다.

```text
while 조건을 검사하기 직전
또는
반복문 body가 시작되기 직전
```

중요한 점은 어느 위치를 기준으로 하는지 고정하는 것입니다.

예를 들어 다음은 너무 모호해서 불변식으로 사용하기 어렵습니다.

```text
배열을 올바르게 탐색하고 있습니다.
답에 가까워지고 있습니다.
현재 상태는 유효합니다.
```

이 문장들은 구체적인 상태에서 참인지 거짓인지 판정하기 어렵습니다.

반면 다음은 판정 가능한 명제입니다.

```text
0 <= low <= high <= n
[0, low)의 모든 원소는 target보다 작습니다.
[high, n)의 모든 원소는 target 이상입니다.
```

특정 `low`, `high`, 배열이 주어지면 각 문장이 참인지 직접 검사할 수 있습니다.

---

## 3. 반복 불변식 증명의 세 단계

반복문을 불변식으로 설명할 때는 다음 세 단계를 분리합니다.

```text
초기화(initialization):
첫 반복이 시작되기 전에 불변식이 참임을 보입니다.

유지(maintenance):
불변식이 참인 상태에서 반복 body를 한 번 실행하면
다음 반복 시작 시점에도 불변식이 참임을 보입니다.

종료 시 해석(termination condition + invariant):
반복이 끝났을 때 종료 조건과 불변식을 결합하여
원하는 반환 조건이 나온다는 것을 보입니다.
```

이 세 단계는 각각 다른 질문에 답합니다.

### 초기화

```text
불변식이 처음부터 성립합니까?
```

### 유지

```text
한 번의 상태 갱신이 이미 알고 있던 사실을 깨뜨리지 않습니까?
```

### 종료 시 해석

```text
더 이상 반복하지 않는다는 사실과 불변식을 합치면
왜 정답이 결정됩니까?
```

여기에 **반복이 반드시 끝나는가?**라는 종료성 증명은 별도로 추가해야 합니다.

## 4. `lower_bound` 예제로 불변식을 구성합니다

정렬된 배열 `A`에서 `A[i] >= target`을 만족하는 첫 index를 찾는다고 가정합니다.

그런 원소가 없으면 `n = len(A)`를 반환합니다.

반열린 탐색 구간 `[low, high)`를 사용하면 다음과 같이 구현할 수 있습니다.

```python
def lower_bound(A, target):
    low = 0
    high = len(A)

    while low < high:
        mid = (low + high) // 2

        if A[mid] < target:
            low = mid + 1
        else:
            high = mid

    return low
```

### 상태 영역을 세 부분으로 나눕니다

반복 중 배열을 다음처럼 생각할 수 있습니다.

```text
[0, low)       [low, high)       [high, n)
확정: < target   아직 미확정       확정: >= target
```

따라서 불변식을 다음처럼 잡을 수 있습니다.

```text
1. 0 <= low <= high <= n
2. [0, low)의 모든 원소는 target보다 작습니다.
3. [high, n)의 모든 원소는 target 이상입니다.
```

`[low, high)`는 아직 첫 삽입 위치가 어디인지 결정되지 않은 후보 영역입니다.

### 초기화

처음에는

```text
low = 0
high = n
```

입니다.

따라서

```text
[0, low) = [0, 0)
[high, n) = [n, n)
```

두 구간은 모두 비어 있습니다.

빈 구간에는 조건을 위반하는 원소가 없으므로 다음 문장은 자동으로 참입니다.

```text
[0, low)의 모든 원소는 target보다 작습니다.
[high, n)의 모든 원소는 target 이상입니다.
```

또한

```text
0 <= 0 <= n <= n
```

이므로 범위 조건도 참입니다.

### 유지: `A[mid] < target`

정렬된 배열에서 `A[mid] < target`이라면 `mid`까지의 원소는 첫 정답 위치가 될 수 없습니다.

따라서

```text
low = mid + 1
```

로 갱신합니다.

정렬되어 있으므로 `[기존 low, mid]`에 있는 모든 원소도 `target`보다 작습니다.

따라서 새로운 `[0, low)` 전체가 여전히 `target`보다 작습니다.

`high`는 바뀌지 않았으므로 오른쪽 불변식도 유지됩니다.

### 유지: `A[mid] >= target`

`A[mid] >= target`이면 `mid` 자신은 정답 후보이며, 첫 위치는 `mid`보다 오른쪽일 필요가 없습니다.

따라서

```text
high = mid
```

로 갱신합니다.

배열이 정렬되어 있으므로 `mid` 이후의 모든 원소도 `target` 이상입니다.

따라서 새로운 `[high, n)` 전체가 `target` 이상이라는 불변식이 유지됩니다.

### 반복 종료 시

반복 조건은

```text
low < high
```

입니다.

종료하면

```text
low == high
```

입니다.

불변식에 따라

```text
[0, low)의 모든 값 < target
[high, n)의 모든 값 >= target
```

이고 `low == high`이므로 경계 하나가 두 영역을 정확히 나눕니다.

따라서 `low`는 `target` 이상인 첫 위치입니다.

만약 모든 값이 `target`보다 작다면 경계는 `n`이 되고, 계약에 따라 `n`을 반환합니다.

## 5. 반복문의 종료성은 감소하는 측정값으로 증명합니다

불변식이 유지된다고 해서 반복문이 반드시 끝나는 것은 아닙니다.

종료성을 설명하려면 반복할 때마다 감소하는 음이 아닌 정수값을 찾는 방법이 유용합니다.

이를 **variant**, **ranking function**, 또는 종료 측정값이라고 부르기도 합니다.

`lower_bound`에서는 다음 값을 사용할 수 있습니다.

```text
high - low
```

반복 조건이 참이면

```text
low < high
```

이므로

```text
high - low > 0
```

입니다.

각 반복에서 `mid`를 선택한 뒤

```text
low = mid + 1
```

또는

```text
high = mid
```

로 갱신하므로 탐색 구간 길이 `high - low`는 엄격히 줄어듭니다.

그리고 이 값은 음수가 될 수 없습니다.

따라서 유한 번의 반복 후 반드시

```text
high - low = 0
```

이 되어 종료합니다.

### 감소하지 않는 갱신을 주의합니다

예를 들어 다음 갱신은 구현 형태에 따라 무한 반복을 만들 수 있습니다.

```text
low = mid
```

만약

```text
low = 3
high = 4
mid = 3
```

이라면 `low`가 그대로 `3`에 머물 수 있습니다.

따라서 종료 증명은 단순히 "구간을 줄입니다"가 아니라, **모든 반복 경로에서 측정값이 실제로 엄격히 감소하는지** 확인해야 합니다.

## 6. 부분 정확성과 종료성을 섞지 않습니다

다음 두 질문은 독립적입니다.

### 부분 정확성

```text
종료했다고 가정하면 반환값이 맞습니까?
```

### 종료성

```text
허용된 모든 입력에서 실제로 종료합니까?
```

예를 들어 다음 의사코드는 결과를 반환하기만 한다면 항상 `0`을 반환합니다.

```text
while some_condition:
    do_nothing()

return 0
```

문제의 정답이 항상 `0`이라고 하더라도 `some_condition`이 영원히 참일 수 있다면 알고리즘은 모든 입력에서 종료하지 않습니다.

반대로 항상 종료하는 함수라도 잘못된 값을 반환할 수 있습니다.

```python
def lower_bound(A, target):
    return 0
```

이 함수는 즉시 종료하지만 대부분의 입력에서 정확하지 않습니다.

따라서 완전한 정확성을 설명하려면 두 요소를 각각 확인해야 합니다.

## 7. 재귀 정확성은 귀납 구조로 설명합니다

재귀 알고리즘은 수학적 귀납법과 자연스럽게 연결됩니다.

기본 구조는 다음과 같습니다.

```text
기저 사례(base case):
가장 작은 입력에서 직접 올바른 결과를 반환합니다.

귀납 가정(induction hypothesis):
현재 입력보다 작은 하위 문제에 대한 재귀 호출은
올바른 결과를 반환한다고 가정합니다.

결합(inductive step):
그 하위 결과를 이용해 현재 문제의 결과도 올바르게 계산함을 보입니다.

종료:
모든 재귀 호출에서 음이 아닌 측정값이 엄격히 줄어
결국 기저 사례에 도달함을 보입니다.
```

### 측정값의 예

재귀 호출마다 감소하는 값은 문제에 따라 다릅니다.

- 배열 길이
- 구간 길이
- 문자열 prefix 길이
- 남은 정점 수
- 아직 결정하지 않은 변수 수
- subtree의 정점 수

중요한 조건은 다음 두 가지입니다.

```text
각 재귀 호출에서 측정값이 엄격히 감소합니다.
측정값에는 더 이상 내려갈 수 없는 하한이 있습니다.
```

### 모든 재귀 경로에서 감소해야 합니다

다음 코드를 생각해 봅시다.

```text
solve(n):
    if n == 0:
        return
    solve(n - 1)
    solve(n)
```

첫 번째 호출에서는 `n`이 줄지만 두 번째 호출에서는 줄지 않습니다.

따라서 "어떤 호출에서는 작아진다"로는 종료를 증명할 수 없습니다.

모든 재귀 호출 경로에서 감소가 보장되어야 합니다.

## 8. 실행 가능성과 최적성을 분리합니다

최적화 문제에서는 올바른 형식의 답을 반환하는 것만으로 부족합니다.

예를 들어 서로 겹치지 않는 구간을 최대한 많이 선택하는 문제를 생각해 봅시다.

다음 결과가 있다고 합시다.

```text
선택한 구간들이 서로 겹치지 않습니다.
```

이는 **실행 가능성**을 보인 것입니다.

그러나 다음 질문은 아직 남아 있습니다.

```text
다른 실행 가능한 선택 중 더 많은 구간을 고를 수는 없습니까?
```

이 질문까지 부정해야 최적성을 보인 것입니다.

### 최적화 문제의 정확성 구조

다음 순서로 설명하면 명확합니다.

```text
1. 반환한 해가 모든 제약을 만족합니다.
2. 반환한 해의 목적값을 정의합니다.
3. 어떤 다른 실행 가능한 해도 더 좋은 목적값을 가질 수 없음을 보입니다.
4. 동점이 여러 개라면 어떤 답을 반환해도 되는지,
   또는 정해진 동점 규칙이 있는지 설명합니다.
```

목적값은 문제에 따라 다음과 같이 달라집니다.

```text
최대화: 선택한 구간 수, 총 가치, flow 값
최소화: 총 거리, 총 비용, spanning tree 가중치
```

---

## 9. greedy는 "좋아 보이는 선택"만으로 증명되지 않습니다

greedy 알고리즘은 현재 단계에서 선택을 한 뒤 일반적으로 그 선택을 되돌리지 않습니다.

따라서 다음 주장이 필요합니다.

```text
이 국소 선택을 해도 어떤 최적해를 잃지 않습니다.
```

대표적인 증명 방법이 **교환 논리(exchange argument)** 입니다.

### 기본 구조

1. 임의의 최적해 `O`를 선택합니다.
2. `O`가 greedy의 현재 선택 `g`를 이미 포함하면 그대로 둡니다.
3. 포함하지 않는다면 `O`의 일부 선택을 `g`로 교체합니다.
4. 교체 후에도 모든 제약이 유지됨을 보입니다.
5. 목적값이 나빠지지 않음을 보입니다.
6. 따라서 `g`를 포함하는 최적해가 하나 이상 존재합니다.
7. `g`를 확정한 뒤 남은 하위 문제에 같은 논리를 적용합니다.

핵심은 모든 최적해가 greedy 선택을 포함한다고 증명할 필요는 없다는 점입니다.

보통 필요한 것은 다음 정도입니다.

```text
greedy 선택을 포함하는 최적해가 적어도 하나 존재합니다.
```

---

## 10. 구간 선택 greedy의 교환 논리

서로 겹치지 않는 구간을 최대 개수로 선택하는 문제에서 대표적인 greedy 규칙은 **가장 일찍 끝나는 구간을 먼저 선택하는 것**입니다.

현재 선택 가능한 구간 중 종료 시간이 가장 빠른 구간을 `g`라고 합시다.

임의의 최적해 `O`에서 첫 번째로 선택한 구간을 `o`라고 하겠습니다.

`g`가 가장 일찍 끝나는 구간이므로

```text
finish(g) <= finish(o)
```

입니다.

이제 `O`에서 `o`를 `g`로 바꿉니다.

`g`는 `o`보다 늦게 끝나지 않으므로, 원래 `o` 뒤에 올 수 있었던 구간들은 `g` 뒤에도 올 수 있습니다.

따라서 교체한 해는 여전히 실행 가능합니다.

또한 구간 하나를 구간 하나로 바꾸었으므로 선택 개수도 줄지 않습니다.

따라서

```text
g를 첫 선택으로 포함하는 최적해가 존재합니다.
```

그 뒤 `g`와 겹치지 않는 나머지 구간들에 같은 논리를 반복할 수 있습니다.

### 잘못된 설명

다음 문장만으로는 충분하지 않습니다.

```text
가장 빨리 끝나는 구간을 고르면 남은 시간이 가장 많으므로 좋습니다.
```

이는 직관일 수는 있지만, 실제로 최적값이 보존되는 이유까지 증명하지는 않습니다.

교환 후에도 실행 가능하고 목적값이 나빠지지 않는다는 연결이 필요합니다.

## 11. 동적 계획법의 불변식도 상태 의미에서 시작합니다

불변식은 반복문뿐 아니라 dynamic programming 상태를 설명하는 데도 중요합니다.

예를 들어 0/1 knapsack에서 1차원 배열 `best[c]`를 사용한다고 합시다.

단순히

```text
best[c]는 최선의 값입니다.
```

이라고 하면 무엇에 대한 최선인지 불명확합니다.

더 정확한 상태 의미는 다음처럼 써야 합니다.

```text
현재까지 처리한 물건들만 사용하여
capacity c 이하에서 얻을 수 있는 최대 가치
```

이 상태 정의가 명확해야 update 순서가 왜 중요한지도 설명할 수 있습니다.

0/1 knapsack에서 같은 물건을 한 번만 사용할 수 있게 하려면 capacity를 큰 값에서 작은 값 방향으로 갱신합니다.

그 이유는 현재 물건으로 갱신한 `best` 값을 같은 반복 안에서 다시 사용하여 동일한 물건을 여러 번 선택하는 것을 막기 위해서입니다.

따라서 DP의 정확성 설명에서도 다음을 확인합니다.

```text
상태가 정확히 무엇을 뜻합니까?
초기 상태는 그 의미와 일치합니까?
transition이 가능한 모든 경우를 포함합니까?
같은 선택을 허용 횟수보다 많이 재사용하지 않습니까?
최종 상태가 문제의 반환값과 어떻게 연결됩니까?
```

## 12. 그래프 알고리즘에서는 알고리즘마다 다른 불변식이 필요합니다

그래프 알고리즘이라고 해서 하나의 공통 불변식으로 설명할 수 있는 것은 아닙니다.

각 알고리즘이 보존하는 핵심 성질을 찾아야 합니다.

### MST / Kruskal

Kruskal 알고리즘에서는 선택한 간선 집합에 대해 다음과 같은 성질을 사용할 수 있습니다.

```text
선택한 간선들은 cycle을 만들지 않는 forest입니다.
현재까지 선택한 간선들을 모두 포함하는 MST가 적어도 하나 존재합니다.
```

DSU는 서로 이미 연결된 두 정점을 다시 잇는 간선을 거부하여 cycle 형성을 막습니다.

그러나 "cycle을 만들지 않는다"는 사실만으로 최소성은 증명되지 않습니다.

가중치가 작은 안전한 간선을 선택해도 어떤 MST와 양립할 수 있다는 cut 성질 등의 근거가 추가로 필요합니다.

### Dijkstra

모든 간선 가중치가 음수가 아니라는 전조건 아래에서 다음 성질이 핵심입니다.

```text
아직 확정되지 않은 정점 중 최소 거리 후보를 가진 정점을 확정할 때,
그 거리는 실제 최단 거리입니다.
```

heap 구현에서는 stale entry가 존재할 수 있으므로 "heap에서 꺼냈다"는 사실만으로 항상 확정이라고 표현하면 구현 세부와 충돌할 수 있습니다.

보통 현재 저장된 거리와 일치하는 유효한 최소 entry인지 확인하는 조건까지 함께 봅니다.

음수 간선이 있으면 아직 처리하지 않은 경로를 통해 나중에 더 짧은 거리가 발견될 수 있으므로 이 불변식의 근거가 깨집니다.

### Bellman–Ford

시작점에서의 최단 거리를 계산한다고 할 때 다음 의미를 사용할 수 있습니다.

```text
k번의 전체 relaxation pass가 끝난 뒤,
간선 수가 최대 k개인 경로로 도달할 수 있는 최단 거리 정보가 반영됩니다.
```

단, 구현 방식에 따라 한 pass 안에서 갱신된 값이 즉시 다시 사용되면 더 긴 경로의 정보까지 일찍 반영될 수 있습니다.

따라서 더 안전한 표현은 다음과 같습니다.

```text
k번의 pass 이후에는
간선 수가 최대 k개인 최단 경로의 거리는 반드시 반영되어 있습니다.
```

즉 "정확히 k개 이하만 반영된다"가 아니라, **최소한 그 범위까지는 보장된다**는 의미입니다.

### 최대 유량

각 augmenting path를 적용한 뒤에도 다음을 유지해야 합니다.

```text
각 간선의 flow는 capacity 제한을 위반하지 않습니다.
source와 sink를 제외한 정점에서 flow conservation이 성립합니다.
residual graph는 현재 flow를 더 늘리거나 일부 선택을 되돌릴 수 있는 가능성을 나타냅니다.
```

역방향 residual capacity는 이전에 보낸 flow 일부를 취소하고 다른 경로로 재배치할 수 있게 합니다.

따라서 단순히 "사용하지 않은 남은 capacity"만 저장하는 구조보다 더 많은 상태를 표현합니다.

## 13. 전조건은 정확성 주장의 일부입니다

알고리즘의 정확성은 모든 가능한 값에 대해 무조건 성립하는 것이 아니라, **정의된 허용 입력 범위 안에서** 성립합니다.

대표적인 전조건은 다음과 같습니다.

| 알고리즘 | 중요한 전조건 |
| --- | --- |
| 이분 탐색 | 입력이 탐색 기준에 따라 정렬되어 있어야 합니다. |
| `lower_bound` | 입력이 정렬되어 있어야 합니다. |
| Dijkstra | 모든 간선 가중치가 음수가 아니어야 합니다. |
| topological order | 모든 정점을 포함하는 위상 순서를 반환하려면 그래프가 DAG여야 합니다. |
| 배열 index 기반 알고리즘 | index가 유효 범위 안이어야 합니다. |
| 재귀 DFS | 구현 환경의 call stack이 필요한 깊이를 감당할 수 있어야 합니다. |

전조건은 다음 두 방식 중 하나로 처리됩니다.

```text
함수가 직접 검사하고 위반 시 오류를 반환합니다.
또는
호출자가 전조건을 보장해야 한다고 계약에 명시합니다.
```

어느 방식인지 명확히 해야 합니다.

### 정확성 전조건과 성능 전제를 구분합니다

다음은 결과의 정확성보다 비용 분석에 더 직접적으로 관련된 전제입니다.

```text
hash 함수가 key를 충분히 분산시킵니다.
적절한 load factor에서 resize가 수행됩니다.
```

이 전제가 깨져도 hash table이 반드시 잘못된 값을 반환하는 것은 아닙니다.

대신 기대 `O(1)` 조회라는 **성능 주장**이 깨질 수 있습니다.

따라서 전제마다 무엇을 보장하는지 구분합니다.

```text
정확성을 위한 전조건
성능 분석을 위한 전제
환경 제한에 관한 전제
```

## 14. overflow와 표현 범위도 정확성 조건입니다

수학적으로 올바른 식이라도 실제 자료형 범위를 넘으면 구현 결과는 달라질 수 있습니다.

예를 들어 두 정수의 합을 비교하는 코드가 있다고 합시다.

```text
A[i] + A[j] < target
```

수학적 정수에서는 문제가 없지만 고정 폭 정수형에서 덧셈이 표현 범위를 넘을 수 있다면 언어의 overflow 규칙에 따라 잘못된 비교가 발생할 수 있습니다.

따라서 정확성 주장을 할 때 다음 중 무엇이 성립하는지 확인합니다.

```text
입력 제한상 연산 결과가 자료형 범위 안에 있습니다.
더 넓은 자료형으로 변환한 뒤 계산합니다.
overflow를 피하는 형태로 비교식을 바꿉니다.
언어가 제공하는 checked arithmetic을 사용합니다.
```

이는 단순 구현 세부가 아니라, 수학적 증명과 실제 프로그램이 같은 연산 모델을 사용하게 만드는 조건입니다.

## 15. 테스트와 증명은 서로 다른 종류의 근거입니다

테스트와 증명은 같은 질문에 답하지 않습니다.

### 테스트가 잘 찾는 결함

테스트는 실제 구현을 실행하므로 다음 문제를 찾는 데 강합니다.

- 의사코드를 실제 언어로 잘못 옮긴 경우
- 빈 입력 처리 오류
- off-by-one index 오류
- 잘못된 종료 조건
- overflow
- 잘못된 동점 처리
- 반환값 형식 오류
- parser나 자료구조 사용 오류
- 증명에서 빠뜨린 전조건

특히 반례 테스트와 무작위 비교 검사는 예상하지 못한 구현 결함을 찾는 데 유용합니다.

### 증명이 설명하는 것

증명은 유한한 테스트 집합을 넘어 허용 입력 전체에 적용되는 논리를 제공합니다.

- 왜 탐색 영역 밖을 버려도 답을 잃지 않는가?
- 왜 현재 상태만 저장해도 충분한가?
- 왜 greedy 선택을 포함하는 최적해가 존재하는가?
- 왜 각 DP transition이 모든 경우를 포함하는가?
- 왜 모든 반복과 재귀가 종료하는가?

### 테스트는 증명을 대신하지 못합니다

아무리 많은 입력을 통과해도 아직 실행하지 않은 입력에서 실패할 가능성은 남습니다.

```text
테스트 1,000,000개 통과
≠
모든 허용 입력에서 정확하다는 증명
```

### 증명도 테스트를 대신하지 못합니다

증명한 알고리즘 아이디어가 올바르더라도 실제 구현에는 다른 결함이 들어갈 수 있습니다.

```text
증명된 의사코드
+
잘못된 index 변환
=
잘못된 프로그램
```

따라서 실전에서는 다음 흐름이 유용합니다.

```text
계약 정의
→ 정확성 근거 작성
→ 구현
→ 단위·경계·반례 테스트
→ 작은 입력에서 기준 계산과 비교
→ 발견한 실패를 회귀 테스트로 보존
```

## 16. 좋은 불변식을 찾는 방법

불변식이 바로 떠오르지 않는다면 먼저 다음 질문을 합니다.

### 무엇이 이미 확정되었습니까?

```text
이 영역의 값은 다시 볼 필요가 없습니다.
이 정점의 최단 거리는 확정되었습니다.
이 capacity까지의 최적값은 현재 물건 범위에 대해 계산되었습니다.
```

### 무엇이 아직 후보입니까?

```text
답이 존재할 수 있는 탐색 구간
아직 확정되지 않은 정점
아직 처리하지 않은 물건
```

### 어떤 관계가 계속 보존되어야 합니까?

```text
선택한 간선은 cycle을 만들지 않습니다.
flow conservation이 유지됩니다.
현재 prefix에 대한 최적값이 저장되어 있습니다.
```

좋은 불변식은 보통 알고리즘의 상태 변수가 왜 존재하는지를 설명합니다.

예를 들어 `low`, `high`를 사용하는 이유를 설명하지 못한다면 그 상태에 대응하는 불변식을 아직 명확하게 잡지 못한 것일 수 있습니다.

---

## 17. 불변식은 너무 강하거나 너무 약할 수 있습니다

불변식은 유지할 수 있을 정도로 강하면서도, 종료 시 원하는 결과를 도출할 수 있을 정도로 충분해야 합니다.

### 너무 약한 불변식

```text
0 <= low <= high <= n
```

이 조건은 index 안전성은 설명하지만, 종료 시 `low`가 왜 정답인지 설명하지 못합니다.

### 충분히 강한 불변식

```text
0 <= low <= high <= n
[0, low)의 모든 값 < target
[high, n)의 모든 값 >= target
```

이제 `low == high`와 결합하면 첫 삽입 위치를 도출할 수 있습니다.

### 지나치게 강한 불변식

다음처럼 반복 중에는 아직 알 수 없는 사실을 요구하면 유지할 수 없습니다.

```text
low는 항상 최종 정답 index입니다.
```

탐색 중 `low`는 단지 후보 구간의 왼쪽 경계일 뿐이므로 이 명제는 일반적으로 참이 아닙니다.

따라서 불변식은 다음 두 조건을 만족해야 합니다.

```text
실제로 초기화하고 유지할 수 있습니다.
종료 시 원하는 결과를 이끌어낼 만큼 충분한 정보를 담습니다.
```

## 18. 정확성 설명 양식

반복·재귀·그래프 알고리즘을 설명할 때 다음 양식을 사용할 수 있습니다.

```text
입력과 반환값:
- 입력은 무엇입니까?
- 반환값은 무엇을 뜻합니까?

전조건:
- 어떤 입력에서만 정확성 주장이 유효합니까?
- 전조건은 함수가 검사합니까, 호출자가 보장합니까?

상태가 뜻하는 값:
- 각 변수와 자료구조는 무엇을 나타냅니까?

불변식:
- 반복의 같은 위치에서 어떤 명제가 항상 참입니까?

초기화:
- 첫 반복 전에 왜 불변식이 참입니까?

유지:
- 각 분기와 상태 갱신 뒤에도 왜 불변식이 참입니까?

종료성:
- 어떤 음이 아닌 측정값이 매번 엄격히 감소합니까?

종료 시 해석:
- 종료 조건과 불변식을 합치면 무엇을 알 수 있습니까?

반환값이 조건을 만족하는 이유:
- 그 사실이 함수 계약과 어떻게 연결됩니까?

시간과 추가 공간:
- 정확성을 얻기 위해 어느 정도 자원을 사용합니까?

실패 조건:
- 전조건이 깨지거나 표현 범위를 넘는 경우 어떻게 처리합니까?
```

최적화 문제라면 다음을 추가합니다.

```text
실행 가능성:
- 반환한 답이 모든 제약을 만족하는 이유는 무엇입니까?

최적성 근거:
- 더 좋은 실행 가능한 답이 존재하지 않는 이유는 무엇입니까?
- 교환 논리, cut 성질, DP 최적 부분 구조 등 어떤 근거를 사용합니까?

동점 처리:
- 최적해가 여러 개라면 어떤 답을 반환해도 됩니까?
- 특정한 순서를 요구한다면 그 규칙을 어떻게 보장합니까?
```

## 연결 구현

[`verified-algorithms`](../../exercises/verified-algorithms/)에서 다음 근거를 직접 설명합니다.

### `lower_bound`

다음 세 영역의 의미를 유지합니다.

```text
[0, low)   : target보다 작은 것으로 확정
[low, high): 아직 후보
[high, n)  : target 이상인 것으로 확정
```

`low == high`가 되면 후보 영역이 비고 두 확정 영역의 경계가 첫 삽입 위치가 됩니다.

종료성은 `high - low`가 각 반복에서 엄격히 감소하는 것으로 설명할 수 있습니다.

### `select_intervals`

가장 일찍 끝나는 구간을 먼저 선택합니다.

정확성 설명에는 두 부분이 필요합니다.

```text
실행 가능성:
선택한 구간들이 서로 겹치지 않습니다.

최적성:
임의의 최적해의 첫 구간을 greedy가 선택한 구간으로 교체해도
실행 가능성과 선택 개수가 나빠지지 않습니다.
```

### `knapsack_01`

`best[c]`가 무엇을 뜻하는지 처리한 물건 범위와 함께 정의해야 합니다.

```text
현재까지 처리한 물건만 사용하여
capacity c 이하에서 얻을 수 있는 최대 가치
```

capacity를 역방향으로 순회하는 이유는 같은 물건을 한 iteration에서 여러 번 재사용하지 않기 위해서입니다.

### `kruskal_mst`

DSU는 현재 선택한 간선이 cycle을 만들지 않도록 합니다.

그러나 forest라는 사실만으로 최소 spanning tree의 최소성은 충분하지 않습니다.

선택하는 간선이 현재 component들을 잇는 안전한 최소 가중치 간선이며, 이를 포함하는 MST가 존재한다는 근거까지 연결해야 합니다.

### `max_flow`

각 augmenting path 적용 뒤에도 다음을 유지합니다.

```text
capacity 제한
flow conservation
현재 flow와 대응하는 residual capacity
```

역방향 residual edge는 이전 flow 일부를 취소해 다른 경로로 재배치할 수 있게 하므로, 지역적으로 선택한 증가 경로가 이후의 더 좋은 경로 구성을 영구적으로 막지 않게 합니다.

## 검토표

정확성 설명을 작성한 뒤 다음을 확인합니다.

- 함수 계약과 내부 상태의 의미를 구분했습니까?
- 불변식은 특정 상태에서 참·거짓을 판정할 수 있는 문장입니까?
- 불변식의 기준 위치가 반복 시작 전인지 끝난 후인지 명확합니까?
- 초기 상태에서 불변식이 실제로 성립합니까?
- 모든 분기에서 불변식이 유지됩니까?
- 종료 시 불변식만으로 충분한지, 종료 조건과 함께 사용해야 하는지 설명했습니까?
- 반복 또는 재귀가 반드시 끝나는 감소 측정값을 찾았습니까?
- 모든 실행 경로에서 그 측정값이 엄격히 감소합니까?
- 최적화 문제에서 실행 가능성과 최적성을 별도로 설명했습니까?
- greedy라면 국소 선택이 최적값을 보존하는 근거가 있습니까?
- 알고리즘의 전조건을 빠뜨리지 않았습니까?
- overflow나 call stack 같은 구현 환경의 조건을 확인했습니까?
- 테스트와 증명이 각각 무엇을 확인하는지 구분했습니까?

## 완료 기준

다음을 모두 설명할 수 있으면 이 문서의 핵심을 이해한 것입니다.

- 함수 계약과 반복 중 상태의 의미를 구분합니다.
- 불변식을 작은 입력의 각 반복 위치에서 참·거짓으로 판정할 수 있습니다.
- 초기화, 유지, 종료 시 해석이 반환값의 조건으로 이어지는 과정을 빠짐없이 설명합니다.
- 감소하는 측정값을 사용해 종료성을 부분 정확성과 별도로 설명합니다.
- 재귀 알고리즘의 기저 사례, 귀납 가정, 결합, 종료를 설명합니다.
- 실행 가능한 결과와 최적 결과를 구분합니다.
- greedy 알고리즘에서 교환 후 실행 가능성과 목적값이 보존되는 이유를 설명합니다.
- 그래프 알고리즘별 전조건과 핵심 불변식을 설명합니다.
- 테스트가 확인하는 유한한 사례와 증명이 다루는 허용 입력 전체를 구분합니다.

## 실패 신호

다음 중 하나라도 해당하면 정확성 설명을 다시 확인해야 합니다.

- 불변식이 "알고리즘이 올바르게 동작합니다"처럼 참·거짓을 판정할 수 없는 문장입니다.
- 불변식이 index 범위만 설명하고 실제 정답과 연결되는 정보를 포함하지 않습니다.
- 초기화와 유지 중 하나를 생략합니다.
- 특정 분기에서만 상태가 감소하고 다른 분기에서는 같은 상태가 반복될 수 있습니다.
- 종료 조건을 반환값의 정확성과 혼동합니다.
- base case가 있다는 이유만으로 재귀 종료가 보장된다고 생각합니다.
- greedy 선택이 제약을 지킨다는 사실만 보이고 최적성은 설명하지 않습니다.
- "가장 좋아 보인다"는 직관만으로 greedy의 최적성을 주장합니다.
- Dijkstra 설명에서 음수 간선이 없다는 전조건을 빠뜨립니다.
- Kruskal에서 cycle이 없다는 사실만으로 최소성을 증명했다고 생각합니다.
- Bellman–Ford의 한 pass가 정확히 특정 길이의 경로만 반영한다고 과도하게 주장합니다.
- 수학적 연산과 실제 자료형의 overflow 조건을 구분하지 않습니다.
- 테스트가 많다는 이유로 불변식이나 종료 근거를 생략합니다.
- 증명된 알고리즘이라는 이유로 구현 테스트를 생략합니다.
