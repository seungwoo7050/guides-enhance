# 정확성, 불변식과 종료

## 학습 목표

- 함수가 제공하는 입력·출력 조건과 반복 중인 상태의 의미를 구분합니다.
- 반복 불변식과 귀납법으로 부분 정확성을 설명합니다.
- 종료를 결과의 정확성과 별도로 증명합니다.
- 실행 가능한 결과와 최적 결과를 구분합니다.
- 테스트와 증명이 서로 대신할 수 없는 이유를 이해합니다.

## 선행지식

[문제 조건과 반례](01-problem-contracts-and-counterexamples.md), 반복문 상태, 수학적 귀납법의 기본 형태를 알고 있어야 합니다.

## 핵심 관점

알고리즘의 완전한 정확성은 두 주장으로 나뉩니다.

```text
부분 정확성: 함수가 종료하면 반환값이 정해진 조건을 만족합니다.
종료성: 모든 허용 입력에서 함수가 실제로 종료합니다.
```

최적화 문제에서는 다음 두 가지도 구분합니다.

```text
실행 가능성: 반환값이 모든 제약을 만족합니다.
최적성: 더 좋은 실행 가능한 답이 존재하지 않습니다.
```

## 1. 반복 불변식

불변식은 각 반복의 같은 위치에서 항상 참인 문장입니다.

증명은 다음 순서로 작성합니다.

```text
초기화: 첫 반복 전에 불변식이 참입니다.
유지: 반복 한 번이 불변식을 보존합니다.
종료: 종료 조건과 불변식을 합치면 반환값의 조건이 나옵니다.
```

### lower bound 예제

정렬된 배열에서 첫 `A[i] >= target` 위치를 찾는다고 가정합니다. 반열린 구간 `[low, high)`를 사용하면 다음을 유지할 수 있습니다.

```text
low 앞의 모든 원소는 target보다 작습니다.
high부터 뒤의 모든 원소는 target 이상입니다.
0 <= low <= high <= n입니다.
```

`low == high`가 되면 두 구간의 경계가 첫 삽입 위치입니다.

## 2. 재귀 귀납

재귀 함수는 다음 형태로 설명합니다.

```text
기저 사례: 가장 작은 입력에서 직접 조건을 만족합니다.
귀납 가정: 더 작은 하위 문제의 결과가 정확합니다.
결합: 하위 결과로 현재 문제의 결과를 계산합니다.
종료: 각 호출에서 음이 아닌 측정값이 줄어듭니다.
```

측정값은 배열 길이, 구간 길이, 남은 정점 수, 아직 결정하지 않은 변수 수처럼 잡을 수 있습니다.

## 3. greedy의 교환 논리

각 단계에서 선택을 되돌리지 않는 알고리즘은 국소 선택이 전체 최적해를 해치지 않는다는 근거가 필요합니다.

1. 임의의 최적해 `O`를 잡습니다.
2. `O`가 greedy의 첫 선택을 포함하지 않으면 일부를 greedy 선택으로 바꿉니다.
3. 바꾼 결과가 여전히 실행 가능하고 목적값이 나빠지지 않음을 보입니다.
4. greedy의 첫 선택을 포함하는 최적해가 존재하므로 남은 문제에 같은 논리를 적용합니다.

“지금 가장 좋아 보이기 때문에 선택합니다”라는 설명만으로는 최적성을 증명하지 못합니다.

## 4. 그래프 알고리즘의 불변식

문제에 맞는 상태를 사용합니다.

- MST: 현재 선택한 간선은 cycle이 없는 forest이며, 이를 포함하는 MST가 하나 이상 존재합니다.
- Dijkstra: 음수 간선이 없을 때 heap에서 현재 최소 거리로 꺼낸 정점의 거리는 확정됩니다.
- Bellman–Ford: `k`번째 전체 relaxation 뒤에는 간선 수가 최대 `k`인 경로가 반영됩니다.
- 최대 유량: 각 증가 경로를 적용한 뒤에도 capacity 제한과 flow conservation이 유지됩니다.

## 5. 전조건은 정확성 설명의 일부입니다

알고리즘의 주장은 허용한 입력 안에서만 유효합니다.

- 이분 탐색: 입력이 정렬되어 있어야 합니다.
- Dijkstra: 모든 간선 가중치가 음수가 아니어야 합니다.
- topological order: 전체 순서를 반환하려면 그래프가 DAG여야 합니다.
- hash 조회의 기대 비용: hash 분포와 resize 방식에 대한 전제가 필요합니다.
- 재귀 DFS: 입력 깊이를 call stack이 감당할 수 있어야 합니다.

이 전조건을 함수가 직접 검사하는지, 호출자가 보장해야 하는지 명확히 적습니다.

## 6. 테스트와 증명의 역할

테스트는 다음 결함을 찾는 데 강합니다.

- 의사코드를 잘못 옮긴 구현
- 빈 입력, index 오류, overflow
- 증명에서 빠뜨린 전조건
- 동점 처리와 반환값 형식 오류

증명은 다음 내용을 설명하는 데 강합니다.

- 무한히 많은 허용 입력에 공통으로 적용되는 근거
- 왜 현재 상태만 저장해도 충분한지
- 왜 greedy 선택이 최적값을 보존하는지
- 왜 모든 실행이 종료하는지

테스트 개수가 많다는 이유로 증명을 생략할 수 없고, 증명이 있다는 이유로 구현 테스트를 생략할 수도 없습니다.

## 7. 정확성 설명 양식

```text
입력과 반환값:
전조건:
상태가 뜻하는 값:
불변식:
초기화:
유지:
종료:
반환값이 조건을 만족하는 이유:
시간과 추가 공간:
실패 조건:
```

최적화 문제라면 다음을 추가합니다.

```text
실행 가능성:
최적성 근거:
동점 처리:
```

## 연결 구현

[`verified-algorithms`](../../exercises/verified-algorithms/)에서 다음 근거를 직접 설명합니다.

- `lower_bound`: 세 구간 불변식과 `low == high`의 의미
- `select_intervals`: 가장 일찍 끝나는 구간을 포함하는 최적해가 존재하는 이유
- `knapsack_01`: `best[c]`가 처리한 물건 범위와 capacity를 뜻하는 방법
- `kruskal_mst`: DSU가 cycle을 막고 선택한 간선이 forest로 남는 이유
- `max_flow`: 역방향 residual capacity가 이전 flow를 취소하는 방법

## 완료 기준

- 불변식을 작은 입력의 각 반복 위치에서 참·거짓으로 판정할 수 있습니다.
- 초기화, 유지, 종료가 반환값의 조건으로 이어지는 과정을 빠짐없이 설명합니다.
- 실행 가능한 결과와 최적 결과를 구분합니다.
- 테스트가 확인하는 사례와 증명이 다루는 전체 입력 범위를 구분합니다.

## 실패 신호

- 불변식이 “알고리즘이 올바르게 동작합니다”처럼 판정할 수 없는 문장입니다.
- 종료 조건을 결과의 정확성과 혼동합니다.
- greedy 선택이 제약을 지킨다는 사실만 보이고 최적성은 설명하지 않습니다.
- Dijkstra 설명에서 음수 간선 전조건을 빠뜨립니다.
- 테스트가 많다는 이유로 불변식이나 종료 근거를 생략합니다.
