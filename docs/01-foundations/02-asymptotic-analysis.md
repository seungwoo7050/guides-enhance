# 점근 분석

## 학습 목표

- 입력 크기와 세려는 기본 연산을 먼저 정합니다.
- `O`, `Ω`, `Θ`와 최악·평균·기대·상각 비용을 구분합니다.
- 반복문뿐 아니라 자료구조 연산, 복사, 재귀 stack, 출력 크기를 포함해 비용을 계산합니다.
- 여러 입력 변수와 희소·밀집 표현의 차이를 유지합니다.

## 선행지식

[문제 조건과 반례](01-problem-contracts-and-counterexamples.md)에서 입력 크기를 정의하는 방법과 기본적인 합·곱·로그 표기를 먼저 이해해야 합니다.

## 핵심 관점

점근 분석은 실행 시간을 초 단위로 맞히는 작업이 아닙니다. 입력이 커질 때 필요한 자원이 어떤 비율로 증가하는지 설명하는 작업입니다.

```text
입력 크기를 정합니다.
→ 기본 연산을 정합니다.
→ 연산 횟수의 상한과 하한을 계산합니다.
→ 추가로 사용하는 메모리를 계산합니다.
```

## 1. `n`의 의미부터 정합니다

- 배열: 원소 수 `n`
- 문자열 검색: 본문 길이 `n`, pattern 길이 `m`
- 그래프: 정점 수 `V`, 간선 수 `E`
- 큰 정수: 값 자체가 아니라 bit 수
- 모든 결과를 열거하는 문제: 입력 크기와 출력 개수 `k`

그래프에서 `O(V)`라고 쓰기 전에 모든 간선을 읽는 비용이 빠지지 않았는지 확인합니다. 인접 list 전체 순회는 보통 `Θ(V+E)`입니다.

## 2. 점근 표기의 의미

충분히 큰 입력에서 다음을 뜻합니다.

```text
f(n) = O(g(n))   : f가 상수배 g보다 빠르게 커지지 않습니다.
f(n) = Ω(g(n))   : f가 양의 상수배 g보다 느리게 커지지 않습니다.
f(n) = Θ(g(n))   : 위 두 조건을 모두 만족합니다.
```

`3n² + 10n + 7`은 `Θ(n²)`입니다. `O(n³)`이라고 해도 틀리지는 않지만 증가율을 불필요하게 느슨하게 표현합니다.

## 3. 입력 경우와 분석 방법을 구분합니다

```text
최악 시간 : 같은 크기의 허용 입력 중 가장 큰 비용
평균 시간 : 명시한 입력 분포에 대한 평균
기대 시간 : 알고리즘 내부 무작위성에 대한 기댓값
상각 시간 : 연속된 여러 연산의 총비용을 연산 수에 나눈 상한
```

hash 조회의 기대 비용과 동적 배열 `append`의 상각 비용은 서로 다른 주장입니다. 둘을 “평균적으로 빠릅니다”라는 한 문장으로 합치지 않습니다.

## 4. 반복문은 상태가 변하는 횟수로 계산합니다

독립적인 중첩 반복은 보통 곱으로 계산하지만, 반복 범위가 달라지면 합을 세워야 합니다.

```text
for i = 1 .. n:
    for j = 1 .. i:
        work()
```

작업 수는 `1 + 2 + ... + n = Θ(n²)`입니다.

두 pointer가 각각 한 방향으로만 움직이면 중첩된 `while`처럼 보여도 총 이동 횟수는 `O(n)`일 수 있습니다. 들여쓰기 깊이가 아니라 각 상태가 몇 번 변하는지 셉니다.

## 5. 자료구조와 언어 연산 비용을 포함합니다

자주 빠지는 비용은 다음과 같습니다.

- 길이 `k`인 문자열이나 배열 복사: `Θ(k)`
- 비교 한 번의 비용이 `C`인 정렬: 보통 `O(n log n · C)`
- heap 삽입·삭제: `O(log n)`
- 균형 tree 탐색: `O(log n)`
- hash 조회: 기대 `O(1)`, 최악 `O(n)` 가능
- 동적 배열 중간 삽입·삭제: `O(n)`
- 재귀 호출 stack: 재귀 깊이에 비례

표준 library 호출도 무료가 아닙니다. 반복문 안에서 `sorted`, slice, 문자열 연결을 사용한다면 해당 비용을 포함해야 합니다.

## 6. 출력 크기는 시간 하한이 됩니다

모든 답을 반환하거나 출력해야 하는 문제는 결과 개수보다 빨리 끝날 수 없습니다.

- 그래프의 모든 간선 반환: `Ω(E)`
- 모든 부분집합 반환: `Ω(2^n)`
- 문자열의 모든 일치 위치 반환: `Ω(k)`

따라서 `O(n+k)`처럼 입력과 출력 크기를 함께 쓰는 표현이 필요합니다.

## 7. 추가 공간과 전체 보관 공간을 구분합니다

```text
입력 그래프 저장: Θ(V+E)
방문 배열: Θ(V)
BFS queue: 최악 Θ(V)
추가 공간: Θ(V)
전체 보관 공간: Θ(V+E)
```

재귀 stack도 추가 공간입니다. 깊이가 `n`인 재귀는 `Θ(n)` stack을 사용합니다.

## 8. 여러 입력 변수를 한 변수로 뭉개지 않습니다

문자열 검색을 무조건 `O(n²)`이라고 쓰면 본문 길이와 pattern 길이의 차이를 잃습니다. 단순 검색은 보통 `O(nm)`, KMP는 `O(n+m)`입니다.

그래프도 표현에 따라 비용이 달라집니다.

- 인접 list: 전체 순회 `Θ(V+E)`
- 인접 matrix: 저장 `Θ(V²)`, 간선 존재 확인 `O(1)`
- edge list 정렬: `O(E log E)`

## 9. 점화식과 실제 비용을 연결합니다

재귀 알고리즘에서는 하위 문제의 수와 크기, 현재 호출이 수행하는 작업을 분리합니다.

```text
T(n) = 하위 문제 비용 + 현재 호출의 작업
```

예를 들어 병합 정렬은 다음과 같습니다.

```text
T(n) = 2T(n/2) + Θ(n) = Θ(n log n)
```

반면 매번 한쪽에 모든 원소가 몰리는 quicksort는 다음과 같습니다.

```text
T(n) = T(n-1) + Θ(n) = Θ(n²)
```

## 검토표

- 입력 변수마다 의미를 적었습니까?
- 최악·평균·기대·상각 중 무엇을 분석했는지 밝혔습니까?
- library 호출, 복사, 재귀 stack을 포함했습니까?
- 출력 개수가 시간 하한이 되는지 확인했습니까?
- 정수 연산을 상수 시간으로 보는 전제가 적절합니까?
- 추가 공간과 입력 저장 공간을 구분했습니까?

## 연결 구현

[`verified-algorithms`](../../exercises/verified-algorithms/)에서 다음 비용을 직접 설명합니다.

- `prefix_sums`: 전처리 `O(n)`, 질의 `O(1)`, 추가 공간 `O(n)`
- `lower_bound`: 시간 `O(log n)`, 추가 공간 `O(1)`
- `dijkstra`: 인접 list와 heap을 사용할 때 `O((V+E) log V)`
- `bellman_ford`: `O(VE)`
- `kmp_find`: 전처리와 검색을 합쳐 `O(n+m)`

## 완료 기준

- 모든 비용식에서 각 변수의 의미를 먼저 정의합니다.
- 최악·기대·상각 비용을 구분합니다.
- library 호출, 복사, 재귀 stack, 출력 크기까지 포함해 다시 계산합니다.
- 그래프의 희소·밀집 표현에 따라 비용이 달라지는 이유를 설명합니다.

## 실패 신호

- `O(n)`이라고 쓰면서 `n`이 무엇인지 정의하지 않습니다.
- 평균 비용과 상각 비용을 같은 뜻으로 사용합니다.
- 그래프 비용을 항상 `O(V²)` 또는 항상 `O(V+E)`라고 단정합니다.
- 재귀 stack이나 반환 결과 저장 공간을 무시합니다.
- benchmark 한 번을 점근 분석의 근거로 사용합니다.
