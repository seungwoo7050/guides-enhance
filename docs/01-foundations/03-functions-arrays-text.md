# 함수·배열·문자열

함수는 코드를 단순히 잘게 나누는 수단이 아닙니다. 함수 하나는 **호출자와 구현 사이의 계약(contract)**을 만듭니다.

함수를 읽을 때는 최소한 다음을 확인해야 합니다.

```text
무엇을 입력으로 받는가?
어떤 입력이 유효한가?
성공하면 무엇을 반환하거나 기록하는가?
실패하면 무엇을 반환하는가?
실패했을 때 출력 값은 변경되는가?
전달받은 포인터가 가리키는 자원의 소유권은 누구에게 있는가?
```

배열과 문자열을 다룰 때는 특히 주의해야 합니다. C 함수는 배열의 길이를 자동으로 알지 못하며, C 문자열은 별도의 문자열 객체가 아니라 **마지막에 NUL 바이트(`'\0'`)가 있는 `char` 배열**이라는 규칙에 의존합니다.

## 함수 선언과 호출

다음 함수 선언을 봅시다.

```c
int parse_count(const char *text, size_t *out_count);
```

선언만 보고도 함수의 역할을 어느 정도 추론할 수 있습니다.

- `text`는 입력 문자열을 가리키는 포인터입니다.
- `const char *`이므로 함수는 `text`가 가리키는 문자를 이 포인터를 통해 수정하지 않겠다는 뜻입니다.
- `out_count`는 성공한 결과를 기록할 위치를 가리킵니다.
- 반환형이 `int`이므로 반환값을 성공·실패 상태에 사용할 수 있습니다.

예를 들어 다음과 같은 계약을 정할 수 있습니다.

```text
입력:
    text는 유효한 NUL 종료 문자열이어야 한다.
    out_count는 결과를 저장할 수 있는 유효한 size_t 객체를 가리켜야 한다.

성공:
    0을 반환한다.
    변환 결과를 *out_count에 기록한다.

실패:
    0이 아닌 값을 반환한다.
    *out_count는 변경하지 않는다.
```

이 계약을 따르는 구현은 다음과 같이 작성할 수 있습니다.

```c
int parse_count(const char *text, size_t *out_count) {
    size_t value;

    if (text == NULL || out_count == NULL) {
        return -1;
    }

    if (parse_size(text, &value) != 0) {
        return -1;
    }

    *out_count = value;
    return 0;
}
```

핵심은 결과를 바로 `*out_count`에 기록하지 않고 먼저 지역 변수 `value`에 계산한다는 점입니다.

```c
size_t value;
```

모든 검사가 성공한 뒤 마지막에:

```c
*out_count = value;
```

를 수행하므로 실패 시 호출자가 넘긴 값은 그대로 유지됩니다.

예를 들어:

```c
size_t count = 100;

if (parse_count("잘못된 입력", &count) != 0) {
    /* count는 여전히 100이라고 계약할 수 있습니다. */
}
```

이 규칙은 호출자가 부분적으로 갱신된 값을 해석할 필요가 없게 해 줍니다.

단, 이런 동작은 C 언어가 자동으로 보장하는 것이 아니라 **함수가 정한 계약**입니다. 다른 함수는 실패 시 출력 매개변수의 값을 보장하지 않을 수도 있으므로 함수의 문서나 구현 규칙을 확인해야 합니다.

## 선언과 정의

함수의 **선언(declaration)**은 함수의 이름, 반환형, 매개변수 타입을 알려 줍니다.

```c
int parse_count(const char *text, size_t *out_count);
```

함수의 **정의(definition)**는 실제 함수 본문까지 포함합니다.

```c
int parse_count(const char *text, size_t *out_count) {
    /* 실제 구현 */
}
```

호출하는 코드보다 앞에 함수 정의가 없다면, 보통 헤더 파일이나 앞쪽 선언을 통해 컴파일러가 함수의 타입을 알 수 있어야 합니다.

예:

```c
int parse_count(const char *text, size_t *out_count);

int main(void) {
    /* parse_count 호출 가능 */
}
```

선언과 정의의 타입이 일치해야 합니다. 매개변수 타입이나 반환형을 다르게 선언하면 잘못된 호출이나 컴파일 진단의 원인이 됩니다.

## 값 전달과 포인터 전달

C 함수의 인자는 **항상 값으로 전달(pass by value)**됩니다.

다음 코드를 봅시다.

```c
void increment(int value) {
    value++;
}
```

호출:

```c
int number = 10;
increment(number);
```

함수의 `value`에는 `number`의 값인 `10`이 복사됩니다.

함수 내부에서:

```c
value++;
```

를 실행하면 복사된 지역 변수만 바뀝니다. 호출자의 `number`는 그대로입니다.

```text
number == 10
```

호출자의 객체를 수정하려면 그 객체의 **주소 값을 인자로 전달**해야 합니다.

```c
int increment(int *value) {
    if (value == NULL) {
        return -1;
    }

    (*value)++;
    return 0;
}
```

호출자는 다음과 같이 주소를 전달합니다.

```c
int number = 10;

if (increment(&number) != 0) {
    /* 실패 처리 */
}
```

이제 함수가 받은 것은 `number` 자체가 아니라 `number`의 주소 값입니다.

```text
value      → number의 주소
*value     → number 객체
```

따라서:

```c
(*value)++;
```

는 호출자의 `number`를 수정합니다.

### 포인터도 값으로 전달된다

"포인터 전달"이라는 표현 때문에 C가 참조 전달을 지원한다고 오해할 수 있습니다. 실제로는 포인터도 하나의 값이며, **포인터 값 자체가 복사되어 함수에 전달됩니다**.

예를 들어:

```c
void reset_pointer(int *pointer) {
    pointer = NULL;
}
```

이 함수는 호출자의 포인터 변수를 `NULL`로 바꾸지 않습니다.

```c
int value = 10;
int *pointer = &value;

reset_pointer(pointer);
```

함수 내부의 `pointer` 복사본만 `NULL`이 됩니다. 호출자의 `pointer`는 여전히 `&value`를 가리킵니다.

호출자의 포인터 변수 자체를 바꾸려면 포인터의 주소를 전달해야 합니다.

```c
void reset_pointer(int **pointer) {
    if (pointer != NULL) {
        *pointer = NULL;
    }
}
```

## 포인터와 소유권

포인터를 함수에 전달했다고 해서 함수가 그 객체나 메모리를 **소유(ownership)**하게 되는 것은 아닙니다.

예를 들어:

```c
void print_text(const char *text);
```

이 함수가 단순히 `text`를 읽고 출력하는 용도라면 보통 호출자가 메모리의 소유권을 유지합니다.

반면 어떤 함수는 동적 메모리를 새로 할당하여 호출자에게 넘길 수 있습니다.

```c
char *make_message(void);
```

이 경우 반환된 메모리를 누가 `free`해야 하는지 계약이 필요합니다.

따라서 포인터를 받거나 반환하는 함수는 다음을 명확히 정해야 합니다.

```text
포인터가 NULL이어도 되는가?
가리키는 객체를 읽기만 하는가?
객체를 수정할 수 있는가?
함수가 메모리를 해제할 수 있는가?
함수가 새 메모리를 할당한다면 누가 해제하는가?
함수 호출 뒤에도 포인터가 유효한가?
```

`const`는 수정 가능성에 대한 정보를 제공하지만 소유권 자체를 나타내지는 않습니다.

## 배열과 길이

함수 매개변수에서 다음 두 선언은 실질적으로 같은 형태로 조정됩니다.

```c
long sum_values(const long values[], size_t length);
```

```c
long sum_values(const long *values, size_t length);
```

함수 매개변수 위치의 배열 표기:

```c
const long values[]
```

는 함수 타입을 정할 때 포인터 타입:

```c
const long *values
```

로 조정됩니다.

따라서 함수는 `values`라는 매개변수만 보고 배열의 전체 크기나 원소 개수를 자동으로 알 수 없습니다.

길이를 별도의 인자로 전달해야 합니다.

```c
long sum_values(const long *values, size_t length) {
    long total = 0;

    for (size_t index = 0; index < length; index++) {
        total += values[index];
    }

    return total;
}
```

이 함수의 계약은 예를 들어 다음과 같이 정할 수 있습니다.

```text
length > 0이면
    values는 최소 length개의 long 원소를 읽을 수 있는 유효한 메모리를 가리켜야 한다.

length == 0이면
    values를 NULL로 허용할지 여부는 함수 계약으로 정한다.
```

### `sizeof`로 함수 안에서 배열 길이를 구할 수 없는 이유

다음 코드는 배열처럼 보이지만 함수 안에서 `values`는 포인터입니다.

```c
void inspect(const int values[]) {
    /* values는 배열 전체가 아니라 포인터 매개변수입니다. */
}
```

따라서:

```c
sizeof(values)
```

는 원래 배열 전체의 바이트 크기가 아니라 **포인터 자체의 크기**를 구합니다.

예를 들어 호출자가:

```c
int numbers[100];
inspect(numbers);
```

라고 하더라도 `inspect` 안에서 `sizeof(values)`를 이용해 원소 수 `100`을 복원할 수 없습니다.

배열 길이가 필요하면 다음처럼 함께 전달해야 합니다.

```c
inspect(numbers, 100);
```

또는 호출 위치에서 실제 배열 객체가 보이는 경우:

```c
size_t length = sizeof(numbers) / sizeof(numbers[0]);
inspect(numbers, length);
```

처럼 계산할 수 있습니다.

이 계산은 `numbers`가 실제 배열 객체로 보이는 범위에서만 배열 전체 크기를 이용할 수 있다는 점이 중요합니다.

## 배열 인덱스의 유효 범위

길이가 `length`인 배열의 유효한 인덱스는 다음과 같습니다.

```text
0부터 length - 1까지
```

따라서 배열에 접근하기 전에:

```c
index < length
```

인지 확인합니다.

```c
if (index >= length) {
    return -1;
}

value = values[index];
```

`index == length`인 위치는 배열 바로 다음 위치이므로 원소로 읽거나 쓸 수 없습니다.

배열 포인터가 `NULL`일 가능성이 있다면 포인터 검사도 먼저 필요합니다.

```c
if (values == NULL || index >= length) {
    return -1;
}
```

단, `length == 0`일 때 `values == NULL`을 허용하는 API를 만들 수도 있습니다. 이 경우 함수 계약을 그 규칙에 맞게 작성해야 합니다.

## 문자열은 NUL로 끝나는 `char` 배열

C 문자열은 별도의 문자열 객체가 아니라 **NUL 문자 `'\0'`을 마지막에 포함하는 `char`의 연속된 배열**입니다.

예:

```c
char text[] = {'h', 'i', '\0'};
```

메모리에는 개념적으로 다음과 같이 저장됩니다.

```text
'h'  'i'  '\0'
```

문자열 리터럴을 이용하면 더 간단하게 쓸 수 있습니다.

```c
char text[] = "hi";
```

이 경우 컴파일러가 마지막 NUL 문자를 포함하는 배열을 만듭니다.

```text
'h'  'i'  '\0'
```

따라서:

```c
sizeof(text)
```

는 이 경우 `3`입니다.

반면 문자열의 **길이**는 마지막 `'\0'`을 제외한 문자 수입니다.

```c
strlen(text)
```

의 결과는 `2`입니다.

즉:

```text
배열 크기: 3바이트
문자열 길이: 2
```

입니다.

## `strlen`이 요구하는 전제

`strlen`은 다음 NUL 문자를 찾을 때까지 메모리를 계속 읽습니다.

```c
size_t strlen(const char *s);
```

따라서 인자로 전달하는 포인터는 **유효한 NUL 종료 문자열**을 가리켜야 합니다.

예를 들어 다음 배열은 C 문자열이 아닙니다.

```c
char text[2] = {'h', 'i'};
```

배열 안에 `'\0'`이 없습니다.

이 배열을 다음처럼 전달하면:

```c
strlen(text);
```

`strlen`은 배열의 끝을 지나서도 NUL 문자를 찾으려고 읽게 되므로 정의되지 않은 동작이 발생합니다.

단순한 문자열 길이 함수도 같은 전제가 필요합니다.

```c
size_t text_length(const char *text) {
    size_t length = 0;

    if (text == NULL) {
        return 0;
    }

    while (text[length] != '\0') {
        length++;
    }

    return length;
}
```

이 구현은 `NULL`인 경우 `0`을 반환하도록 별도의 정책을 정했지만, `text != NULL`이라고 해서 무조건 안전한 것은 아닙니다.

`text`가 실제로 NUL 종료 문자열을 가리켜야 합니다.

즉 이 함수가 안전하려면 다음 조건이 필요합니다.

```text
text == NULL
또는
text가 접근 가능한 범위 안에 '\0'을 포함하는 문자열을 가리킨다.
```

실제 표준 `strlen`은 `NULL`을 허용하지 않습니다. `NULL`을 전달하면 정의되지 않은 동작이 발생합니다.

따라서 사용자 정의 함수가 `NULL`을 특별하게 처리한다면 표준 함수와 다른 계약을 가진다는 점을 분명히 해야 합니다.

## 문자열 공간과 마지막 NUL 바이트

문자열 길이가 `length`라면 내용을 복사하기 위해 필요한 저장 공간은 보통:

```text
length + 1
```

바이트입니다.

추가되는 1바이트는 마지막 NUL 문자를 위한 공간입니다.

예를 들어 `"hello"`는 문자 수가 5이지만 저장에는 다음 6바이트가 필요합니다.

```text
'h' 'e' 'l' 'l' 'o' '\0'
```

따라서:

```c
char buffer[6] = "hello";
```

는 충분합니다.

반면 다음 배열은 문자열의 모든 문자와 종료 문자를 동시에 저장하기에 부족합니다.

```c
char buffer[5];
```

문자열을 복사하거나 동적으로 메모리를 할당할 때는 이 마지막 바이트를 빠뜨리지 않아야 합니다.

동적 할당 예시는 다음과 같습니다.

```c
size_t length = strlen(source);
char *copy = malloc(length + 1);
```

단, `length + 1` 자체가 `size_t` 범위를 넘을 가능성까지 고려해야 하는 일반적인 라이브러리 코드라면 덧셈 전에 overflow 여부도 확인해야 합니다.

## 문자열 리터럴과 수정 가능 여부

문자열 리터럴은 다음처럼 사용할 수 있습니다.

```c
const char *message = "hello";
```

문자열 리터럴의 문자를 수정하려는 동작은 정의되지 않은 동작입니다.

따라서 다음처럼 사용해서는 안 됩니다.

```c
char *message = "hello";
message[0] = 'H';   /* 정의되지 않은 동작 */
```

일부 컴파일러가 이 코드를 허용하더라도 수정이 안전하다는 의미는 아닙니다.

읽기 전용으로 사용할 목적이라면 다음처럼 `const` 포인터로 받는 편이 의도를 분명하게 드러냅니다.

```c
const char *message = "hello";
```

수정 가능한 문자열이 필요하다면 별도의 배열을 만듭니다.

```c
char message[] = "hello";
message[0] = 'H';
```

이 경우 `message`는 다음 내용을 가진 수정 가능한 배열입니다.

```text
'H' 'e' 'l' 'l' 'o' '\0'
```

## 배열과 포인터는 완전히 같은 것이 아니다

배열이 함수 인자로 전달될 때 포인터로 조정되기 때문에 배열과 포인터가 같은 것처럼 보일 수 있지만, 둘은 동일한 개념이 아닙니다.

예를 들어:

```c
char array[] = "hello";
char *pointer = array;
```

`array`는 실제로 여러 개의 `char` 원소를 포함하는 배열 객체입니다.

`pointer`는 그 배열의 첫 원소 주소를 저장하는 포인터 객체입니다.

따라서:

```c
sizeof(array)
```

는 배열 전체 크기를 구하지만:

```c
sizeof(pointer)
```

는 포인터 하나의 크기를 구합니다.

많은 표현식에서 배열 이름은 첫 원소를 가리키는 포인터로 변환되지만, **배열 자체와 포인터 변수 자체가 같은 객체라는 뜻은 아닙니다**.

이 차이는 `sizeof`, 주소 계산, 함수 매개변수의 의미를 이해할 때 중요합니다.

## `ctype` 함수와 음수 `char`

`<ctype.h>`에는 문자 분류와 변환을 위한 함수들이 있습니다.

예:

```c
isspace
isdigit
isalpha
toupper
tolower
```

이 함수들의 인자는 아무 `int` 값이나 사용할 수 있는 것이 아닙니다.

인자로 전달할 수 있는 값은 다음 둘 중 하나여야 합니다.

```text
EOF
또는
unsigned char로 표현 가능한 값을 int로 변환한 값
```

문자열을 순회하면서 다음과 같이 쓰는 것은 위험할 수 있습니다.

```c
if (isspace(*cursor)) {
    /* ... */
}
```

`char`가 부호 있는 타입인 환경에서는 상위 비트가 설정된 바이트가 음수로 해석될 수 있습니다.

예를 들어 어떤 바이트 값이 `char`에서 음수가 되었는데 그것이 `EOF`도 아니라면 `isspace`의 허용 범위를 벗어난 값이 됩니다. 이 경우 동작은 정의되지 않습니다.

따라서 일반적인 안전 패턴은 다음과 같습니다.

```c
if (isspace((unsigned char)*cursor)) {
    /* 공백 문자입니다. */
}
```

변환 순서는 개념적으로 다음과 같습니다.

```text
*cursor
→ unsigned char로 변환
→ 정수 승격
→ isspace에 전달
```

`isdigit`, `isalpha`, `tolower`, `toupper` 등에도 같은 원칙을 적용합니다.

예:

```c
if (isdigit((unsigned char)*cursor)) {
    /* 숫자 문자 */
}
```

단, `getchar()`처럼 이미 `int`를 반환하고 `EOF`를 구분해야 하는 함수의 결과는 별도로 생각해야 합니다.

예를 들어:

```c
int ch = getchar();

if (ch != EOF && isspace(ch)) {
    /* ... */
}
```

이 경우 `ch`는 `getchar()`가 반환한 `int` 값이므로 `EOF` 여부를 유지한 채 사용할 수 있습니다.

## `struct`로 함께 변하는 값 묶기

여러 값이 하나의 논리적 상태를 함께 표현한다면 구조체로 묶는 것이 좋습니다.

```c
struct buffer {
    char *data;
    size_t length;
    size_t capacity;
};
```

각 필드의 의미를 명확히 정합니다.

```text
data     → 실제 저장 공간의 시작 주소
length   → 현재 사용 중인 데이터의 길이
capacity → 현재 확보된 저장 공간의 크기
```

이 구조체를 올바르게 사용하려면 필드 사이에 유지되어야 하는 조건을 정해야 합니다.

이런 조건을 **불변식(invariant)**이라고 부릅니다.

예를 들어 다음 조건을 정할 수 있습니다.

```text
length <= capacity
capacity == 0이면 data == NULL
문자열을 저장한다면 data[length] == '\0'
```

다만 문자열 버퍼에서 `data[length] == '\0'`을 유지하려면 NUL 바이트를 저장할 공간도 실제로 존재해야 합니다.

따라서 `capacity`를 "할당된 전체 바이트 수"로 정의한다면 문자열이 들어 있는 상태에서는 보통:

```text
length < capacity
```

가 필요합니다.

왜냐하면:

```text
data[0] ... data[length - 1] → 문자열 내용
data[length]                 → '\0'
```

이기 때문입니다.

반대로 `capacity`를 "NUL을 제외하고 저장 가능한 문자 수"로 정의한다면 다른 관계를 사용할 수도 있습니다.

중요한 것은 **필드의 의미를 먼저 정의하고 모든 함수가 같은 정의를 따르는 것**입니다.

## 구조체 불변식은 자동으로 지켜지지 않는다

구조체를 선언했다고 해서 내부 상태가 자동으로 올바르게 유지되는 것은 아닙니다.

예를 들어:

```c
struct buffer buffer;
```

만 선언하면 각 필드는 초기화되지 않은 값을 가질 수 있습니다.

명확한 초기 상태를 만드는 함수가 필요할 수 있습니다.

```c
void buffer_init(struct buffer *buffer) {
    if (buffer == NULL) {
        return;
    }

    buffer->data = NULL;
    buffer->length = 0;
    buffer->capacity = 0;
}
```

이후 버퍼를 변경하는 함수도 불변식을 깨뜨리지 않아야 합니다.

예를 들어 크기를 늘리는 함수는 단순히 `capacity`만 바꾸는 것이 아니라 실제 메모리 공간도 그 값과 일치하도록 조정해야 합니다.

마찬가지로 문자열을 저장하는 버퍼라면 내용을 변경한 뒤에도 적절한 위치에 `'\0'`을 유지해야 합니다.

따라서 구조체 상태를 다루는 함수는 다음을 생각해야 합니다.

```text
호출 전 어떤 불변식이 성립해야 하는가?
성공 후 어떤 불변식이 성립해야 하는가?
실패했을 때 기존 상태는 유지되는가?
자원 소유권은 바뀌는가?
```

## 함수 이름은 실제 동작을 드러내기

함수 이름은 구현 방법보다 **무엇을 하는지**를 드러내는 것이 좋습니다.

예를 들어 다음 작업들은 서로 다른 역할을 가집니다.

```text
문자열을 정수로 변환한다.
통계 값에 새 정수를 추가한다.
결과를 stdout에 출력한다.
동적 버퍼의 크기를 늘린다.
파일에서 남은 바이트를 읽는다.
```

이런 작업에는 다음처럼 대상과 동작이 드러나는 이름을 붙일 수 있습니다.

```c
parse_integer(...)
statistics_add(...)
print_result(...)
buffer_grow(...)
read_remaining_bytes(...)
```

반면 다음과 같은 이름은 함수가 무엇을 입력으로 받고 어떤 상태를 바꾸는지 알기 어렵습니다.

```c
process(...)
handle(...)
manage(...)
```

이런 이름이 항상 잘못된 것은 아니지만, 코드의 문맥 없이도 함수의 역할을 추론할 수 있는 구체적인 이름이 유지보수에 더 도움이 됩니다.

## 반환값과 출력 매개변수

함수가 실패할 수 있으면서 성공한 결과도 반환해야 할 때 **상태 반환값 + 출력 매개변수** 패턴을 사용할 수 있습니다.

예:

```c
int vector_get(
    const struct vector *vector,
    size_t index,
    int *out_value
) {
    if (vector == NULL ||
        out_value == NULL ||
        index >= vector->size) {
        return -1;
    }

    *out_value = vector->data[index];
    return 0;
}
```

이 함수의 계약을 다음처럼 정할 수 있습니다.

```text
성공:
    0 반환
    *out_value에 요청한 값을 기록

실패:
    -1 반환
    *out_value는 변경하지 않음
```

중요한 점은 모든 검사보다 먼저 출력 값을 변경하지 않는 것입니다.

다음처럼 작성하면 실패 시 부분 변경이 생길 수 있습니다.

```c
*out_value = 0;

if (vector == NULL || index >= vector->size) {
    return -1;
}
```

이 경우 호출자는 실패했는데도 `*out_value`가 바뀐 상태를 보게 됩니다.

반면 앞의 구현은 모든 검사를 끝낸 뒤:

```c
*out_value = vector->data[index];
```

를 수행하므로 실패하면 출력 매개변수를 그대로 유지할 수 있습니다.

## 출력 매개변수 패턴을 호출하는 방법

호출자는 먼저 결과를 받을 객체를 준비합니다.

```c
int value;

if (vector_get(&vector, 3, &value) != 0) {
    fprintf(stderr, "원소를 읽을 수 없습니다.\n");
    return -1;
}

printf("%d\n", value);
```

중요한 점은 반환값을 먼저 검사하고 성공한 경우에만 `value`를 결과로 사용한다는 것입니다.

함수 계약상 실패 시 `value`가 유지된다고 하더라도, 실패한 호출의 출력 값을 새 결과처럼 사용하는 것은 좋지 않습니다.

```text
함수 호출
→ 반환 상태 검사
→ 성공한 경우에만 출력 값 사용
```

이 순서를 습관화하면 실패 처리가 명확해집니다.

## `const`가 의미하는 것

다음 선언을 비교해 봅시다.

```c
const char *text;
char *text;
```

`const char *text`는 `text`를 통해 가리키는 문자를 수정하지 않겠다는 뜻입니다.

```c
text[0] = 'A';   /* 허용되지 않음 */
```

반면:

```c
char *text;
```

는 가리키는 문자를 수정할 수 있는 타입입니다. 물론 실제로 가리키는 객체가 수정 가능한 메모리여야 합니다.

`const`는 함수 계약을 더 분명하게 만드는 데 유용합니다.

예를 들어:

```c
size_t count_spaces(const char *text);
```

라는 선언은 함수가 문자열을 읽어서 계산하지만, 문자열 내용을 바꾸는 함수는 아니라는 의도를 드러냅니다.

그러나 `const`는 다음을 자동으로 보장하지 않습니다.

```text
포인터가 NULL이 아니다.
포인터가 유효한 메모리를 가리킨다.
문자열이 NUL로 끝난다.
함수가 메모리를 소유하지 않는다.
```

이 조건들은 별도의 함수 계약으로 정해야 합니다.

## 함수 인터페이스를 읽는 순서

함수 하나를 처음 볼 때 다음 순서로 읽으면 좋습니다.

예를 들어:

```c
int parse_count(const char *text, size_t *out_count);
```

### 1. 반환형 확인

```c
int
```

성공·실패 상태를 나타내는 데 쓰이는지 확인합니다.

### 2. 입력 매개변수 확인

```c
const char *text
```

읽기 전용 문자열 입력이라는 의도를 확인합니다.

### 3. 출력 매개변수 확인

```c
size_t *out_count
```

함수가 호출자의 객체에 결과를 기록한다는 점을 확인합니다.

### 4. `NULL` 허용 여부 확인

두 포인터가 `NULL`일 때 함수가 어떻게 동작하는지 계약을 확인합니다.

### 5. 실패 시 상태 확인

실패했을 때 `*out_count`가 유지되는지, 일부만 변경될 수 있는지 확인합니다.

### 6. 소유권 확인

함수가 `text`나 `out_count`가 가리키는 메모리를 해제하거나 소유권을 가져가는지 확인합니다.

이 습관은 함수 호출 코드를 읽을 때도 그대로 적용할 수 있습니다.

## 완료 기준

다음을 직접 설명하고 작성할 수 있어야 합니다.

1. 함수 선언만 보고 입력, 출력 매개변수, 반환값의 역할을 설명합니다.
2. 함수 선언과 함수 정의의 차이를 설명합니다.
3. C의 모든 인자가 값으로 전달되며, 포인터도 포인터 값의 복사본이 전달된다는 점을 설명합니다.
4. 호출자의 객체를 수정하려면 그 객체의 주소를 전달해야 하는 이유를 설명합니다.
5. 포인터 전달과 메모리 소유권 이전이 서로 다른 개념임을 설명합니다.
6. 함수 매개변수의 배열 표기가 포인터 타입으로 조정된다는 점을 설명합니다.
7. 함수가 배열의 길이를 자동으로 알 수 없으므로 배열과 길이를 함께 전달합니다.
8. 함수 안에서 배열 매개변수에 `sizeof`를 사용해 원래 배열 길이를 구할 수 없는 이유를 설명합니다.
9. 길이가 `length`인 배열의 유효 인덱스가 `0`부터 `length - 1`까지임을 설명합니다.
10. C 문자열이 NUL 바이트로 끝나는 `char` 배열이라는 점을 설명합니다.
11. `strlen`에 전달하는 값이 반드시 유효한 NUL 종료 문자열이어야 하는 이유를 설명합니다.
12. 문자열 저장 공간을 계산할 때 마지막 NUL 바이트를 위한 `length + 1` 공간을 고려합니다.
13. 문자열 리터럴을 수정하지 않고, 수정 가능한 문자열이 필요하면 배열을 만듭니다.
14. 배열과 포인터가 여러 표현식에서 밀접하게 연결되지만 동일한 객체는 아니라는 점을 설명합니다.
15. `ctype` 함수에는 `EOF` 또는 `unsigned char`로 표현 가능한 값을 전달해야 하는 이유를 설명합니다.
16. 함께 변하는 상태를 구조체로 묶고, 필드 사이에 유지되어야 하는 불변식을 작성합니다.
17. 실패 가능한 함수에서 출력 매개변수를 모든 검사가 끝난 뒤 갱신하여 실패 시 기존 값을 보존하는 패턴을 작성합니다.
18. `const`가 수정 가능성에 관한 정보는 제공하지만 유효성이나 소유권까지 보장하지는 않는다는 점을 설명합니다.
