# 순서, 탐색, 힙과 우선순위

## 학습 목표

- 정렬이 단순히 원소를 보기 좋게 배치하는 작업이 아니라 이후 질의를 빠르게 만들기 위한 전처리라는 점을 설명합니다.
- 이분 탐색에서 탐색 구간, 판정 조건, 동점 처리, 반환 위치를 명확히 정의합니다.
- heap이 보장하는 부분 순서와 정렬된 배열이 보장하는 전체 순서를 구분합니다.
- 답을 직접 찾기 어려운 문제를 단조 판정 함수로 바꾸어 parametric search를 설계합니다.

## 선행지식

[선형 자료구조와 구간](01-linear-structures-ranges-and-hashing.md), 비교 순서, [정확성 문서](../01-foundations/04-correctness-and-invariants.md)의 lower bound 불변식을 먼저 이해해야 합니다.

특히 다음 개념을 알고 있어야 합니다.

- 반열린 구간 `[left, right)`
- `O(log n)`, `O(n log n)` 시간 복잡도
- 정렬된 입력에서의 단조성
- 루프 불변식과 종료 조건

## 핵심 관점

정렬하면 일부 연산이 빨라지지만 그 대가도 있습니다.

```text
정렬 비용
+ 이후 질의 비용
+ 갱신 비용
+ 원래 순서를 보존하는 비용
```

따라서 다음처럼 생각합니다.

```text
정렬한 뒤 무엇이 빨라집니까?
정렬 비용을 몇 번의 질의로 회수합니까?
입력이 자주 바뀝니까?
원래 입력 순서가 정답의 일부입니까?
전체 순서가 필요합니까, 최솟값 하나만 필요합니까?
```

자료구조와 알고리즘은 이름보다 **필요한 순서 정보의 강도**를 기준으로 선택합니다.

## 1. 정렬을 사용하는 이유

정렬은 원소 사이에 전체 순서를 만들어 이후 알고리즘이 구조를 이용할 수 있게 하는 전처리입니다.

정렬한 뒤에는 다음 작업을 수행하기 쉬워집니다.

- 같은 값을 연속된 구간으로 묶습니다.
- two pointers를 사용합니다.
- 이분 탐색을 수행합니다.
- sweep line에서 event 처리 순서를 고정합니다.
- greedy 선택 순서를 고정합니다.
- 중복을 제거하고 순위를 계산합니다.

예를 들어 정렬되지 않은 배열에서 특정 값의 존재 여부를 한 번 찾는다면 선형 탐색으로 `O(n)`에 찾을 수 있습니다.

```text
한 번 검색:
선형 탐색 O(n)

정렬 후 검색:
정렬 O(n log n) + 이분 탐색 O(log n)
```

질의가 한 번뿐이라면 정렬이 오히려 더 비쌀 수 있습니다.

반대로 같은 배열에 대해 `q`번 검색한다면 다음을 비교할 수 있습니다.

```text
매번 선형 탐색:
O(qn)

한 번 정렬 후 매번 이분 탐색:
O(n log n + q log n)
```

`q`가 충분히 크면 정렬 비용을 이후 질의에서 회수할 수 있습니다.

### 정렬이 입력을 바꾸는 비용

정렬은 값의 원래 위치를 바꿉니다.

원래 index가 필요하다면 값을 단독으로 정렬하지 않고 다음처럼 원래 위치를 함께 보존할 수 있습니다.

```text
(value, original_index)
```

따라서 정렬 여부를 결정할 때는 시간 복잡도뿐 아니라 **원래 순서를 잃어도 되는지**도 확인해야 합니다.

## 2. lower bound

오름차순으로 정렬된 배열 `A`에서 `lower_bound(target)`는 다음 위치를 찾습니다.

> 첫 번째 `A[i] >= target`인 index `i`

그런 원소가 없으면 `len(A)`를 반환합니다.

예:

```text
A = [1, 2, 2, 2, 5, 8]

lower_bound(2) = 1
lower_bound(3) = 4
lower_bound(9) = 6
lower_bound(0) = 0
```

`target`이 실제 배열에 존재하지 않아도 **삽입해도 정렬 순서를 깨뜨리지 않는 첫 위치**를 반환한다는 점이 중요합니다.

### 구현

```text
low = 0
high = len(A)

while low < high:
    middle = low + (high - low) // 2

    if A[middle] < target:
        low = middle + 1
    else:
        high = middle

return low
```

이 구현은 탐색 구간을 `[low, high)`로 해석합니다.

### 유지하는 불변식

루프가 반복되는 동안 다음 조건을 유지합니다.

```text
0 <= low <= high <= n

index < low 인 모든 원소는 target보다 작습니다.
index >= high 인 모든 원소는 target 이상입니다.

아직 답일 수 있는 위치는 [low, high)에 있습니다.
```

여기서 두 번째와 세 번째 조건이 핵심입니다.

```text
[0, low)      : 답이 될 수 없음, 모두 A[i] < target
[low, high)   : 아직 확인해야 하는 후보
[high, n)     : 답보다 오른쪽이거나 답 자체일 수 있으며 모두 A[i] >= target
```

### 왜 갱신이 안전한가

`A[middle] < target`이면 오름차순이므로 `middle` 이하의 모든 위치도 첫 `A[i] >= target`이 될 수 없습니다.

따라서:

```text
low = middle + 1
```

로 버릴 수 있습니다.

반대로 `A[middle] >= target`이면 `middle`이 답일 수도 있고 더 왼쪽에 첫 번째 만족 위치가 있을 수도 있습니다.

따라서 `middle`을 버리면 안 됩니다.

```text
high = middle
```

로 유지합니다.

### 종료 시 왜 `low`가 답인가

루프는 `low == high`일 때 종료합니다.

종료 시:

```text
[0, low)의 모든 원소는 target보다 작음
[low, n)의 모든 원소는 target 이상
```

이므로 `low`가 첫 `A[i] >= target` 위치입니다.

만약 그런 원소가 하나도 없다면 모든 원소가 `target`보다 작으므로 `low == n`이 됩니다.

### upper bound

`upper_bound(target)`는 다음 위치를 찾습니다.

> 첫 번째 `A[i] > target`인 index

예:

```text
A = [1, 2, 2, 2, 5, 8]

lower_bound(2) = 1
upper_bound(2) = 4
```

따라서 정렬된 배열에서 `target`의 개수는 다음과 같습니다.

```text
upper_bound(target) - lower_bound(target)
```

위 예에서는:

```text
4 - 1 = 3
```

입니다.

## 3. 이분 탐색에서 자주 생기는 오류

이분 탐색의 오류는 대부분 **구간 표현, 판정 조건, 반환 의미를 섞는 것**에서 발생합니다.

### 닫힌 구간과 반열린 구간을 섞음

다음 두 방식은 모두 가능하지만 갱신식이 다릅니다.

```text
닫힌 구간: [low, high]
반열린 구간: [low, high)
```

예를 들어 `[low, high)`에서는 `high = n`이 가능하지만 `[low, high]`에서는 마지막 유효 index가 `n - 1`입니다.

한 함수 안에서는 한 표현만 사용해야 합니다.

### 구간이 줄지 않음

매 반복에서 탐색 후보 구간이 반드시 줄어야 합니다.

잘못된 예:

```text
low = middle
```

`middle == low`인 상황에서는 `low`가 변하지 않아 무한 반복할 수 있습니다.

lower bound 구현에서 `A[middle] < target`이면:

```text
low = middle + 1
```

로 `middle`을 확실히 제거합니다.

### 반환하려는 위치가 불명확함

이분 탐색은 단순히 "값을 찾는 알고리즘"이 아닙니다.

문제에 따라 찾는 경계가 다릅니다.

```text
첫 번째 target 이상
첫 번째 target 초과
첫 번째 true
마지막 true
첫 번째 false
마지막 false
```

구현 전에 반환 의미를 한 문장으로 적는 것이 좋습니다.

### 중복 값에서 임의 위치를 반환함

```text
A = [1, 2, 2, 2, 5]
```

`target = 2`일 때 단순히 `A[middle] == target`에서 즉시 반환하면 `1`, `2`, `3` 중 어느 index가 반환될지 구현과 입력에 따라 달라질 수 있습니다.

첫 위치가 필요하다면 lower bound처럼 경계를 찾아야 합니다.

### 정렬 전조건을 빠뜨림

일반적인 값 기반 이분 탐색은 배열이 판정 조건에 대해 단조롭게 정렬되어 있어야 합니다.

정렬되지 않은 배열에서는 다음 추론을 할 수 없습니다.

```text
A[middle] < target
-> middle 왼쪽은 모두 버려도 됨
```

따라서 이분 탐색 함수의 계약에 정렬 전조건을 명시해야 합니다.

### `middle` 계산 overflow

고정 폭 정수를 사용하는 언어에서 다음 식은 overflow할 수 있습니다.

```text
(low + high) / 2
```

대신 다음 형태를 사용할 수 있습니다.

```text
low + (high - low) / 2
```

Python처럼 정수가 임의 정밀도인 언어에서는 정수 overflow 문제가 없지만, 언어에 독립적인 구현 습관으로는 후자가 안전합니다.

## 4. 답에 대한 이분 탐색: parametric search

때로는 정답을 직접 구성하기 어렵지만, 특정 후보값 `x`가 가능한지는 쉽게 검사할 수 있습니다.

이때 다음 형태의 판정 함수를 만듭니다.

```text
feasible(x) -> x가 조건을 만족하는가?
```

그리고 `feasible(x)`가 값의 크기에 따라 한 방향으로만 바뀐다면 값의 범위 자체를 이분 탐색할 수 있습니다.

이 문서에서는 이 형태를 **답에 대한 이분 탐색** 또는 parametric search라고 부릅니다.

### 단조 판정 함수

예를 들어 용량 `x`가 커질수록 작업 수행이 쉬워진다고 하겠습니다.

```text
x가 가능하면 그보다 큰 값도 모두 가능
```

즉:

```text
false false false true true true
                  ↑
               첫 true
```

이 구조에서는 첫 번째 `true`를 이분 탐색할 수 있습니다.

반대 방향도 가능합니다.

```text
true true true false false false
             ↑
          마지막 true
```

중요한 것은 **참과 거짓이 여러 번 번갈아 나타나지 않는다는 것**입니다.

### 예시 문제

다음과 같은 문제를 판정 문제로 바꿀 수 있습니다.

```text
용량 x로 모든 작업을 제한 시간 안에 처리할 수 있습니까?
거리 x 이상을 유지하며 k개 지점을 고를 수 있습니까?
구간별 최대 합을 x 이하로 제한해 m개 이하로 나눌 수 있습니까?
```

예를 들어 "필요한 최소 용량"을 찾는다면:

```text
feasible(x) = 용량 x로 모든 작업을 처리할 수 있는가?
```

라고 정의합니다.

용량이 커질수록 작업 수행이 더 쉬워진다면:

```text
feasible(x) == true
-> 모든 y >= x에 대해 feasible(y) == true
```

가 성립합니다.

이제 찾을 값은 **첫 번째 true**입니다.

### 설계 순서

답에 대한 이분 탐색은 다음 순서로 설계합니다.

```text
1. 후보 답 x의 의미를 정의한다.
2. feasible(x)의 의미를 한 문장으로 정의한다.
3. feasible이 단조인지 증명한다.
4. 찾는 경계를 정한다.
5. 답을 반드시 포함하는 초기 범위를 정한다.
6. 각 반복에서 범위가 줄어드는지 확인한다.
7. 판정 함수의 비용까지 포함해 전체 복잡도를 계산한다.
```

### 전체 시간 복잡도

탐색할 정수 범위의 크기를 `R`, 판정 함수 비용을 `T`라고 하면 일반적으로:

```text
O(T log R)
```

입니다.

예를 들어 판정 함수가 입력 전체를 한 번 순회해 `O(n)`이고 답 범위가 `0..M`이면:

```text
O(n log M)
```

입니다.

여기서 `log n`이 아니라 **답의 탐색 범위 크기**에 로그가 붙는다는 점을 구분해야 합니다.

### 상한을 모르는 경우

답의 상한을 모르면 충분한 상한을 찾을 때까지 두 배로 늘리는 방법을 사용할 수 있습니다.

```text
high = 초기값
while not feasible(high):
    high *= 2
```

그 뒤 답을 포함하는 범위에서 이분 탐색합니다.

다만 다음을 확인해야 합니다.

- 고정 폭 정수에서 `high *= 2`가 overflow하지 않는가?
- 판정 함수를 몇 번 추가 호출하는가?
- 문제 조건에서 답이 존재한다는 보장이 있는가?
- `high`가 자료형이나 문제의 최대 허용값을 넘지 않는가?

### 실수 범위의 이분 탐색

정수처럼 정확한 경계 index를 찾는 문제와 달리 실수 답을 찾는 문제에서는 보통 반복 횟수 또는 허용 오차를 정해야 합니다.

```text
고정 횟수 반복
또는
high - low <= epsilon까지 반복
```

부동소수점에서는 정확한 `low == high` 종료를 기대하지 않는 것이 일반적입니다.

## 5. heap

heap은 모든 원소를 정렬하지 않고 **가장 우선순위가 높은 원소에 빠르게 접근하기 위한 자료구조**입니다.

min-heap에서는 보통 다음 조건을 유지합니다.

```text
부모의 값 <= 자식의 값
```

따라서 root에는 항상 최솟값이 있습니다.

그러나 heap 배열 전체가 오름차순인 것은 아닙니다.

예를 들어 다음 배열은 min-heap 조건을 만족할 수 있습니다.

```text
[1, 4, 2, 9, 7, 5]
```

하지만 전체가 정렬되어 있지는 않습니다.

### heap이 제공하는 부분 순서

min-heap이 보장하는 것은 다음 정도입니다.

```text
root는 전체 최솟값
각 부모는 자기 자식보다 크지 않음
```

다음은 보장하지 않습니다.

```text
두 형제 중 어느 쪽이 더 작은가?
임의의 i번째 작은 값은 어디에 있는가?
배열을 앞에서부터 읽으면 정렬되어 있는가?
```

이 때문에 heap을 정렬 배열처럼 사용하면 안 됩니다.

### 주요 연산 비용

| 연산 | 일반적인 비용 |
| --- | ---: |
| 최소값 확인 | `O(1)` |
| 삽입 | `O(log n)` |
| 최소값 제거 | `O(log n)` |
| 임의 값 탐색 | 보통 `O(n)` |
| `n`개 원소로 heap 구성 | `O(n)` 가능 |

`n`개 값을 하나씩 삽입하면 `O(n log n)`이지만, 기존 배열 전체를 bottom-up 방식으로 heapify하면 `O(n)`에 heap을 구성할 수 있습니다.

### 언제 heap이 적합한가

heap은 다음처럼 전체 순서가 아니라 **다음에 처리할 하나의 우선순위 원소**가 반복해서 필요할 때 적합합니다.

```text
현재 최소 비용 상태를 하나 꺼냄
새 상태를 몇 개 추가
다시 최소 비용 상태를 꺼냄
```

대표적인 예는 다음과 같습니다.

- priority queue
- Dijkstra의 다음 정점 선택
- 상위 또는 하위 `k`개 값 유지
- 여러 정렬된 stream의 병합
- 작업 스케줄링

### 상위 `k`개 유지 예

가장 큰 `k`개 값만 필요하다면 크기 `k`의 min-heap을 유지할 수 있습니다.

```text
새 값 삽입
heap 크기가 k를 넘으면 최솟값 제거
```

처리가 끝나면 heap에는 가장 큰 `k`개 후보가 남습니다.

전체 정렬 `O(n log n)` 대신 대략:

```text
O(n log k)
```

로 처리할 수 있습니다.

## 6. lazy deletion과 stale entry

일반적인 binary heap은 root 제거는 빠르지만 임의 위치의 항목을 찾아 삭제하거나 우선순위를 직접 수정하는 기능이 간단하지 않습니다.

이때 **오래된 항목을 heap 안에 남겨 두고, 나중에 root로 나왔을 때 버리는 방식**을 사용할 수 있습니다.

이를 lazy deletion 또는 stale entry 처리라고 합니다.

### 기본 구조

```text
heap에는 같은 key의 여러 버전이 들어갈 수 있습니다.
별도 map에는 각 key의 최신 값 또는 최신 version을 저장합니다.
pop한 항목이 최신 상태와 다르면 사용하지 않고 다시 pop합니다.
```

예:

```text
heap:
(priority=10, key=A, version=1)
(priority=4,  key=A, version=2)

latest[A] = version 2
```

`version 1` 항목은 heap 안에 남아 있어도 최신 상태가 아니므로 stale entry입니다.

### 왜 안전한가

오래된 항목을 즉시 삭제하지 않아도 실제 처리 직전에 최신 여부를 검사하면 잘못된 상태를 확장하거나 반환하지 않을 수 있습니다.

즉 heap 자체는 오래된 데이터를 포함할 수 있지만 **외부의 최신 상태가 정답의 기준**입니다.

### Dijkstra 예

Dijkstra에서 정점 `v`의 더 짧은 거리를 발견할 때마다 새 `(distance, v)`를 heap에 넣는 구현을 생각해 보겠습니다.

```text
처음 발견:
(10, v)

나중에 더 짧은 경로 발견:
(4, v)
```

두 항목이 모두 heap에 남을 수 있습니다.

현재 최단 거리 배열이 다음과 같다면:

```text
dist[v] = 4
```

나중에 `(10, v)`가 pop되었을 때:

```text
popped_distance != dist[v]
```

이므로 stale entry이며 확장하지 않습니다.

전형적인 조건은 다음과 같습니다.

```text
if popped_distance != dist[v]:
    skip
```

일부 구현에서는 문제의 조건에 따라 `>` 비교를 사용하기도 있지만, 어떤 비교를 사용하는지는 저장하는 상태와 갱신 규칙에 맞춰 일관되게 정해야 합니다.

### 메모리 비용

lazy deletion은 삭제 비용을 단순화하는 대신 stale entry가 heap에 남습니다.

따라서 다음을 확인해야 합니다.

- 동일 key에 대한 새 entry가 얼마나 자주 생성되는가?
- heap 크기가 실제 활성 원소 수보다 얼마나 커질 수 있는가?
- 장시간 실행되는 시스템에서 주기적 rebuild가 필요한가?

시간 복잡도뿐 아니라 메모리 증가도 설계의 일부입니다.

## 7. 비교 함수와 동점 처리

정렬과 heap에 사용하는 비교는 알고리즘이 기대하는 일관된 순서를 만들어야 합니다.

일반적인 엄격한 순서 비교 `<`는 최소한 다음 성질을 만족해야 합니다.

```text
a < a 는 거짓

a < b 가 참이면 b < a 는 거짓

a < b 와 b < c 가 참이면 a < c 도 참
```

즉 자기 자신보다 작다고 판단해서는 안 되고, 서로 모순되는 비교 결과가 나오면 안 되며, 추이성이 깨져서도 안 됩니다.

### 동점 처리

첫 번째 기준이 같은 두 원소의 순서까지 결과에 영향을 준다면 두 번째 기준을 명시합니다.

예:

```text
(end, start)
(weight, source, target)
(priority, sequence)
```

이렇게 하면 같은 입력에 대해 반환 순서가 결정적이 됩니다.

### 동점을 정의하지 않아도 되는 경우

정답이 집합으로만 중요하고 같은 우선순위 원소의 처리 순서가 결과에 영향을 주지 않는다면 별도의 tie-breaker가 필요하지 않을 수 있습니다.

하지만 다음 상황에서는 동점 규칙을 명시하는 것이 좋습니다.

- 테스트에서 반환 순서를 비교함
- 실행마다 같은 출력을 원함
- 다음 비교 항목이 비교 불가능한 객체임
- 같은 우선순위라도 처리 순서가 의미를 가짐

### Python `heapq`의 동점 문제

Python tuple은 앞 원소가 같으면 다음 원소를 비교합니다.

따라서 다음 항목을 heap에 넣는다고 하겠습니다.

```text
(priority, item)
```

두 `priority`가 같고 `item`끼리 `<` 비교할 수 없다면 오류가 발생할 수 있습니다.

이때 증가하는 정수 `sequence`를 넣을 수 있습니다.

```text
(priority, sequence, item)
```

`sequence`가 항상 다르면 `item` 자체를 비교할 필요가 없습니다.

### 순서를 깨뜨릴 수 있는 값

다음 값은 비교 규칙을 불안정하게 만들 수 있습니다.

- 부동소수점 `NaN`
- heap이나 정렬 중에 바뀌는 비교 필드
- 비교 함수가 참조하는 외부 mutable state

예를 들어 원소를 heap에 넣은 뒤 priority 필드를 직접 변경해도 heap 구조는 자동으로 재정렬되지 않습니다.

따라서 heap에 들어 있는 동안 우선순위 기준을 바꾸기보다 새 entry를 넣고 stale entry를 버리는 방식이 더 안전할 수 있습니다.

## 8. 원래 순서가 필요할 때

정렬은 원소 위치를 바꾸므로 원래 index가 필요하다면 함께 저장합니다.

```text
(value, original_index)
```

예:

```text
원본:
index: 0  1  2
value: 8  3  5

함께 저장:
(8, 0), (3, 1), (5, 2)

value 기준 정렬:
(3, 1), (5, 2), (8, 0)
```

정렬 뒤에도 각 값의 원래 위치를 알 수 있습니다.

### stable sort

stable sort는 비교 key가 같은 원소들의 기존 상대 순서를 보존합니다.

예:

```text
입력:
(A, 2), (B, 1), (C, 2)

두 번째 값만 기준으로 stable sort:
(B, 1), (A, 2), (C, 2)
```

`A`와 `C`는 같은 key `2`를 가지므로 원래 상대 순서 `A -> C`가 유지됩니다.

같은 key의 기존 순서가 의미가 있다면 정렬 알고리즘이나 언어의 sort가 stable한지 확인해야 합니다.

### 제자리 정렬 여부

함수 계약에는 다음도 명시하는 것이 좋습니다.

```text
입력 배열 자체를 정렬하는가?
정렬된 복사본을 만드는가?
```

호출자가 원래 배열 순서를 이후에도 사용한다면 이 차이가 중요합니다.

## 9. 정렬된 배열과 heap 비교

두 구조 모두 "순서"를 사용하지만 제공하는 기능이 다릅니다.

| 요구 | 정렬된 배열 | heap |
| --- | --- | --- |
| 전체 순서를 순회 | 적합 | 직접 보장하지 않음 |
| 최솟값 확인 | `O(1)` 가능 | `O(1)` |
| 최솟값 반복 제거 | 앞쪽 제거 구현에 따라 비용 주의 | `O(log n)` |
| 값의 존재 위치 이분 탐색 | `O(log n)` | 보통 `O(n)` |
| 새 값 삽입 후 정렬 유지 | 보통 원소 이동 `O(n)` | `O(log n)` |
| 다음 최소 우선순위 원소 반복 선택 | 가능하지만 갱신이 불편할 수 있음 | 적합 |
| 임의의 k번째 순위 접근 | index로 가능 | 일반적으로 직접 지원하지 않음 |

핵심 차이는 다음과 같습니다.

```text
정렬된 배열:
전체 순서를 유지

heap:
root가 가장 우선이라는 부분 순서만 유지
```

전체 순서가 필요하지 않은데 매 갱신마다 전체를 다시 정렬하면 불필요한 비용이 생길 수 있습니다.

```text
[0, low)의 값은 모두 target보다 작다.

[low, high)가 아직 가능한 답의 범위다.
```

```text
기계 하나가 시간 x 동안 일정한 규칙으로 물건을 생산한다.
전체 생산량이 목표량 이상이 되는 최소 시간 x를 찾는다.
```

검증할 때는 작은 입력 범위에서:

```text
선형 탐색으로 최소 x 계산
이분 탐색으로 최소 x 계산
두 결과 비교
```

를 수행합니다.

이렇게 하면 판정 함수의 단조 방향과 경계 처리 오류를 쉽게 찾을 수 있습니다.

## 완료 기준

- 정렬 전처리가 언제 이득이고 언제 불필요한지 비용식으로 설명합니다.
- lower bound가 찾는 위치를 "첫 `A[i] >= target`"이라고 정확히 정의합니다.
- lower bound의 세 구간 조건을 적고 각 갱신 뒤에도 유지되는 이유를 설명합니다.
- 종료 시 `low == high`가 첫 삽입 위치가 되는 이유를 설명합니다.
- `lower_bound`와 `upper_bound`의 차이를 중복 값 예제로 설명합니다.
- 답에 대한 이분 탐색에서 `feasible(x)`의 의미와 단조 방향을 증명합니다.
- 답에 대한 이분 탐색의 전체 비용을 `판정 비용 × 이분 탐색 횟수`로 계산합니다.
- heap과 정렬된 배열이 제공하는 순서의 강도를 구분합니다.
- heap에서 임의 순위 탐색이 빠르지 않은 이유를 설명합니다.
- stale entry를 버릴 때 비교할 최신 상태 또는 version을 명확히 정합니다.
- 동점 처리와 반환 순서를 테스트로 고정합니다.
- 정렬 뒤 원래 index가 필요할 때 `(value, index)`를 사용하는 이유를 설명합니다.

## 실패 신호

- 정렬 비용을 무시하고 "이분 탐색이 `O(log n)`이므로 항상 빠르다"고 설명합니다.
- 닫힌 구간과 반열린 구간 갱신 공식을 한 구현에서 섞습니다.
- `middle`을 제거하지 않는 갱신 때문에 탐색 범위가 줄지 않습니다.
- 중복 값의 첫 위치와 임의 일치 위치를 혼동합니다.
- 정렬되지 않은 배열에 값 기반 이분 탐색을 그대로 적용합니다.
- 답에 대한 이분 탐색에서 판정 함수의 단조성을 확인하지 않습니다.
- 첫 `true`, 마지막 `true`, 첫 `false` 중 무엇을 찾는지 정의하지 않습니다.
- 답의 초기 탐색 범위가 실제 답을 포함한다는 근거가 없습니다.
- heap을 정렬된 배열처럼 사용해 임의 순위를 빠르게 찾으려 합니다.
- heap 배열을 앞에서부터 읽으면 정렬된 순서라고 가정합니다.
- lazy deletion에서 최신 여부를 판정할 값이나 version이 없습니다.
- stale entry를 실제 처리 전에 걸러내지 않습니다.
- 비교 함수가 동점이나 추이성을 정의하지 않습니다.
- heap에 넣은 뒤 비교에 사용하는 필드를 직접 변경하고 heap이 자동으로 재정렬될 것이라고 가정합니다.
- 원래 순서가 필요한데 정렬 전에 원래 index를 보존하지 않습니다.
