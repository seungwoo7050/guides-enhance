# 순서, 탐색, 힙과 우선순위

## 학습 목표

- 정렬이 이후 질의를 빠르게 만들기 위한 전처리라는 점을 설명합니다.
- 이분 탐색의 구간, 판정 함수, 동점 처리와 반환 위치를 명확히 정합니다.
- heap이 제공하는 부분 순서와 정렬된 배열의 전체 순서를 구분합니다.
- 답을 직접 찾지 않고 단조 판정 함수로 바꾸는 parametric search를 설계합니다.

## 선행지식

[선형 자료구조와 구간](01-linear-structures-ranges-and-hashing.md), 비교 순서, [정확성 문서](../01-foundations/04-correctness-and-invariants.md)의 lower bound 불변식을 먼저 이해해야 합니다.

## 핵심 관점

정렬하면 일부 연산이 빨라지지만 정렬 비용, 갱신 비용, 원래 순서를 잃는 비용이 생깁니다.

```text
정렬 비용
+ 이후 질의 비용
+ 갱신 비용
+ 원래 순서를 보존하는 비용
```

## 1. 정렬을 사용하는 이유

정렬한 뒤에는 다음 작업을 수행하기 쉬워집니다.

- 같은 값을 묶습니다.
- two pointers를 사용합니다.
- 이분 탐색을 수행합니다.
- sweep line의 event 순서를 정합니다.
- greedy 선택 순서를 고정합니다.
- 중복을 제거하고 순위를 계산합니다.

질의가 한 번뿐이고 입력이 작다면 정렬 비용이 더 클 수 있습니다. 정렬 뒤의 작업이 `O(n log n)` 비용을 상쇄하는지 계산합니다.

## 2. lower bound

오름차순으로 정렬된 배열 `A`에서 첫 `A[i] >= target` 위치를 찾습니다. 그런 원소가 없으면 `len(A)`를 반환합니다.

```text
low = 0
high = len(A)
while low < high:
    middle = low + (high - low) // 2
    if A[middle] < target:
        low = middle + 1
    else:
        high = middle
return low
```

유지하는 조건은 다음과 같습니다.

```text
low 앞의 모든 원소는 target보다 작습니다.
high부터 뒤의 모든 원소는 target 이상입니다.
0 <= low <= high <= n입니다.
```

`upper_bound`는 첫 `A[i] > target` 위치입니다. 두 위치의 차이는 `target`의 개수입니다.

## 3. 이분 탐색에서 자주 생기는 오류

- 닫힌 구간과 반열린 구간 공식을 섞습니다.
- `middle`이나 구간 끝이 줄지 않아 무한 반복합니다.
- 첫 참, 마지막 참, 마지막 거짓의 반환 위치를 혼동합니다.
- 중복 값에서 임의의 일치 위치를 반환합니다.
- 정렬 전조건을 빠뜨립니다.
- 고정 폭 정수에서 `(low + high) / 2`가 overflow할 수 있습니다.

한 함수 안에서는 구간 표현을 끝까지 하나로 유지합니다.

## 4. 답에 대한 이분 탐색

답 `x`에 대한 판정 함수 `feasible(x)`가 한 방향으로만 바뀐다면 값의 범위를 이분 탐색할 수 있습니다.

예를 들면 다음과 같습니다.

```text
용량 x로 모든 작업을 제한 시간 안에 처리할 수 있습니까?
거리 x 이상을 유지하며 k개 지점을 고를 수 있습니까?
구간별 최대 합을 x 이하로 제한해 m개 이하로 나눌 수 있습니까?
```

먼저 단조 방향을 증명합니다.

```text
feasible(x)가 참이면 모든 더 큰 x도 참입니다.
```

또는 반대 방향일 수 있습니다. 찾는 값이 첫 참인지, 마지막 거짓인지, 최대 가능한 값인지 명확히 정합니다.

상한을 모르면 답을 포함할 때까지 두 배로 늘릴 수 있지만 overflow 여부와 판정 함수 비용을 함께 확인해야 합니다.

## 5. heap

min-heap은 전체가 정렬된 상태가 아닙니다. root가 최솟값이며 부모가 자식보다 우선한다는 조건만 유지합니다.

| 연산 | 일반적인 비용 |
| --- | ---: |
| 최소값 확인 | `O(1)` |
| 삽입 | `O(log n)` |
| 최소값 제거 | `O(log n)` |
| 임의 값 탐색 | 보통 `O(n)` |
| `n`개 원소로 heap 구성 | `O(n)` 가능 |

상위 `k`개 값을 유지하거나 다음에 처리할 최소 비용 상태를 계속 꺼낼 때 적합합니다. 전체 순서가 필요하지 않다면 매번 정렬하지 않습니다.

## 6. lazy deletion과 stale entry

heap에서 임의 항목을 바로 삭제하기 어렵다면 최신 값을 별도 map에 저장하고 `pop`할 때 오래된 항목을 버릴 수 있습니다.

```text
heap에는 같은 key의 여러 버전이 들어갈 수 있습니다.
map에는 각 key의 최신 값이나 version을 저장합니다.
pop한 값이 최신 상태와 다르면 사용하지 않습니다.
```

오래된 항목이 계속 쌓일 수 있으므로 메모리 사용량과 정리 시점도 확인합니다.

Dijkstra에서도 같은 정점의 더 긴 거리 항목이 heap에 남을 수 있습니다. `pop`한 거리와 현재 최단 거리 배열이 다르면 확장하지 않습니다.

## 7. 비교 함수와 동점 처리

정렬과 heap에 사용하는 비교는 일관된 순서를 만들어야 합니다.

- `a < a`는 거짓이어야 합니다.
- `a < b`와 `b < a`가 동시에 참이면 안 됩니다.
- 비교 결과는 추이성을 만족해야 합니다.
- 동점일 때 사용할 두 번째 key를 정해야 합니다.

부동소수점 `NaN`, 실행 중 바뀌는 필드, 비교 시 참조하는 외부 mutable state는 순서 조건을 깨뜨릴 수 있습니다.

Python `heapq`에서 첫 값이 같을 때 두 번째 값끼리 비교할 수 없다면 `(priority, sequence, item)`처럼 증가하는 `sequence`를 사용합니다.

## 8. 원래 순서가 필요할 때

정렬 뒤 원래 index가 필요하다면 `(value, index)`를 함께 저장합니다. 같은 key의 상대 순서를 보존해야 한다면 stable sort 여부를 확인합니다.

정렬이 입력을 직접 바꾸는지 새 배열을 만드는지도 함수 조건에 포함합니다.

## 완료 기준

- lower bound의 세 구간 조건을 적고 종료 시 첫 삽입 위치가 되는 이유를 설명합니다.
- 답에 대한 이분 탐색에서 판정 함수의 단조 방향을 증명합니다.
- heap과 정렬된 배열이 제공하는 연산을 구분합니다.
- stale entry를 버릴 때 사용할 최신 상태를 명확히 정합니다.
- 동점 처리와 반환 순서를 테스트로 고정합니다.

## 실패 신호

- heap을 정렬된 배열처럼 사용해 임의 순위를 빠르게 찾으려 합니다.
- 답에 대한 이분 탐색에서 단조성을 확인하지 않습니다.
- 중복 값의 첫 위치와 임의 일치 위치를 혼동합니다.
- lazy deletion에서 최신 여부를 판정할 값이나 version이 없습니다.
- 비교 함수가 동점이나 추이성을 정의하지 않습니다.
