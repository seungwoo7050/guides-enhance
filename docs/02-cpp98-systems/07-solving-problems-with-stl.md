# C++98 STL로 문제 풀기

## 사용 시점

이 문서는 선행 필수가 아닙니다. 실제 프로젝트에서 어떤 container나 algorithm을 써야 할지 결정하기 어렵거나, 입력 검증과 정렬 결과를 안정적으로 만들 필요가 있을 때 참고합니다.

## 연산을 먼저 적습니다

예를 들어 날짜별 값을 저장하고 기준 날짜 이전의 가장 가까운 값을 찾는다면 필요한 연산은 다음과 같습니다.

```text
날짜 key로 정렬해 저장
중복 날짜 거부
주어진 날짜보다 큰 첫 원소 찾기
그 직전 원소 사용
```

이 경우 `std::map`과 `upper_bound()`가 맞습니다.

```cpp
Map::const_iterator found = rates.upper_bound(date);
if (found == rates.begin())
    throw NoEarlierValue();
--found;
return found->second;
```

container 이름을 먼저 정한 뒤 문제를 맞추지 않습니다.

## 입력을 내부 값으로 바꿉니다

문자열 비교만으로 날짜를 처리하려면 형식이 항상 `YYYY-MM-DD`이고 실제 달력 날짜인지 먼저 확인해야 합니다. 숫자도 전체 문자열을 소비하고 범위를 검사합니다.

입력 하나가 잘못됐을 때 전체 작업을 중단할지, 그 줄만 오류를 출력하고 다음 줄을 처리할지 정합니다.

## stack을 사용하는 문제

후위 표기식은 마지막 두 값을 꺼내 연산하고 결과를 다시 넣습니다.

```text
3 4 + 2 *
```

연산자마다 다음을 확인합니다.

- stack에 값이 두 개 이상 있는가
- 오른쪽과 왼쪽 operand 순서가 맞는가
- 0으로 나누는가
- 결과가 정수 범위를 넘는가

검사가 끝나기 전에 stack에서 값을 영구적으로 제거하면 실패 뒤 상태를 복구하기 어렵습니다. 필요한 값을 읽고 연산 가능 여부를 확인한 뒤 변경합니다.

## 안정 정렬

같은 key의 입력 순서를 보존해야 한다면 `std::stable_sort`를 사용합니다.

```cpp
struct Record {
    int value;
    std::size_t inputOrder;
};
```

입력 순서 자체를 결과에서 사용해야 한다면 record에 함께 저장합니다. stable sort를 쓴다는 사실만으로 이후 다른 정렬이나 변환에서도 순서가 보존된다고 가정하지 않습니다.

## 결정적인 출력

`map`은 key 순서로 순회하지만 `unordered_map`은 C++98 표준에 없고 구현별 확장도 순서를 보장하지 않습니다. test와 사용자 출력에 순서가 중요하면 정렬된 container나 명시적 정렬을 사용합니다.

정렬 기준이 같은 원소의 순서도 정합니다. 값만 비교할지, 원래 입력 위치를 tie-breaker로 쓸지 요구사항에 맞춥니다.

## 복잡도와 실제 비용

- `vector` 검색은 선형이지만 메모리가 연속입니다.
- `map` 검색은 로그 시간이지만 원소마다 node 할당이 있습니다.
- 작은 데이터에서는 단순한 vector가 더 빠를 수 있습니다.
- 입력 parsing과 출력은 정렬보다 더 큰 비용일 수 있습니다.

측정할 때는 정렬 구간만 따로 재고, Release build와 입력 크기를 기록합니다.

## 전체 파일을 후보 상태로 읽기

설정이나 CSV를 읽다 중간 오류가 나면 기존 데이터를 일부 덮어쓰지 않습니다.

```cpp
Map candidate;
read_all_rows(input, candidate);
validate(candidate);
rates_.swap(candidate);
```

이 방식은 파일 전체가 유효할 때만 새 상태를 반영합니다.

## 자주 놓치는 문제

- `map::operator[]`로 조회하다 없는 key를 의도치 않게 추가합니다.
- `upper_bound()`가 `begin()`인 경우 직전 원소로 이동합니다.
- 후위식 operand 순서를 반대로 계산합니다.
- 정렬 전에 입력 전체를 검증하지 않습니다.
- Debug build 한 번의 시간을 성능 결과로 사용합니다.
- 같은 key의 출력 순서를 구현 우연에 맡깁니다.

## 완료 기준

- 주요 연산을 적고 그에 맞는 container를 선택합니다.
- `find`, `lower_bound`, `upper_bound` 차이를 설명합니다.
- stack 연산의 operand 순서와 실패 조건을 검사합니다.
- 안정 정렬과 명시적인 tie-breaker를 구분합니다.
- 전체 입력을 후보 상태로 읽고 성공 후 반영합니다.
- 복잡도와 실제 측정 범위를 함께 기록합니다.
