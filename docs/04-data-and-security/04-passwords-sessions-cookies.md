# 비밀번호, 세션과 쿠키

로그인은 비밀번호가 맞는지 확인하는 단계와 이후 요청에서 같은 사용자를 식별하는 단계로 나뉩니다. 비밀번호 원문과 세션 토큰은 유출되면 바로 악용될 수 있으므로 저장과 로그 처리에 주의해야 합니다.

## 목표

- 검증된 비밀번호 해시 함수를 사용합니다.
- 예측하기 어려운 세션 토큰을 발급하고 서버에는 다이제스트만 저장합니다.
- 쿠키 속성과 서버 세션 만료를 함께 관리합니다.
- 로그인, 로그아웃, 만료, 토큰 교체와 계정 정지 뒤 동작을 정합니다.
- 로그와 오류 응답에 비밀값을 남기지 않습니다.

## 비밀번호 저장

비밀번호는 복호화할 필요가 없습니다.

```ts
const passwordHash = await passwordHasher.hash(password);
const matches = await passwordHasher.verify(user.passwordHash, candidate);
```

SHA-256을 한 번 적용하거나 자체 솔트 형식을 만들지 않습니다. Argon2id나 scrypt처럼 비밀번호 저장용 알고리즘을 검증된 라이브러리로 사용하고, 운영 환경에서 지연 시간과 메모리 사용량을 측정합니다.

## 입력 규칙

- 지나치게 짧은 값은 거부합니다.
- 긴 암호 문구를 허용할 충분한 최대 길이를 둡니다.
- 불필요한 대문자·소문자·특수문자 조합만 강제하지 않습니다.
- 유니코드 정규화 방식을 정합니다.
- 원문을 로그와 분석 도구에 보내지 않습니다.
- 가입과 비밀번호 변경에 같은 규칙을 적용합니다.

로그인 실패 응답으로 계정 존재 여부를 과도하게 드러내지 않습니다.

## 해시 설정 갱신

비밀번호 검사에 성공한 뒤 저장된 해시가 오래된 비용 설정을 사용했는지 확인하고 새 설정으로 다시 만들 수 있습니다.

```text
비밀번호 확인 성공
→ 재해싱 필요 여부 확인
→ 새 해시 저장
→ 로그인 완료
```

비밀번호를 바꿀 때는 기존 비밀번호 확인, 새 해시 저장과 기존 세션 폐기를 함께 정합니다.

## 세션 토큰

```ts
const token = randomBytes(32).toString("base64url");
const digest = createHash("sha256").update(token).digest("hex");
```

여기서 SHA-256은 이미 무작위인 토큰을 서버에서 찾기 위한 다이제스트에 사용합니다. 데이터베이스에는 다이제스트를 저장하고 원문 토큰은 브라우저 쿠키로 전달합니다.

```sql
create table sessions (
  id uuid primary key,
  user_id uuid not null references users(id) on delete cascade,
  token_digest text not null unique,
  expires_at timestamptz not null,
  created_at timestamptz not null,
  revoked_at timestamptz
);
```

요청마다 쿠키 토큰을 같은 방식으로 다이제스트하고, 만료·폐기 여부와 사용자 계정 상태를 함께 확인합니다.

## 쿠키 속성

```ts
reply.setCookie("app_session", token, {
  path: "/",
  httpOnly: true,
  secure: config.production,
  sameSite: "lax",
  maxAge: 60 * 60 * 24 * 14
});
```

- `HttpOnly`: 브라우저 JavaScript가 토큰을 읽지 못하게 합니다.
- `Secure`: HTTPS에서만 전송합니다.
- `SameSite`: 교차 사이트 요청에서 전송을 제한합니다.
- `Path`: 쿠키를 보낼 경로를 제한합니다.
- `Max-Age`·`Expires`: 브라우저가 보관할 시간을 정합니다.

삭제할 때도 발급할 때와 같은 이름, 경로와 도메인을 사용합니다. 값이 다르면 이전 쿠키가 브라우저에 남을 수 있습니다.

## 로그인 순서

```text
이메일·비밀번호 검사
→ 사용자 조회
→ 비밀번호 확인
→ 계정 상태 확인
→ 새 세션 토큰 생성
→ 다이제스트 저장
→ 쿠키 발급
→ 공개 사용자 정보 반환
```

비밀번호 해시는 비용이 큰 연산이므로 로그인 시도에 속도 제한이 필요합니다. IP와 계정 하나만 기준으로 무조건 차단하면 정상 사용자를 막거나 특정 계정을 공격자가 잠글 수 있습니다.

## 토큰 교체

인증 전 세션 ID를 로그인 뒤에도 그대로 사용하지 않습니다. 로그인, 권한 상승, 비밀번호 변경 때 새 토큰을 발급하고 이전 토큰을 폐기합니다.

로그아웃은 다음 두 작업을 모두 완료해야 합니다.

1. 브라우저 쿠키 삭제
2. 서버 세션 폐기

쿠키만 지우면 유출된 토큰이 서버에서 계속 유효할 수 있습니다.

## 요청에서 사용자 찾기

인증 훅이나 공통 함수가 쿠키를 읽고 사용자 정보를 만듭니다.

```ts
interface Actor {
  userId: string;
  sessionId: string;
  accountStatus: "active" | "suspended";
}
```

각 라우트에서 같은 토큰 파싱을 반복하지 않습니다. 정지되거나 삭제된 사용자는 만료되지 않은 세션이 있어도 거부합니다.

## 만료와 정리

최종 만료 기준은 서버의 `expires_at`입니다. 브라우저에 쿠키가 남아 있어도 서버 세션이 만료되면 요청을 거부합니다. 슬라이딩 만료를 쓰면 요청마다 데이터베이스를 갱신하지 않도록 갱신 간격과 최대 절대 수명을 정합니다.

## 비밀번호 재설정

재설정 토큰도 원문은 사용자에게 전달하고 서버에는 다이제스트만 저장합니다.

- 짧은 만료 시간
- 한 번 사용 뒤 즉시 폐기
- 새 토큰 발급 시 이전 토큰 처리
- 성공 뒤 기존 세션 폐기 여부
- 계정 존재를 과도하게 드러내지 않는 응답

## 기록하지 않을 값

- 원문 비밀번호
- 세션 쿠키
- `Authorization` 헤더
- 비밀번호 재설정 토큰
- 전체 비밀번호 해시

요청 ID, 사용자 ID, 처리 결과와 속도 제한 결과처럼 비밀이 아닌 값만 남깁니다.

## 흔한 실수

- 일반 해시를 한 번 적용해 비밀번호를 저장합니다.
- 자체 비밀번호 해시 형식을 만듭니다.
- 세션 원문 토큰을 데이터베이스에 저장합니다.
- 쿠키만 삭제하고 서버 세션은 남깁니다.
- 만료와 계정 정지 상태를 확인하지 않습니다.
- 로그인 전후에 같은 세션 토큰을 사용합니다.
- 비밀번호와 쿠키를 로그에 기록합니다.

## 완료 기준

- 비밀번호 해시와 무작위 토큰 다이제스트의 용도를 구분합니다.
- 로그인, 로그아웃, 만료와 토큰 교체를 구현합니다.
- `HttpOnly`, `Secure`, `SameSite`, `Path`의 역할을 설명합니다.
- 매 요청에서 세션과 계정 상태를 확인합니다.
- 저장소와 로그에 인증 비밀값을 남기지 않습니다.
