# 모바일 애플리케이션 학습 로드맵

이 로드맵은 `Field Notes`를 완성된 학습 단위로 사용해 모바일 앱의 실행 수명, 오프라인 저장, 기기 기능, 백그라운드 작업과 배포 검증을 익히는 순서를 정합니다.

목표는 문서 수를 줄이는 것이 아니라, 모바일 앱 개발에 필요한 개념을 빠뜨리지 않으면서 가능한 한 일찍 구현을 시작하는 것입니다.

## 시작 전 기준

다음 능력을 전제로 합니다.

- TypeScript 타입과 런타임 값이 다르다는 점을 알고 외부 `unknown` 값을 검증합니다.
- React 컴포넌트와 `props`, 상태, 제어 입력, `effect` 등록·정리를 사용할 수 있습니다.
- Promise의 완료 순서가 시작 순서와 다를 수 있음을 이해합니다.
- HTTP 상태, 응답 본문 파싱과 애플리케이션 오류를 구분합니다.
- Git 저장소에서 설치, 빌드, 테스트 명령을 찾아 실행합니다.

React와 TypeScript 자체가 익숙하지 않다면 이 저장소 안에서 동시에 해결하려 하지 말고 먼저 해당 기초를 보완합니다.

## 최종 역량

### 1. 실행 수명과 상태 보존

- 포그라운드, 백그라운드, 프로세스가 종료된 상태를 업무 상태와 구분합니다.
- 프로세스 종료 전에 반드시 남아야 하는 값을 즉시 저장합니다.
- 시작 절차에서 데이터베이스, 세션, 외부 결과, 화면 이동 요청의 선후관계를 정합니다.

### 2. 화면과 화면 이동

- 안전 영역, 키보드, 큰 글자, 작은 화면과 보조기술을 고려합니다.
- 경로 매개변수와 외부 링크를 검증합니다.
- 딥 링크, 알림, 복원과 내부 화면 이동을 같은 화면 판단 과정으로 연결합니다.
- 저장하지 않은 초안이 있을 때 화면 이동을 막거나 명시적으로 버립니다.

### 3. 오프라인 저장과 동기화

- `Record` 변경과 outbox 명령을 같은 SQLite 트랜잭션에 저장합니다.
- 파일 복사와 SQLite 커밋이 하나의 원자 작업이 아님을 처리합니다.
- 명령 ID, 최초 시도 사본, lease와 저장된 처리 결과를 사용합니다.
- 응답 유실, 중복, 순서 역전, 401, 형식이 잘못된 응답, 버전 충돌 뒤에도 상태를 설명할 수 있습니다.

### 4. 기기 기능과 운영체제 입력

- 기능 사용 가능 여부와 권한 상태를 따로 표현합니다.
- 카메라, 사진 선택기, 포그라운드 위치 측정 결과를 명시적인 상태로 변환합니다.
- 프로세스 중단 뒤 대기 중인 선택기 결과와 앱이 소유한 파일을 조정합니다.
- 백그라운드 작업이 실행되지 않아도 다음 포그라운드 실행에서 수렴하게 만듭니다.
- 알림 데이터를 최신 업무 상태로 믿지 않고 저장소를 다시 읽습니다.

### 5. 네이티브 빌드와 배포 근거

- JavaScript 변경과 네이티브 바이너리 변경을 구분합니다.
- 설정 플러그인, 생성된 프로젝트, Kotlin과 Swift 진입점과 운영체제 기능이 어떻게 연결되는지 읽습니다.
- 애플리케이션 ID, 앱 버전, 빌드 번호, runtimeVersion과 소스 리비전을 구분합니다.
- 빌드, 서명, 설치, 스토어 상태를 하나의 성공 값으로 합치지 않습니다.

### 6. 검증

- 순수 모델, 저장소, 어댑터, 화면, 통합, 실제 기기 검사가 확인하는 범위를 구분합니다.
- 시간, ID, 네트워크, 권한과 저장소 실패를 결정적으로 만들 수 있습니다.
- 프로세스 재시작, 마이그레이션, 권한 철회, 바이너리와 런타임 불일치를 실제로 재현합니다.

- 경로, 링크, 복원 입력 검증
- 기록 목록·상세·편집 화면

이후 다음 구현을 확인합니다.

## 최종 검증

### 자동 검사

```sh
cd exercises/field-notes
npm install
npm run verify
```

### 실제 기기 검사

Android와 iOS에서 최소한 다음 작업을 수행합니다.

1. 앱을 설치하고 콜드 스타트합니다.
2. 기록을 저장한 뒤 프로세스를 종료하고 다시 실행합니다.
3. 네트워크 없이 기록을 수정합니다.
4. 권한을 거절하고도 텍스트 기록을 저장합니다.
5. 카메라 또는 사진 선택기 중단을 확인합니다.
6. 응답 유실과 충돌을 재현합니다.
7. 백그라운드 작업이 실행되지 않아도 포그라운드 복귀에서 대기 중인 상태를 처리합니다.
8. 알림을 통한 콜드 스타트와 웜 상태 진입을 확인합니다.
9. 큰 글자와 TalkBack과 VoiceOver에서 핵심 작업을 수행합니다.
10. 설치한 산출물과 소스, 앱, 빌드와 런타임 식별 정보를 연결합니다.

- 프로세스가 어느 지점에서 종료돼도 이미 저장한 사용자 의도가 남습니까?
- 외부 링크와 알림이 저장소 준비보다 먼저 화면을 바꾸지 않습니까?
- SQLite와 파일 시스템이 어긋났을 때 다음 시작에서 어떤 상태로 조정합니까?
- 서버 결과를 모르는 시간 초과 뒤 같은 명령을 어떻게 다시 보냅니까?
- 포그라운드와 백그라운드 작업자가 동시에 실행돼도 같은 명령을 어떻게 보호합니까?
- 권한을 잃었을 때 핵심 기록 작성은 계속 가능합니까?
- JavaScript가 설치된 바이너리에 없는 네이티브 API를 요구하지 않는지 어떻게 판정합니까?
- 어떤 검사는 실제 기기, 서명, 스토어 배포를 대신하지 못합니까?
