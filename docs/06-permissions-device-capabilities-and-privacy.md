# 권한, 기기 기능과 개인정보

권한은 설치할 때 한 번 확인하고 끝나는 설정이 아닙니다. 사용자는 기능을 처음 실행할 때 허용하거나 거절할 수 있고, 제한된 범위만 허용하거나 나중에 설정에서 철회할 수 있습니다. 기기에 해당 기능이 없거나 현재 빌드에 필요한 네이티브 모듈이 빠진 경우도 있습니다.

이 문서는 카메라, 시스템 사진 선택기와 포그라운드 위치 측정을 최소한의 권한으로 사용하고, 결과를 앱이 처리할 수 있는 값으로 바꾸는 방법을 다룹니다. 백그라운드 위치 측정과 지속적인 센서 수집은 필수 범위에 포함하지 않습니다.

## 이 문서에서 확인할 내용

- 기기 기능의 가용 여부와 권한 상태를 구분합니다.
- 사용자가 해당 기능을 선택한 순간에 권한을 요청합니다.
- `not-determined`, `granted`, `limited`, `denied`, `restricted`, `unavailable`를 따로 처리합니다.
- 선택기, 카메라, 위치 결과와 프로세스 중단을 명시적인 값으로 바꿉니다.
- 임시 URI를 앱이 소유하는 파일로 복사합니다.
- 파일 메타데이터, 보존 기간, 업로드와 로그의 개인정보 노출을 검토합니다.
- 네이티브 권한 설명이 실제 바이너리에 들어갔는지 확인합니다.

## 기기 기능과 권한을 따로 표현합니다

```text
기기 기능 사용 가능 여부
- 기기에 카메라가 있습니까?
- 현재 OS에서 API를 사용할 수 있습니까?
- 설치된 바이너리에 네이티브 모듈이 들어 있습니까?

권한
- 사용자가 이 앱에 현재 허용했습니까?
- 전체 또는 제한된 범위입니까?
- 다시 요청할 수 있습니까?
```

카메라 권한이 `granted`여도 하드웨어 오류나 다른 앱의 사용 때문에 촬영이 실패할 수 있습니다. 반대로 사진 선택기는 보관함 전체 권한 없이 사용자가 선택한 항목 하나만 제공할 수 있습니다.

두 값을 하나의 불리언으로 합치지 않습니다.

```ts
type CapabilityAvailability =
  | { kind: "available" }
  | { kind: "limited"; description: string }
  | { kind: "unavailable"; reason: string };

type PermissionState =
  | { kind: "not-required" }
  | { kind: "not-determined" }
  | { kind: "granted" }
  | { kind: "limited"; description: string }
  | { kind: "denied"; canAskAgain: boolean }
  | { kind: "restricted"; reason: string };
```

`not-required`는 모든 데이터에 접근할 수 있다는 뜻이 아닙니다. 시스템 선택기처럼 사용자가 직접 선택한 항목만 돌려주는 기능일 수 있습니다.

## 시작 절차에서 권한을 연속으로 요청하지 않습니다

앱을 열자마자 카메라, 위치, 알림 권한을 모두 요청하면 사용자는 필요한 이유를 알기 어렵습니다.

권장 순서는 다음과 같습니다.

```text
사용자가 "사진 추가" 선택
→ 현재 상태 확인
→ 기능이 필요한 이유와 거절 시 가능한 작업 설명
→ 필요하면 OS 권한 요청
→ 허용되면 카메라 실행
→ 거절되면 사진 없이 기록 계속
```

권한 설명 화면이 OS 대화 상자를 흉내 내거나 사용자를 압박하지 않게 합니다. 실제 수집 범위와 대체 작업을 설명합니다.

## 기능을 실행하기 직전에 상태를 다시 읽습니다

사용자는 앱 밖 설정에서 권한을 바꿀 수 있습니다.

- 이전 `granted` 값을 영구 캐시하지 않습니다.
- 카메라를 실행하기 직전에 현재 권한을 다시 확인합니다.
- 앱이 활성화되면 현재 화면에서 사용하는 기기 기능을 다시 읽습니다.
- `canAskAgain=false`이면 같은 대화 상자를 반복하지 않고 설정 이동을 안내합니다.
- 설정에서 돌아왔다는 이유로 카메라나 위치를 자동 실행하지 않습니다. 사용자의 원래 동작을 다시 확인합니다.

## 카메라와 시스템 사진 선택기를 분리합니다

### 카메라

- 카메라 하드웨어와 네이티브 모듈 가용 여부
- 카메라 권한
- 미리보기와 촬영 수명
- 촬영 중 백그라운드 전환, 전화 수신과 화면 잠금
- 결과 파일의 크기, MIME, 방향 정보

### 시스템 사진 선택기

- 사용자가 선택한 파일 하나에 대한 제한된 접근
- 보관함 전체 권한이 필요하지 않을 수 있음
- 제공자 URI의 수명
- Android `Activity`와 프로세스 재생성
- 원격 제공자에서 바이트를 내려받는 지연
- 파일 이름과 MIME 정보가 없거나 서로 맞지 않을 가능성

Field Notes는 사진 선택기와 직접 촬영을 별도 동작으로 제공합니다. 라이브러리 전체를 조회하는 기능으로 확장하지 않습니다.

## 외부 UI 실행을 재시작 뒤에도 남는 작업으로 기록합니다

선택기나 카메라를 여는 동안 프로세스가 종료될 수 있습니다. 외부 UI를 열기 전에 작업 ID와 대상 기록을 저장합니다.

```text
작업 행 생성
→ 카메라 또는 선택기 실행
→ 결과 회수
→ 작업 ID 선점
→ 파일 복사
→ 첨부 파일 메타데이터 커밋
→ 작업 완료
```

같은 결과가 두 번 전달돼도 작업 선점이 한 번만 성공해야 합니다. 프로세스가 종료된 경우 시작 절차에서 활성화 작업과 플랫폼 대기 중인 결과를 확인합니다.

플랫폼이 대기 중인 결과 조회 기능을 제공하지 않으면 성공을 추측하지 않습니다. 작업을 `interrupted`로 종료하고 사용자가 다시 선택하게 합니다.

## 선택기 결과를 앱이 소유하는 파일로 바꿉니다

시스템 API가 반환한 URI를 영구 데이터로 저장하지 않습니다.

```text
임시 URI
→ 앱 소유 임시 저장 경로로 복사
→ 파일 존재, 바이트 크기, 체크섬 확인
→ 앱이 관리하는 영구 저장 경로로 이동
→ SQLite 첨부 파일 메타데이터 추가
```

검증할 항목:

- 결과가 취소인지 성공인지
- 리소스가 정확히 한 개인지
- URI가 비어 있지 않은지
- MIME이 허용한 이미지 종류인지
- 파일이 비어 있지 않은지
- 크기가 앱의 안전 상한을 넘지 않는지
- 체크섬을 얻을 수 있는지

원본 파일 이름, 확장자와 MIME 정보를 신뢰하지 않습니다. 업로드를 받는 서버에서도 콘텐츠를 다시 검사해야 합니다.

## 파일 복사와 메타데이터 커밋 실패를 처리합니다

파일 시스템과 SQLite는 하나의 트랜잭션을 공유하지 않습니다.

- 복사가 실패하면 임시 저장 파일을 제거합니다.
- 복사가 성공했지만 메타데이터 추가가 실패하면 새로 만든 앱 소유 파일을 제거하거나, 다음 시작 시 참조되지 않은 파일로 정리합니다.
- 메타데이터가 있지만 파일이 없으면 첨부 파일을 `missing-local-file` 상태로 바꿉니다.
- 프로세스가 복사 중 종료되면 오래된 부분 파일을 제거합니다.
- 같은 대기 중인 결과를 다시 처리하면 `duplicate`로 종료합니다.

실패 뒤 어떤 파일이 남는지 코드와 테스트에서 확인합니다.

## 위치에는 품질과 시각을 함께 저장합니다

`위치 권한 있음`만으로 기록에 저장한 좌표의 의미를 설명할 수 없습니다.

```ts
type LocationMeasurement = {
  latitude: number;
  longitude: number;
  accuracyMeters: number;
  measuredAt: string;
};
```

다음 항목을 확인합니다.

- 위도와 경도 범위
- 정확도가 0 이상인지
- 측정 시각이 유효한지
- 측정 시간 초과
- 위치 서비스가 꺼졌는지
- 권한이 측정 직전에 철회됐는지

Field Notes는 사용자가 편집 화면에서 명시적으로 선택했을 때 포그라운드 위치를 한 번 측정합니다. 위치가 실패하거나 권한이 거절돼도 텍스트 기록을 저장할 수 있습니다.

백그라운드 위치 측정은 별도 제품 요구입니다. 포그라운드 서비스, 배터리, 스토어 심사, 지속 표시, 중지 제어, 보존 기간을 함께 설계하지 않은 채 권한 하나만 추가하지 않습니다.

## 제한됨과 시스템 선택기를 혼동하지 않습니다

사진 라이브러리 API의 제한됨 권한과 시스템 선택기가 선택한 파일 하나를 제공하는 동작은 다릅니다.

- 시스템 선택기는 보관함 전체 목록을 제공하지 않습니다.
- 라이브러리 API의 제한됨 상태는 일부 리소스만 목록으로 볼 수 있는 권한일 수 있습니다.
- 사용자가 선택한 리소스 ID와 파일 이름이 항상 존재한다고 가정하지 않습니다.
- 필요한 경우 선택기를 다시 열어 추가 선택하게 합니다.

Field Notes의 목적은 `보관함 전체 접근`이 아니라 `사용자가 고른 사진을 기록에 연결`하는 것입니다.

## 사진 메타데이터와 위치 정보를 검토합니다

이미지에는 EXIF 촬영 시각, 기기 정보, 방향 정보와 위치가 들어 있을 수 있습니다.

업로드 전에 다음을 정합니다.

- 방향 정보를 보존할지
- EXIF 위치를 제거할지
- 원본을 계속 보관할지
- 썸네일을 별도로 만들지
- 로컬과 원격에서 삭제할 시점을 어떻게 맞출지

사용자가 위치를 별도로 선택하는 앱이라면 이미지 EXIF 위치를 자동으로 수집하지 않는 편이 일관적일 수 있습니다.

로그와 비정상 종료 보고 도구에는 다음 값을 넣지 않습니다.

- 로컬 파일 URI
- 서명된 업로드 URL 전체
- 기록 제목과 메모
- 정확한 위도와 경도
- 인증 정보

## 생체 인증은 로컬 접근 확인입니다

생체 인증 대화 상자로 로컬 인증 정보 사용을 허용할 수 있지만 서버 계정 유효성까지 보장하지는 않습니다.

```text
생체 인증으로 로컬 인증 정보 사용 승인
→ 보안 저장소에서 인증 정보 읽기
→ 서버에서 인증 정보 갱신 또는 인가 확인
→ 보호된 데이터 표시
```

사용 불가, 등록되지 않음, 취소, 잠금 상태에 대한 대체 인증 수단을 정합니다. 생체 인증, 카메라 권한과 서버 인가를 같은 결과 값으로 합치지 않습니다.

## 네이티브 권한 설정은 빌드 입력입니다

권한 설명, 매니페스트와 plist 항목은 런타임 JavaScript가 아니라 네이티브 바이너리에 들어갑니다.

CNG를 사용한다면 다음 과정을 확인합니다.

```text
앱 설정과 플러그인 옵션
→ 초기 상태에서 네이티브 프로젝트 다시 생성
→ Android 병합된 매니페스트와 iOS 빌드된 설정
→ 개발용 빌드
→ 실제 기기의 권한 대화 상자
```

문구를 바꾼 뒤 Metro 새로고침만 확인하지 않습니다. 새 개발용 빌드를 설치해야 합니다.

의존성이 불필요한 권한을 추가하는지도 생성된 결과에서 확인합니다. Field Notes는 백그라운드 위치 측정, 마이크, 사진 보관함 전체 접근 권한처럼 사용하지 않는 항목을 차단합니다.

## 데이터 목록을 유지합니다

| 데이터 | 수집하는 순간 | 로컬 저장 | 원격 전송 | 삭제와 보존 | 사용자 제어 |
|---|---|---|---|---|---|
| 기록 내용 | 저장 | SQLite | 동기화 명령 | 제품 규칙 | 편집, 삭제 |
| 사진 | 사진 추가 | 앱이 소유한 파일 | 첨부 파일 업로드 | 제품 규칙 | 제거, 삭제 |
| 포그라운드 위치 측정 | 위치 추가 | SQLite | 기록 동기화 | 기록과 동일 | 거절, 제거 |
| 인증 정보 | 로그인과 갱신 | 보안 저장소 | 인가 헤더 | 로그아웃과 철회 | 로그아웃 |
| 진단 정보 | 오류나 성능 문제 발생 | 크기가 제한된 버퍼 | 허용한 관찰 정보 | 짧은 기간 | 개인정보 보호 설정 |

실제 코드, 백엔드, 스토어 개인정보 보호 입력 화면과 이 표가 일치해야 합니다.

## 사용자에게 제공할 상태

### 다시 요청할 수 있는 거절

- 기능 없이 가능한 작업을 계속 제공합니다.
- 다음 사용자 동작에서 필요한 이유를 다시 설명합니다.
- 같은 화면에서 즉시 대화 상자를 반복하지 않습니다.

### 다시 요청할 수 없는 거절

- 설정에서 바꾸는 방법을 안내합니다.
- 돌아오면 상태를 다시 읽습니다.
- 기능 없이 가능한 범위를 보여 줍니다.

### 제한된 상태

- 현재 가능한 범위를 설명합니다.
- 전체 접근이 정말 필요한 기능인지 다시 확인합니다.

### 기능 없음

- 비정상 종료하지 않습니다.
- 필요한 경우 기능을 사용할 수 없는 이유와 대체 입력을 제공합니다.

## 검증 시나리오

- 첫 권한 요청 거절
- `canAskAgain=false`
- 정확도가 제한된 위치
- 선택기 취소
- 선택기 실행 중 프로세스 종료
- 대기 중인 결과 중복 전달
- 0바이트 파일
- 허용하지 않은 MIME
- 20 MiB 상한 초과
- 저장 공간 부족
- 파일 복사는 성공했지만 메타데이터 커밋은 실패함
- 위치 서비스 꺼짐
- 위치 시간 초과
- 설정에서 권한 철회 뒤 복귀
- 네이티브 설정에 불필요한 권한이 추가됨

## 완료 기준

- 기능 사용 가능 여부와 권한 상태를 별도 값으로 처리합니다.
- 권한은 관련 사용자 동작에서 요청합니다.
- 기능을 실행하기 직전에 권한을 다시 확인합니다.
- 거절, 제한, 접근 제한, 사용 불가 상태에서도 텍스트 기록을 저장할 수 있습니다.
- 선택기나 카메라 URI를 앱이 소유한 파일로 복사합니다.
- 프로세스 중단과 대기 중인 결과 중복을 처리합니다.
- 위치에 측정 시각과 정확도가 있습니다.
- 권한이나 설정 변경 뒤 새 개발용 빌드를 설치해 확인합니다.
- 데이터 목록과 실제 저장·전송·삭제 동작이 일치합니다.
- 로그와 근거에 사진, 정확한 위치와 인증 정보를 남기지 않습니다.
