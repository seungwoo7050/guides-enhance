# 레이아웃, 입력과 접근성

React Native 화면은 웹 페이지를 작은 크기로 옮긴 결과물이 아닙니다. 손가락 입력, 화상 키보드, 안전 영역, 회전, 큰 글자, 스크린 리더와 플랫폼 화면 이동이 같은 화면에 동시에 영향을 줍니다.

화면이 작아지거나 입력 방법이 바뀌어도 사용자가 저장한 `Record`와 초안이 달라져서는 안 됩니다. 이 문서는 UI를 예쁘게 만드는 방법보다 **같은 작업을 여러 기기와 입력 수단에서 끝까지 수행하게 만드는 방법**을 다룹니다.

## 이 문서에서 확인할 내용

- 물리 픽셀과 React Native 레이아웃 단위를 구분합니다.
- 기기 이름이 아니라 현재 창과 콘텐츠 크기로 배치를 바꿉니다.
- 안전 영역과 키보드가 입력 항목, 오류, 저장 버튼을 가리지 않게 합니다.
- 터치, 물리 키보드, 스크린 리더가 같은 기능을 실행할 수 있게 합니다.
- 큰 글자, 긴 번역, 오른쪽에서 왼쪽으로 쓰는 언어를 고려합니다.
- 접근성 라벨, 역할, 상태와 포커스를 화면 상태와 함께 갱신합니다.
- Android와 iOS 실제 보조기술에서 핵심 작업을 확인합니다.

## 화면에 영향을 주는 값과 업무 상태를 분리합니다

| 값 | 누가 바꾸는가 | UI가 해야 할 일 | 바뀌면 안 되는 값 |
|---|---|---|---|
| 창 크기, 안전 영역 여백값, 글자 크기 배율 | 운영체제와 사용자 설정 | 현재 제약에 맞게 다시 배치 | 기록, 초안, 선택한 항목 |
| 키보드와 입력 포커스 | 운영체제와 현재 화면 | 입력 항목과 오류를 보이게 유지 | 저장 여부와 outbox 상태 |
| 스크린 리더 포커스 | 보조기술과 화면 | 작업 결과와 다음 동작을 읽을 수 있게 함 | 현재 업무 상태 |
| 로딩, 오류, 동기화 상태 | 애플리케이션 코드 | 시각 정보와 접근성 상태를 같은 값에서 계산 | 저장소에 저장된 데이터 |

화면 크기가 바뀌었다고 초안을 초기화하거나 선택한 기록을 잃지 않습니다.

## 기기 이름 대신 현재 제약을 사용합니다

다음과 같은 분기는 유지하기 어렵습니다.

```ts
if (deviceName === "specific-phone") {
  // 특정 기기에만 맞춘 배치
}
```

같은 기기에서도 분할 화면, 화면 확대, 회전, 큰 글자 설정에 따라 사용 가능한 공간이 달라집니다. 현재 너비, 높이, 글자 크기 배율과 콘텐츠 길이를 기준으로 배치를 정합니다.

```text
좁은 화면
→ 목록과 상세를 별도 경로로 표시

넓은 화면
→ 목록과 상세를 한 화면에 함께 표시할 수 있음

큰 글자
→ 한 줄 동작을 여러 줄이나 메뉴로 재배치
```

React Native 스타일의 숫자는 물리 픽셀 고정값이 아닙니다. 픽셀 밀도와 글자 크기 배율은 별도 입력입니다. 화면 캡처 한 장만 보고 모든 기기에서 같은 크기라고 판단하지 않습니다.

## Flexbox를 웹 CSS와 동일하게 가정하지 않습니다

React Native는 Yoga로 레이아웃을 계산합니다. 웹 CSS와 같은 이름의 속성도 기본값이나 지원 범위가 다를 수 있습니다.

확인할 내용은 다음과 같습니다.

- 부모가 자식에게 실제로 제공하는 공간
- 콘텐츠가 필요한 크기와 넘침
- 스크롤 컨테이너 안팎의 높이 계산
- 텍스트가 길어졌을 때 줄바꿈과 동작 재배치
- 절대 배치가 안전 영역이나 키보드 문제를 숨기지 않는지 여부

`flex: 1`을 추가하는 것만으로 모든 넘침이 해결됐다고 보지 않습니다.

Field Notes 목록 항목은 정보 우선순위를 명확히 둡니다.

```text
기록 제목
→ 기록 상태와 동기화 상태
→ 관찰 시각
→ 첨부 파일 여부
```

아이콘만으로 첨부 파일이나 동기화 상태를 표시하지 않습니다. 글자나 접근성 라벨로 같은 의미를 제공합니다.

## 안전 영역은 고정 여백이 아닙니다

상태 표시줄, 카메라 컷아웃, 홈 표시기와 시스템 제스처 영역은 기기와 방향에 따라 달라집니다. 화면 루트에서 여백값을 읽고 필요한 콘텐츠에 적용합니다.

다음 조합을 확인합니다.

- 화면 끝까지 그리는 화면의 상단 제목과 하단 동작
- 전체 화면 모달과 카메라
- 키보드가 열린 상태의 하단 버튼
- 가로 방향과 태블릿
- Android 화면 이동 모드 차이

안전 영역 여백값은 런타임 레이아웃 입력입니다. 기록이나 설정 값 저장소에 업무 값처럼 저장하지 않습니다.

## 키보드를 외부 시스템으로 취급합니다

화상 키보드는 화면 일부를 가리거나 창 크기를 바꿉니다. 입력 화면에서 다음 문제가 자주 발생합니다.

- 현재 입력과 검증 메시지가 가려집니다.
- 저장 또는 취소 버튼에 도달할 수 없습니다.
- 스크롤 위치가 갑자기 바뀝니다.
- Android와 iOS가 서로 다른 크기 조정과 화면 이동 동작을 보입니다.
- 물리 키보드에서는 화면 키보드를 전제로 한 코드가 맞지 않습니다.

입력 화면은 다음 조건을 만족해야 합니다.

1. 포커스된 필드를 보이는 영역으로 이동할 수 있습니다.
2. 오류 요약에서 문제가 있는 필드로 이동할 수 있습니다.
3. 키보드를 닫지 않아도 저장 동작에 도달할 수 있습니다.
4. 키보드를 닫아도 초안을 지우지 않습니다.
5. 저장 실패 뒤 입력값과 포커스할 위치가 남습니다.
6. 저장 성공 뒤 이동할 경로와 포커스 대상을 정합니다.

`KeyboardAvoidingView`를 추가한 것만으로 끝내지 않습니다. 실제 입력 화면, 스크롤, 모달과 각 플랫폼에서 확인합니다.

## 터치 동작의 상태를 명확히 표시합니다

손가락 입력은 마우스보다 정확하지 않으며 마우스를 올려 정보를 확인하는 동작도 없습니다. 작은 아이콘에만 기능을 넣거나 설명을 보이지 않게 숨기지 않습니다.

각 동작은 다음 정보를 가져야 합니다.

- 충분한 터치 영역과 주변 버튼 사이 간격
- 눌림 표시
- 비활성 상태와 작업 중 상태의 차이
- 빠른 연속 탭 처리
- 길게 누르기가 필수 동작인지 선택 동작인지 여부
- 제스처를 사용할 수 없을 때 실행할 대체 동작

예를 들어 동기화 버튼 상태를 다음처럼 나눌 수 있습니다.

```ts
type SyncActionState =
  | { kind: "ready" }
  | { kind: "running"; pendingCount: number }
  | { kind: "offline"; pendingCount: number }
  | { kind: "blocked"; reason: string };
```

`running`일 때 투명도만 낮추지 않습니다. 접근성 상태, 진행 설명과 사용자가 할 수 있는 다음 동작을 함께 제공합니다.

## 화면과 접근성 트리를 같은 상태에서 계산합니다

스크린 리더는 픽셀을 읽지 않습니다. 컴포넌트의 역할, 라벨, 값, 상태와 포커스 순서를 사용합니다.

### 라벨

눈에 보이는 이름이 없는 아이콘 버튼은 작업 결과를 설명하는 라벨을 가집니다.

```tsx
<Pressable
  accessibilityRole="button"
  accessibilityLabel="사진 추가"
  accessibilityHint="카메라 또는 사진 선택 화면을 엽니다"
  onPress={openAttachmentPicker}
>
  <CameraIcon />
</Pressable>
```

`카메라 아이콘`처럼 모양을 말하기보다 `사진 추가`처럼 사용자가 수행할 작업을 말합니다.

### 역할과 상태

- 실행 가능한 항목은 `button` 역할을 가집니다.
- 선택된 필터는 선택됨 상태를 제공합니다.
- 동기화 중이면 작업 중 상태와 진행 문구를 제공합니다.
- 검증 오류는 관련 필드와 연결합니다.
- 장식용 이미지는 포커스 대상에서 제외합니다.

색상, 아이콘, 라벨, 접근성 상태를 서로 다른 조건문에서 계산하지 않습니다. 하나의 애플리케이션 상태에서 파생합니다.

### 포커스

화면 전환과 오류 뒤 포커스가 갈 곳을 정합니다.

```text
새 화면 진입
→ 화면 제목 또는 첫 의미 있는 영역

모달 닫힘
→ 모달을 연 조작 요소

저장 실패
→ 오류 요약 또는 첫 오류 입력 항목

기록 삭제
→ 목록 제목 또는 합리적인 다음 항목
```

포커스를 무조건 화면 첫 항목으로 보내지 않습니다. 사용자가 수행한 작업과 현재 위치를 기준으로 정합니다.

## 상태 변경을 보이지 않게 끝내지 않습니다

오프라인 저장, 동기화 성공, 충돌 발생은 화면 일부만 바뀌더라도 사용자가 알아야 할 수 있습니다.

- 짧은 상태 변화는 플랫폼에 맞는 음성 알림을 사용합니다.
- 오류를 토스트에만 넣지 않고 화면에 남는 설명과 다음 동작을 제공합니다.
- 여러 기록의 동기화 결과를 모두 연속으로 읽지 않고 요약합니다.
- 백그라운드에서 바뀐 상태는 앱으로 돌아왔을 때 필요한 만큼 알립니다.

Android 실시간 알림 영역과 iOS 음성 알림이 같은 방식으로 동작한다고 가정하지 않습니다. TalkBack과 VoiceOver에서 중복 발화와 누락을 따로 확인합니다.

## 큰 글자와 긴 문자열을 정상 입력으로 둡니다

모든 텍스트에 `numberOfLines={1}`을 적용해 잘림을 숨기지 않습니다. 정보 우선순위에 따라 줄바꿈, 축약, 상세 화면 이동을 정합니다.

검사 항목:

- 최대 글자 크기 배율에서도 제목과 주요 동작이 보입니까?
- 버튼 글자가 길어져도 다른 버튼을 덮지 않습니까?
- 날짜와 숫자가 로케일에 맞게 표시됩니까?
- 오른쪽에서 왼쪽으로 쓰는 언어에서 아이콘 방향과 화면 이동 의미가 맞습니까?
- 색을 보지 못해도 동기화, 오류, 선택됨 상태를 구분할 수 있습니까?
- 굵은 글씨 텍스트 설정이 레이아웃을 깨뜨리지 않습니까?

문자열 길이를 영어 기준으로 고정하지 않습니다.

## 초안과 명시적 저장을 구분합니다

사용자가 전화를 받거나 다른 앱으로 이동해도 작성 중인 내용을 쉽게 잃지 않아야 합니다. 필요한 경우 다음처럼 나눌 수 있습니다.

```text
입력값 변경
→ 메모리 초안 갱신
→ 필요하면 로컬 초안 저장
→ 사용자가 저장 선택
→ 기록과 outbox 트랜잭션
```

- 초안 저장은 작성 중 입력을 복구하기 위한 것입니다.
- 저장은 로컬 리비전과 동기화 명령을 만드는 업무 사건입니다.

두 의미를 섞으면 사용자가 저장하지 않은 내용이 서버로 전송되거나, 저장했다고 생각한 내용이 메모리에만 남을 수 있습니다.

Field Notes의 완성 구현은 화면을 떠날 때 저장하지 않은 초안을 명시적으로 처리하고, 저장이 성공하면 기록과 outbox를 함께 커밋합니다.

## 긴 목록과 이미지를 다룹니다

기록이 많아지면 모든 항목을 한 번에 렌더링하거나 원본 사진을 목록에서 직접 디코딩하지 않습니다.

- 키는 기록 식별 정보를 사용합니다.
- 행은 관련 없는 전역 상태 변화 때문에 모두 다시 렌더링되지 않게 합니다.
- 썸네일은 화면에 필요한 크기로 디코딩하고 캐시 상한을 둡니다.
- 로컬 쿼리와 다음 페이지가 같은 정렬 규칙을 사용합니다.
- 빈 상태, 로딩, 오래된, 오류, 오프라인 상태를 구분합니다.
- 접근성 읽기 순서와 눈에 보이는 순서를 맞춥니다.

성능 개선은 추측으로 결과 저장을 추가하는 방식이 아니라 릴리스에 가까운 빌드에서 측정한 뒤 진행합니다.

## Android와 iOS에 같은 모양을 강제하지 않습니다

두 플랫폼에서 같은 업무 결과를 제공하되, 운영체제가 제공하는 관례와 제어를 무시하지 않습니다.

- 뒤로 가기 동작은 플랫폼별 입력이 달라도 같은 초안 처리 규칙을 사용합니다.
- 권한 대화 상자와 설정 이동은 플랫폼 방식에 맞춥니다.
- 모달, 헤더와 제스처는 플랫폼 기대와 충돌하지 않게 합니다.
- 같은 색상과 간격을 강제하는 것보다 같은 정보와 동작에 접근 가능한지가 중요합니다.

## 실제 검증

최소한 다음 상태를 Android와 iOS에서 확인합니다.

```text
작은 휴대전화
큰 글자 크기 배율
화상 키보드
물리 키보드 가능 시
스크린 리더
가로 방향 또는 분할 화면 가능 시
저장 실패
오프라인 저장
충돌 표시
모달과 뒤로 가기
```

자동 컴포넌트 테스트는 역할, 라벨, 상태와 일부 상호작용을 확인할 수 있습니다. 실제 스크린 리더의 발화 순서, 키보드가 가리는 영역, 제스처와 포커스 이동은 실제 기기에서 확인해야 합니다.

## 완료 기준

- 기기 이름이 아니라 현재 창과 글자 크기 배율로 레이아웃을 정합니다.
- 안전 영역과 키보드가 주요 동작과 오류를 가리지 않습니다.
- 큰 글자와 긴 문자열에서도 저장과 취소를 수행할 수 있습니다.
- 화면에 보이는 상태와 접근성 상태가 같은 값에서 계산됩니다.
- 아이콘만 있는 동작에 작업 중심 라벨이 있습니다.
- 저장 실패 뒤 초안과 합리적인 포커스 위치가 남습니다.
- 터치를 사용할 수 없는 경우에도 핵심 동작을 실행할 수 있습니다.
- TalkBack과 VoiceOver에서 기록 생성, 저장, 오류 확인과 충돌 선택을 수행했습니다.
