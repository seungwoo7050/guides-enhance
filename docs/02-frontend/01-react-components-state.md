# React 컴포넌트와 상태

React에서는 현재 값으로 화면을 다시 계산합니다. 따라서 중요한 질문은 “컴포넌트를 몇 개로 나눌까?”보다 “어느 값이 상태이고, 누가 그 값을 바꿀까?”입니다.

## 목표

- `props`와 `state`의 차이를 설명합니다.
- 상태를 실제로 함께 사용하는 가장 가까운 컴포넌트에 둡니다.
- 이전 상태를 바탕으로 새 배열과 객체를 만듭니다.
- 기존 값에서 계산할 수 있는 값을 별도 상태로 저장하지 않습니다.
- 서버, URL, 컴포넌트에 저장할 값을 구분합니다.

## 컴포넌트는 입력으로 화면을 만듭니다

```tsx
type TaskItemProps = {
  task: Task;
  onToggle: (id: string) => void;
};

export function TaskItem({ task, onToggle }: TaskItemProps) {
  return (
    <li>
      <label>
        <input
          type="checkbox"
          checked={task.completed}
          onChange={() => onToggle(task.id)}
        />
        {task.title}
      </label>
    </li>
  );
}
```

`props`는 부모가 전달한 입력입니다. 자식이 `props`를 직접 바꾸지 않고, 변경 요청을 콜백으로 부모에게 전달합니다.

## 렌더링 사이에 유지할 값만 state로 둡니다

```tsx
const [tasks, setTasks] = useState<Task[]>([]);
```

사용자 입력 뒤에도 남아 있어야 하고 다음 화면에 영향을 주는 값은 `state`가 될 수 있습니다.

- 입력 중인 문자열
- 선택한 탭
- 대화 상자의 열림 여부
- 서버 응답을 기다리는 임시 항목

반면 아래 값은 `tasks`에서 바로 계산할 수 있습니다.

```tsx
const openCount = tasks.filter((task) => !task.completed).length;
```

`tasks`와 `openCount`를 모두 상태로 저장하면 한쪽만 갱신되어 값이 어긋날 수 있습니다.

## 이전 상태에 의존하면 함수형 갱신을 사용합니다

```tsx
setTasks((current) => current.map((task) =>
  task.id === id ? { ...task, completed: !task.completed } : task
));
```

React는 여러 상태 변경을 한 번에 처리할 수 있습니다. 다음 값이 직전 값에 의존한다면 현재 렌더링이 기억한 변수를 사용하지 말고 갱신 함수를 전달합니다.

```tsx
setCount((value) => value + 1);
setCount((value) => value + 1);
```

## 배열과 객체를 직접 바꾸지 않습니다

```tsx
// 피합니다.
tasks.push(newTask);
setTasks(tasks);
```

같은 배열을 다시 전달하면 React가 변경을 감지하지 못할 수 있습니다. 변경할 경로에 새 배열이나 객체를 만듭니다.

```tsx
setTasks((current) => [...current, newTask]);
```

스프레드 문법은 한 단계만 복사합니다. 중첩된 객체를 바꿀 때는 실제로 달라지는 경로마다 새 값을 만들어야 합니다.

## 상태를 저장할 위치

| 값 | 기준이 되는 위치 | 예시 |
|---|---|---|
| 서버 데이터 | API와 데이터베이스 | 사용자, 보드, 경기 기록 |
| 주소로 공유할 값 | URL | 검색어, 필터, 페이지 번호 |
| 연결 중에 받은 값 | 서버 메시지와 마지막 시퀀스 | 접속 상태, 실시간 변경 |
| 화면에서만 쓰는 값 | 컴포넌트 | 입력 초안, 메뉴 열림 여부 |

서버에서 받은 같은 목록을 여러 컴포넌트의 `useState`에 각각 복사하면 변경 뒤 서로 다른 값을 보여 줄 수 있습니다. 한곳에서 읽고 필요한 컴포넌트에 전달하거나, 하나의 캐시가 값을 관리하도록 합니다.

## 상태를 위로 올릴 때

형제 컴포넌트가 같은 값을 읽거나 바꿔야 한다면 가장 가까운 공통 부모가 상태를 가질 수 있습니다. 모든 값을 페이지 최상단으로 옮기지는 않습니다.

다음 질문으로 위치를 정합니다.

1. 누가 이 값을 바꿉니까?
2. 어느 컴포넌트까지 이 값이 필요합니까?
3. 서버나 URL에 이미 기준값이 있습니까?
4. 다른 값에서 계산할 수 있습니까?

## 컴포넌트를 나누는 기준

다음 중 실제 이유가 있을 때 분리합니다.

- 독립적으로 사용할 수 있는 UI입니다.
- 별도의 상태나 Effect를 관리합니다.
- 여러 화면에서 반복해서 사용합니다.
- 단독 테스트가 의미 있습니다.
- 서버에서 실행할 코드와 브라우저에서 실행할 코드를 나눠야 합니다.

JSX 줄 수만으로 작은 래퍼 컴포넌트를 계속 만들 필요는 없습니다.

## 목록의 `key`

```tsx
{tasks.map((task) => <TaskItem key={task.id} task={task} />)}
```

`key`는 이전 렌더링의 항목과 다음 렌더링의 항목을 연결합니다. 정렬·삽입·삭제가 있는 목록에서 배열 인덱스를 쓰면 입력값이나 포커스가 다른 항목에 붙을 수 있습니다.

## 흔한 실수

- 전달받은 `props`를 직접 바꿉니다.
- 계산 가능한 값을 별도 상태로 저장합니다.
- 배열과 객체를 제자리에서 수정합니다.
- 서버 값과 URL 값을 컴포넌트 상태에 다시 복사합니다.
- 목록의 `key`로 배열 인덱스를 사용합니다.
- 작은 입력값까지 모두 페이지 최상단에서 관리합니다.

## 완료 기준

- `props`와 `state`를 누가 바꿀 수 있는지 설명합니다.
- 기존 상태에서 새 배열과 객체를 만듭니다.
- 계산 가능한 값을 중복 저장하지 않습니다.
- 서버, URL, 실시간 연결, 컴포넌트 중 어디에 값을 둘지 선택할 수 있습니다.
- 목록에서 안정적인 식별자를 `key`로 사용합니다.
