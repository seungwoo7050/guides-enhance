# 데이터 경로와 제어

ISA가 명령의 결과를 정하면 프로세서는 레지스터 파일, ALU, 메모리 포트와 멀티플렉서를 연결해 그 결과를 만듭니다. 값이 지나가는 연결을 데이터 경로라고 부르고, 어느 입력을 선택하고 어느 저장소에 쓸지는 제어 신호가 정합니다.

## 학습 목표

- 명령별로 읽는 값, 계산 경로와 변경하는 상태를 구분합니다.
- 조합 논리와 클록에 맞춰 값을 저장하는 상태 요소를 구분합니다.
- `lw`, `sw`, ALU 명령과 분기의 제어 신호를 작성합니다.
- 임계 경로와 예외가 발생했을 때 막아야 할 쓰기를 찾습니다.

## 명령을 상태 변경으로 봅니다

소프트웨어에 보이는 상태를 단순화하면 다음과 같습니다.

```text
PC
integer registers
memory
```

명령 하나는 이 상태 일부를 읽고 다음 상태를 만듭니다.

```text
PC가 가리키는 명령 읽기
→ 연산 코드와 피연산자 해석
→ ALU 결과·주소·분기 조건 계산
→ 필요한 경우 데이터 메모리 접근
→ 필요한 경우 레지스터에 결과 기록
→ 다음 PC 선택
```

단일 사이클 구현은 이 과정을 한 클록 주기 안에 끝냅니다. 다중 사이클 구현은 한 명령을 여러 사이클로 나누고, 파이프라인은 서로 다른 명령의 단계를 겹칩니다.

## 주요 구성 요소

### PC 레지스터

현재 명령 주소를 보관합니다. 순차 주소, 분기 목적지, 점프 목적지 또는 예외 벡터 중 다음 값을 선택합니다.

### 명령 메모리 또는 명령 캐시

PC를 주소로 사용해 명령 비트를 제공합니다. 첫 모델에서는 한 번에 읽힌다고 가정하지만 실제 프로세서에서는 캐시 실패와 주소 변환이 필요할 수 있습니다.

### 레지스터 파일

소스 레지스터를 읽고 목적지 레지스터에 결과를 씁니다. 같은 사이클에 읽기와 쓰기가 겹칠 때 어느 값이 보이는지는 타이밍과 전달 경로 설계에 영향을 줍니다.

### 즉시값 생성기

명령 형식에 흩어진 즉시값 필드를 합치고 부호 확장 또는 0 확장을 수행합니다.

### ALU

산술, 비트 연산, 비교와 주소 계산을 수행합니다. 어떤 연산을 선택하는지 제어 신호로 지정해야 합니다.

### 데이터 메모리 포트

적재 명령은 주소에서 값을 읽고, 저장 명령은 주소와 쓸 값을 전달합니다. 바이트 쓰기 활성화, 정렬과 예외 여부도 확인해야 합니다.

### 멀티플렉서

여러 후보 가운데 하나를 선택합니다. 예를 들어 ALU의 두 번째 피연산자가 레지스터인지 즉시값인지, 레지스터에 쓸 값이 ALU 결과인지 메모리에서 읽은 값인지 정합니다.

## `add`의 경로

```text
register[rs1] ─┐
                ├─ ALU(add) ─→ register[rd]
register[rs2] ─┘
PC ─→ 다음 순차 PC
```

필요한 제어는 다음과 같습니다.

- 레지스터 쓰기 활성화
- ALU 피연산자 B를 레지스터로 선택
- ALU 연산을 덧셈으로 선택
- 레지스터에 쓸 값으로 ALU 결과 선택
- 메모리 읽기와 쓰기 비활성화
- 다음 PC로 순차 주소 선택

## `addi`의 경로

`addi`는 `add`와 같은 ALU를 사용하지만 두 번째 피연산자로 부호 확장한 즉시값을 선택합니다.

```text
register[rs1] ─┐
                ├─ ALU(add) ─→ register[rd]
immediate ──────┘
```

명령 종류마다 별도 ALU를 만들 필요는 없습니다. 같은 하드웨어를 제어 신호로 재사용할 수 있습니다.

## `lw`의 경로

```text
base register + sign-extended offset
→ effective address
→ data memory read
→ destination register write-back
```

단일 사이클 구현에서는 명령 인출, 레지스터 읽기, ALU 계산, 데이터 메모리 읽기와 레지스터 쓰기가 한 클록 주기에 들어갈 수 있습니다. `lw`가 가장 긴 경로라면 단순한 ALU 명령도 같은 클록 주기를 사용해야 합니다.

```sh
cd exercises/processor-model
python3 processor-model.py control lw
```

출력에서 `mem_read=1`, `reg_write=1`, `writeback=memory`를 확인합니다.

## `sw`의 경로

```text
base + offset → address
source register → data memory write data
```

저장 명령은 주소 계산에 사용하는 기준 레지스터와 실제로 저장할 값의 레지스터를 모두 읽습니다. 목적지 레지스터가 없으므로 `reg_write`를 활성화하면 의도하지 않은 레지스터가 바뀔 수 있습니다.

## 분기의 경로

`beq`를 단순화하면 두 레지스터를 비교하고 분기 목적지 또는 순차 PC를 선택합니다.

```text
register[rs1] - register[rs2] → zero?
PC + branch offset            → target
zero && branch                → next PC 선택
```

분기 목적지를 계산하는 덧셈기를 ALU와 공유하면 같은 사이클에 두 계산이 필요할 때 자원 충돌이 생길 수 있습니다. 별도 덧셈기를 두면 하드웨어는 늘지만 타이밍과 파이프라인 구성이 단순해질 수 있습니다.

## 제어표

Tiny-RISC의 일부 명령을 비교하면 다음과 같습니다.

| 연산 코드 | `reg_write` | ALU B | `mem_read` | `mem_write` | `writeback` | 분기 |
| --- | ---: | --- | ---: | ---: | --- | --- |
| `add` | 1 | 레지스터 | 0 | 0 | ALU | none |
| `addi` | 1 | 즉시값 | 0 | 0 | ALU | none |
| `lw` | 1 | 즉시값 | 1 | 0 | 메모리 | none |
| `sw` | 0 | 즉시값 | 0 | 1 | none | none |
| `beq` | 0 | 레지스터 | 0 | 0 | none | equal |

새 명령을 추가할 때는 명령 이름만 설명하지 말고 다음을 확인합니다.

1. 어느 레지스터와 메모리를 읽습니까?
2. ALU가 어떤 값을 계산합니까?
3. 어떤 상태 요소에 결과를 씁니까?
4. 예외가 나면 어떤 쓰기를 막아야 합니까?
5. 다음 PC는 어떻게 정합니까?

## 조합 논리와 상태 요소

ALU, 비교기와 멀티플렉서는 현재 입력으로 출력을 계산하는 조합 논리입니다. PC와 레지스터 파일의 저장 부분은 클록 사이에 값을 유지하는 상태 요소입니다.

클록 기반 회로를 볼 때는 다음을 구분합니다.

1. 한 사이클 동안 어느 경로로 값이 전달됩니까?
2. 클록 에지에서 어느 상태 요소가 값을 받아들입니까?
3. 쓰기 활성화 신호가 꺼져 있으면 이전 값이 유지됩니까?
4. 경로 지연이 클록 주기 안에 들어옵니까?

소프트웨어 문장처럼 위에서 아래로 즉시 값이 바뀐다고 생각하면 같은 사이클의 읽기와 쓰기 의미를 잘못 해석할 수 있습니다.

## 임계 경로

클록 주기는 가장 긴 활성 조합 논리 경로보다 짧을 수 없습니다.

```text
clock period ≥ state output delay
             + combinational path delay
             + setup time
```

단일 사이클 프로세서가 CPI 1이라는 사실만으로 빠르다고 결론 내릴 수 없습니다.

```text
CPU time = instruction count × CPI × clock period
```

CPI와 클록 주기를 함께 비교해야 합니다.

## 다중 사이클 실행

한 명령을 여러 사이클로 나누면 ALU 하나를 PC 증가, 주소 계산과 산술 연산에 다시 사용할 수 있습니다.

```text
cycle 1: fetch
cycle 2: decode / register read
cycle 3: execute / address calculation
cycle 4: memory
cycle 5: write-back
```

모든 명령이 모든 사이클을 사용할 필요는 없습니다. 대신 중간 결과를 저장할 레지스터와 다음 단계를 정하는 제어 상태가 필요합니다.

다중 사이클 실행과 파이프라인은 다릅니다.

- 다중 사이클 실행은 한 명령의 단계를 여러 사이클로 나눕니다.
- 파이프라인은 서로 다른 명령의 단계를 겹칩니다.

## 하드와이어드 제어와 마이크로코드

연산 코드 필드를 조합 논리로 해석해 제어 신호를 직접 만들 수 있습니다. 복잡한 명령을 더 작은 내부 연산의 순서로 실행하도록 제어 저장소를 사용할 수도 있습니다.

이 둘을 RISC와 CISC의 절대적인 구분으로 사용하면 안 됩니다. 실제 프로세서는 명령 종류에 따라 여러 방법을 함께 사용할 수 있습니다. 소프트웨어에 보이는 ISA 명령 한 개와 내부 마이크로 연산 수가 항상 같지도 않습니다.

## 예외와 부분 쓰기 방지

잘못된 적재 주소를 확인하기 전에 목적지 레지스터를 바꾸면 한 명령의 결과가 일부만 반영됩니다. 예외가 확정되면 다음 쓰기를 막아야 합니다.

- 레지스터 쓰기
- 메모리 쓰기
- 정상 실행 경로의 PC 쓰기

파이프라인과 비순차 실행에서는 여러 명령이 동시에 진행하므로 더 젊은 명령의 쓰기도 함께 취소해야 합니다.

## 데이터 경로 그림을 읽는 순서

1. 선택한 명령이 읽는 상태를 표시합니다.
2. 사용하지 않는 멀티플렉서 입력을 지웁니다.
3. ALU 연산과 메모리 방향을 적습니다.
4. 목적지 상태를 표시합니다.
5. 다음 PC 경로를 표시합니다.
6. 잘못된 연산 코드 또는 주소에서 끌 쓰기 활성화 신호를 표시합니다.
7. 활성 경로 가운데 가장 긴 경로를 찾습니다.
