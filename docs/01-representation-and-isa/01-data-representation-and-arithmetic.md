# 데이터 표현과 산술

프로세서는 레지스터와 메모리에 비트 패턴을 저장합니다. `11111111`이 `255`, `-1`, 문자 한 바이트 또는 명령의 일부 가운데 무엇을 뜻하는지는 그 비트를 읽는 명령과 자료형이 결정합니다. 값과 비트 패턴을 구분하면 오버플로, 바이트 순서, 정렬과 부동소수점 반올림을 같은 기준으로 설명할 수 있습니다.

## 학습 목표

- 고정 폭 정수를 부호 있는 값과 부호 없는 값으로 각각 해석합니다.
- 자리올림과 부호 있는 오버플로를 구분합니다.
- 확장, 축소, 시프트, 바이트 순서와 정렬을 설명합니다.
- IEEE 754의 부호, 지수, 가수 필드와 특별한 값을 구분합니다.

## 비트 패턴에는 자료형이 없습니다

8비트 패턴 `11111111`을 두 방식으로 읽을 수 있습니다.

```text
unsigned 8-bit: 255
signed 8-bit two's complement: -1
```

메모리에는 `signed`라는 표시가 따로 저장되지 않습니다. 어떤 명령이 그 비트를 읽는지, 컴파일러가 어떤 연산을 선택했는지가 해석을 정합니다.

폭이 `w`인 부호 없는 정수의 범위는 다음과 같습니다.

```text
0 .. 2^w - 1
```

2의 보수 부호 있는 정수의 범위는 다음과 같습니다.

```text
-2^(w-1) .. 2^(w-1) - 1
```

8비트에서 `10000000`은 `-128`입니다. 같은 폭으로 `+128`을 표현할 수 없는 이유는 최상위 비트가 1인 패턴 절반을 음수에 배정하기 때문입니다.

## 고정 폭 덧셈

하위 `w`비트만 남기면 연산 결과는 `2^w`를 법으로 하는 나머지 연산과 같습니다.

```text
8-bit unsigned: 255 + 1 = 0, carry out = 1
8-bit signed:   127 + 1 = -128, signed overflow = 1
```

두 계산은 같은 덧셈 결과 비트를 사용하지만 범위를 벗어났는지 판정하는 조건은 다릅니다.

### 자리올림과 부호 없는 오버플로

최상위 비트 밖으로 자리올림이 나가면 부호 없는 정수 범위를 벗어났습니다.

### 부호 있는 오버플로

같은 부호의 두 값을 더했는데 결과의 부호가 바뀌면 2의 보수 부호 있는 정수 범위를 벗어났습니다.

```text
positive + positive → negative
negative + negative → non-negative
```

`127 + 1`은 자리올림 없이 부호 있는 오버플로가 발생합니다. `255 + 1`은 자리올림이 발생하지만 같은 비트를 부호 있는 값으로 읽으면 `-1 + 1 = 0`이므로 부호 있는 오버플로는 아닙니다.

직접 확인할 수 있습니다.

```sh
cd exercises/processor-model
python3 processor-model.py bits add 127 1 --width 8
python3 processor-model.py bits add 255 1 --width 8
```

## 확장과 축소

작은 폭의 값을 큰 폭으로 옮길 때는 상위 비트를 어떻게 채울지 정해야 합니다.

```text
8-bit pattern: 11111111
zero extension to 16-bit: 00000000 11111111 = 255
sign extension to 16-bit: 11111111 11111111 = -1
```

부호 있는 값을 보존하려면 부호 비트를 복제하고, 부호 없는 값을 보존하려면 0을 채웁니다. 단순히 더 큰 자료형으로 변환했다고 값이 항상 보존되는 것은 아닙니다. 원래 폭과 부호 해석을 먼저 확인해야 합니다.

좁히는 변환은 상위 비트를 버립니다. 버린 비트를 다시 부호 확장하거나 0으로 확장했을 때 원래 값이 되지 않는다면 정보가 손실된 것입니다.

## 시프트

왼쪽 시프트는 범위를 넘지 않는 조건에서 `2^n`을 곱한 것과 같은 결과를 만들 수 있습니다. 오른쪽 시프트는 비워진 상위 비트를 채우는 방법을 구분합니다.

- 논리 오른쪽 시프트는 0을 채웁니다.
- 산술 오른쪽 시프트는 부호 비트를 복제합니다.

ISA는 두 동작을 서로 다른 명령으로 제공할 수 있습니다. 프로그래밍 언어의 음수 시프트 규칙과 ISA의 명령 의미를 같은 것으로 취급하면 안 됩니다. 이동량이 피연산자 폭 이상일 때도 언어와 ISA의 규칙이 다를 수 있습니다.

## 바이트 순서

`0x12345678`을 네 바이트로 나누면 `12 34 56 78`입니다.

```text
낮은 주소 → 높은 주소
big-endian:    12 34 56 78
little-endian: 78 56 34 12
```

바이트 순서는 한 바이트 안의 비트 순서를 뒤집는 개념이 아닙니다. 여러 바이트를 메모리나 바이트 스트림에 놓고 다시 정수로 조립할 때 드러납니다.

파일 형식, 네트워크 프로토콜과 직렬화 형식은 바이트 순서를 명시해야 합니다. 호스트 바이트 순서를 영구 형식으로 그대로 저장하면 다른 환경에서 같은 값을 읽지 못할 수 있습니다.

```sh
python3 processor-model.py bits int 0x12345678 --width 32
```

## 정렬

4바이트 워드를 4의 배수 주소에서 읽는 규칙을 예로 들 수 있습니다.

```text
aligned:   0, 4, 8, 12, ...
unaligned: 1, 2, 3, 5, ...
```

정렬되지 않은 접근은 ISA와 명령에 따라 다음과 같이 처리될 수 있습니다.

- 예외를 발생시킵니다.
- 하드웨어가 여러 접근으로 나눕니다.
- 일부 명령에서만 허용합니다.
- 허용하지만 더 많은 사이클이 필요합니다.

C 구조체에는 각 멤버의 정렬을 맞추기 위한 패딩이 들어갈 수 있습니다.

```c
struct item {
    char kind;
    int value;
};
```

따라서 `sizeof(struct item)`을 단순히 `1 + 4`라고 계산할 수 없습니다. 멤버 순서를 바꾸면 크기가 줄 수 있지만 ABI, 직렬화와 캐시 라인 배치도 함께 달라질 수 있습니다.

Tiny-RISC는 워드 접근을 4바이트 정렬로 제한합니다.

```sh
python3 -m unittest \
  tests.test_processor_model.IsaTests.test_unaligned_access_fails -v
```

## 정수와 포인터 폭

주소를 `int`에 저장할 수 있다고 가정하면 주소 폭이 더 큰 환경에서 상위 비트를 잃을 수 있습니다. C에서 포인터를 정수로 옮겨야 하는 특별한 경우에는 `uintptr_t`처럼 목적이 드러나는 자료형을 검토해야 합니다.

폭이 충분하다는 사실만으로 유효한 포인터가 되지는 않습니다. 해당 주소가 매핑되어 있고, 접근 권한과 정렬이 맞으며, 가리키는 객체가 아직 살아 있어야 합니다.

## IEEE 754 부동소수점

대표적인 이진 부동소수점 형식은 다음 필드를 사용합니다.

| 형식 | 부호 | 지수 | 가수 | 전체 폭 |
| --- | ---: | ---: | ---: | ---: |
| binary32 | 1 | 8 | 23 | 32 |
| binary64 | 1 | 11 | 52 | 64 |

정규값은 개념적으로 다음과 같습니다.

```text
(-1)^sign × 1.fraction × 2^(exponent-bias)
```

유한한 비트로 모든 실수를 정확히 표현할 수는 없습니다. `0.1`은 이진 분수로 유한하게 끝나지 않으므로 f32와 f64 모두 가장 가까운 표현 가능한 값으로 반올림합니다.

```sh
python3 processor-model.py bits float 0.1 --format f32
python3 processor-model.py bits float 0.1 --format f64
```

### 특별한 지수 값

- 지수 필드가 모두 0이면 0 또는 비정규값입니다.
- 지수 필드가 모두 1이면 무한대 또는 NaN입니다.
- `+0`과 `-0`은 비트가 다르지만 비교 결과는 같을 수 있습니다.
- NaN은 일반 실수와 다른 비교 규칙을 가집니다.

## 연산 순서와 반올림

실수 수학에서는 덧셈의 결합법칙이 성립하지만 부동소수점 연산은 각 중간 결과를 반올림합니다.

```text
(a + b) + c != a + (b + c) 일 수 있음
```

컴파일러가 벡터화 또는 병렬 축약으로 연산 순서를 바꾸면 마지막 비트가 달라질 수 있습니다. 다음 요구를 구분해야 합니다.

- 허용 오차 안의 결과가 필요한 계산
- 비트 단위 재현성이 필요한 계산
- 오버플로, 언더플로와 NaN 전파를 검사해야 하는 계산

`fast-math` 계열 옵션은 단순한 속도 옵션이 아닙니다. IEEE 754에 관한 일부 가정을 완화할 수 있으므로 허용되는 변환을 확인해야 합니다.

## 고정소수점

화폐처럼 소수 자릿수가 고정되어 있고 정확한 정수 계산이 중요하면 최소 단위를 정수로 저장할 수 있습니다.

```text
10.25 단위 → 1025 최소 단위
```

이 방법도 배율, 곱셈 중간값의 폭, 나눗셈 반올림과 오버플로를 명시해야 합니다.
