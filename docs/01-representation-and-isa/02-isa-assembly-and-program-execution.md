# ISA, 어셈블리와 프로그램 실행

명령어 집합 구조(ISA)는 소프트웨어가 프로세서에 기대할 수 있는 명령의 의미를 정합니다. 레지스터, 명령 인코딩, 주소 계산, 예외와 메모리 접근 규칙이 여기에 포함됩니다. 반면 파이프라인 단계 수, 캐시 크기와 내부 실행 장치는 일반적으로 마이크로아키텍처가 정합니다.

## 학습 목표

- ISA, ABI와 마이크로아키텍처를 구분합니다.
- 명령 하나가 레지스터, PC와 메모리를 어떻게 바꾸는지 추적합니다.
- 소스가 객체 파일과 실행 파일을 거쳐 실행되는 과정을 구분합니다.
- 함수 호출과 시스템 호출이 사용하는 상태와 권한을 설명합니다.

## ISA와 마이크로아키텍처

같은 ISA 바이너리는 서로 다른 프로세서에서 실행될 수 있습니다.

```text
같은 ISA
├─ 작은 순차 실행 코어
├─ 넓은 비순차 실행 코어
└─ 에뮬레이터 또는 가상 머신
```

각 구현은 같은 명령에 대해 소프트웨어가 관찰하는 레지스터와 메모리 결과를 같게 만들어야 합니다. 그러나 사이클 수, 캐시 상태와 내부 실행 순서는 달라질 수 있습니다.

따라서 특정 구현을 지정하지 않고 “이 명령은 한 사이클에 실행됩니다”라고 말할 수 없습니다.

## 레지스터와 ABI 이름

레지스터 파일은 ALU 피연산자와 결과를 저장하는 작은 저장소입니다. ISA는 명령 안에 레지스터 번호를 넣고, ABI는 같은 레지스터에 스택 포인터, 반환 주소와 인자처럼 함수 호출에서 사용하는 역할을 부여합니다.

다음 세 가지를 구분해야 합니다.

- 명령 인코딩에 들어가는 레지스터 번호
- 어셈블리 문법에서 사용하는 레지스터 이름
- ABI가 부여한 함수 호출 역할

ABI가 붙인 이름은 명령 자체의 산술 의미가 아닙니다.

## 적재와 저장

대표적인 RISC 명령은 계산과 메모리 접근을 나눕니다.

```text
load:  memory → register
ALU:   register operands → register result
store: register → memory
```

예를 들면 다음과 같습니다.

```asm
lw   r1, 0(r2)
add  r3, r1, r4
sw   r3, 0(r2)
```

`0(r2)`는 기준 레지스터 `r2`와 즉시값 오프셋 `0`을 더해 유효 주소를 만듭니다. 즉시값 폭, 부호 확장, 정렬과 예외 규칙은 ISA마다 다릅니다.

## 즉시값과 의사 명령

명령 폭은 제한되어 있으므로 큰 상수를 한 명령에 모두 넣지 못할 수 있습니다. 어셈블러는 작성 편의를 위한 의사 명령 하나를 여러 실제 명령으로 바꿀 수 있습니다.

```text
어셈블리 소스 한 줄
≠ 반드시 기계어 명령 한 개
```

반대로 압축 명령처럼 같은 의미를 더 짧은 인코딩으로 표현하는 확장도 있습니다. 성능을 분석할 때는 소스 줄 수가 아니라 실제 명령열을 확인해야 합니다.

## PC와 제어 이동

PC는 다음에 가져올 명령의 주소를 가리킵니다. 일반 명령은 다음 순차 주소로 이동하고, 분기·점프·예외는 다른 주소를 선택할 수 있습니다.

```text
if condition:
    PC = target
else:
    PC = next
```

ISA는 분기 조건과 목적지 계산법을 정합니다. 프로세서가 분기 결과를 어느 단계에서 확인하고 잘못 가져온 명령을 어떻게 버리는지는 마이크로아키텍처가 정합니다.

## 명령 형식

고정 폭 RISC 명령에는 일반적으로 다음 정보가 들어갑니다.

- 연산 코드
- 소스 레지스터
- 목적지 레지스터
- 즉시값 또는 기능 필드

모든 명령이 같은 필드를 같은 위치에 둘 필요는 없습니다. 바이너리 명령을 읽을 때는 다음 순서를 사용합니다.

1. 명령 폭과 바이트 순서를 확인합니다.
2. 연산 코드로 명령 형식을 고릅니다.
3. 레지스터와 기능 필드를 나눕니다.
4. 흩어진 즉시값 조각을 명세 순서대로 합칩니다.
5. 부호 확장과 정렬 단위를 적용합니다.

## 소스에서 실행 파일까지

대표적인 네이티브 빌드 과정은 다음과 같습니다.

```text
C/C++ source
→ compiler가 assembly 또는 machine code 생성
→ assembler가 relocatable object file 생성
→ linker가 symbol과 relocation 해결
→ loader가 실행 구간과 shared library를 address space에 배치
→ entry point 실행
```

### 어셈블러

레이블을 명령 주소로 바꾸고 명령 이름을 바이너리 인코딩으로 변환합니다. 최종 주소를 아직 모르면 재배치 정보를 남길 수 있습니다.

### 링커

여러 객체 파일과 라이브러리의 심볼을 연결하고 섹션을 배치합니다. 해결되지 않은 심볼이나 중복 정의는 이 단계에서 드러날 수 있습니다.

### 로더

운영체제가 실행 파일과 공유 라이브러리를 가상 주소 공간에 매핑하고 스택, 인자와 초기 레지스터 상태를 준비합니다.

“컴파일러가 실행 파일을 만듭니다”라는 표현은 전체 도구를 묶어 부를 때는 편리합니다. 오류가 난 단계를 찾을 때는 컴파일러, 어셈블러, 링커와 로더를 구분해야 합니다.

## ABI와 함수 호출

ISA가 같아도 인자, 반환값, 스택 정렬과 보존 레지스터 규칙이 다르면 독립적으로 만든 객체 파일이 서로 호출될 수 없습니다. ABI가 이 규칙을 정합니다.

### 호출자가 보존하는 레지스터

호출한 함수가 값을 계속 사용해야 한다면 호출 전에 저장합니다. 호출받은 함수는 해당 레지스터를 덮어쓸 수 있습니다.

### 호출받은 함수가 보존하는 레지스터

호출받은 함수가 수정했다면 반환 전에 원래 값을 복원합니다.

한 방식이 항상 더 빠른 것은 아닙니다. 호출 그래프와 레지스터 사용량에 따라 실제 저장 횟수가 달라집니다.

## 스택 프레임

레지스터에 남기지 못한 지역 값, 보존 레지스터, 반환 주소와 일부 인자를 스택에 둘 수 있습니다.

```text
높은 주소
┌────────────────┐
│ caller frame   │
├────────────────┤
│ saved values   │
│ local / spill  │ ← current frame
├────────────────┤
│ callee frame   │
└────────────────┘
낮은 주소
```

스택이 자라는 방향, 프레임 포인터 사용 여부와 반환 주소 위치는 ISA와 ABI에 따라 다릅니다. 컴파일러가 함수를 인라인하면 소스의 함수 호출이 실제 호출 명령으로 남지 않을 수도 있습니다.

어셈블리에서 함수 호출을 볼 때는 다음을 확인합니다.

1. 인자는 어느 레지스터 또는 스택 위치에 있습니까?
2. 반환 주소는 어디에 저장됩니까?
3. 호출받은 함수가 보존해야 할 레지스터를 수정합니까?
4. 반환값은 어디에 놓입니까?
5. 스택 포인터는 호출 전후에 같은 값으로 복원됩니까?

## 시스템 호출

일반 함수 호출은 같은 권한 수준의 코드로 이동합니다. 시스템 호출 명령은 정해진 레지스터와 트랩 방식을 사용해 커널로 제어를 넘깁니다.

```text
사용자 코드
→ 라이브러리 감싸기 함수
→ 시스템 호출 명령
→ 커널 처리기
→ 사용자 모드 복귀
```

모든 라이브러리 함수 호출이 시스템 호출 하나와 일대일로 대응하는 것은 아닙니다. 버퍼링, vDSO와 런타임 처리가 중간에 있을 수 있습니다.

## Tiny-RISC로 상태 추적

Tiny-RISC는 `r0`부터 `r7`까지 8개 레지스터, 32비트 순환 정수와 little-endian 메모리를 사용합니다.

```text
li add addi sub and or xor
lw sw
beq bne j
halt
```

자세한 규칙은 [`Tiny-RISC ISA 명세`](../../exercises/processor-model/spec/tiny-risc-isa.md)에 있습니다.

```sh
cd exercises/processor-model
python3 processor-model.py isa fixtures/programs/sum.asm --max-steps 100
```

결과에서 다음을 확인합니다.

- `r0`은 쓰기를 시도해도 0입니다.
- 반복문의 분기가 PC를 이전 명령으로 되돌립니다.
- `sw`와 `lw`가 같은 32비트 값을 공유합니다.
- 동적으로 실행한 명령 수는 소스 줄 수와 다릅니다.

## 실제 컴파일러 출력 확인

호스트 컴파일러가 있으면 작은 함수를 어셈블리로 만들 수 있습니다.

```sh
cc -O2 -S example.c -o example.s
```

호스트가 x86-64라면 RISC-V나 MIPS 어셈블리가 나오지 않습니다. 명령 이름을 억지로 대응시키기보다 다음 의미를 확인합니다.

- 적재·저장과 산술 연산의 구분
- 비교와 분기
- 호출 전후 레지스터와 스택 변화
- 반복문의 역방향 분기

## ISA 문서를 읽는 순서

한 명령을 다음 순서로 확인하면 빠진 조건을 줄일 수 있습니다.

1. 피연산자와 결과 폭
2. 소스와 목적지 레지스터
3. 즉시값 조립과 확장
4. 주소 계산과 정렬
5. 예외 조건
6. PC 변경
7. 메모리 순서 또는 원자성 조건
8. 권한 수준 제한

## 직접 확인할 문제

1. 0 레지스터가 있으면 어떤 명령열이 단순해지는지 예를 들어 보세요.
2. 의사 명령 한 줄을 기계어 명령 한 개로 세면 안 되는 이유를 설명해 보세요.
3. 호출자가 보존하는 레지스터와 호출받은 함수가 보존하는 레지스터가 모두 필요한 이유를 설명해 보세요.
4. 같은 ISA의 프로세서가 서로 다른 파이프라인과 캐시를 사용해도 같은 바이너리를 실행할 수 있는 이유를 설명해 보세요.
5. 잘못 정렬된 `lw`의 ISA 예외와 C에서 유효하지 않은 포인터를 사용하는 문제를 구분해 보세요.
