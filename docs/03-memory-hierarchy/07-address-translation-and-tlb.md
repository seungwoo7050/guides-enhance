# 주소 변환과 TLB

프로그램이 사용하는 가상 주소는 캐시와 메모리 제어기가 사용하는 물리 주소와 다를 수 있습니다. 프로세서는 가상 주소를 페이지 번호와 오프셋으로 나누고, 페이지 테이블에서 물리 프레임과 접근 권한을 찾습니다. TLB는 최근 변환 결과를 저장해 페이지 테이블 순회를 줄입니다.

이 문서는 주소 변환 하드웨어와 ISA에 보이는 폴트를 다룹니다. 운영체제가 페이지를 언제 할당·회수·교체하는지, 쓰기 시 복사와 파일 매핑을 어떻게 처리하는지는 별도 주제입니다.

## 학습 목표

- 가상 주소를 VPN과 페이지 오프셋으로 나눕니다.
- TLB, 페이지 테이블과 PTE가 저장하는 값을 구분합니다.
- TLB 실패, 페이지 폴트, 보호 예외와 데이터 캐시 실패를 구분합니다.
- 매핑 변경 뒤 오래된 TLB 항목을 제거해야 하는 이유를 설명합니다.

## 가상 주소와 물리 주소

서로 다른 주소 공간은 같은 가상 주소를 서로 다른 물리 프레임에 연결할 수 있습니다.

```text
address space A: virtual 0x4000 → physical frame 12
address space B: virtual 0x4000 → physical frame 91
```

메모리 접근을 완료하려면 두 질문에 답해야 합니다.

1. 가상 주소가 어느 물리 주소에 대응합니까?
2. 현재 접근 종류와 권한 수준에서 읽기, 쓰기 또는 실행이 허용됩니까?

주소 숫자만 같다고 같은 바이트를 뜻하지 않습니다. 주소 공간 식별자와 페이지 테이블 루트도 변환 입력입니다.

## VPN과 오프셋

페이지 크기가 `2^p`바이트라면 주소 하위 `p`비트가 페이지 오프셋입니다.

```text
virtual address
| virtual page number | page offset |
```

4KiB 페이지의 오프셋은 12비트입니다.

```text
virtual address 0x12345
VPN    = 0x12
offset = 0x345
PFN    = 0x2a
physical address = 0x2a345
```

페이지 크기와 주소 폭을 먼저 정해야 VPN, 오프셋과 페이지 테이블 인덱스를 계산할 수 있습니다.

## 다단계 페이지 테이블

큰 가상 주소 공간의 모든 페이지 항목을 한 배열에 만들면 표 자체가 매우 커집니다. 다단계 페이지 테이블은 VPN 비트를 여러 인덱스로 나누고 필요한 하위 표만 만듭니다.

```text
root table
→ level 1 entry
→ next table
→ level 2 entry
→ ...
→ leaf PTE
```

각 단계는 메모리 접근이 필요할 수 있습니다. 프로세서가 중간 항목을 위한 페이지 순회 캐시를 둘 수도 있지만 단계 수와 내부 캐시 구성은 구현마다 다릅니다.

## PTE

마지막 페이지 테이블 항목에는 다음 정보가 들어갈 수 있습니다.

- 항목의 유효 여부
- 물리 프레임 번호
- 읽기, 쓰기, 실행 권한
- 사용자 또는 관리자 권한
- 접근 여부 비트
- 수정 여부 비트
- 메모리 종류와 캐시 사용 가능 여부
- 큰 페이지 여부

정확한 비트 배치와 누가 비트를 갱신하는지는 ISA마다 다릅니다. PFN을 찾았더라도 권한 검사를 통과해야 메모리 접근을 계속할 수 있습니다.

## TLB

Translation Lookaside Buffer는 최근 `VPN → PFN` 변환과 권한을 저장합니다.

```text
virtual address
→ TLB lookup
   ├─ hit: PFN과 권한 사용
   └─ miss: page-table walk 후 TLB fill
```

TLB 적중과 데이터 캐시 적중은 서로 다른 사건입니다.

```text
TLB hit  + cache miss
TLB miss + cache hit
TLB miss + cache miss
```

첫 번째는 주소 변환은 빨리 끝나지만 데이터가 캐시에 없습니다. 두 번째는 변환을 다시 찾지만 물리 주소가 정해진 뒤 데이터는 캐시에 있을 수 있습니다.

## TLB 실패와 폴트

### TLB 실패

TLB에 항목이 없다는 뜻입니다. 페이지 테이블에 유효한 PTE가 있다면 순회와 항목 추가를 수행한 뒤 원래 접근을 계속할 수 있습니다.

### 페이지 폴트

유효한 매핑을 찾지 못했습니다. ISA는 폴트 원인과 재시작 가능한 상태를 커널에 전달합니다. 커널이 페이지를 할당하거나 저장장치에서 읽을지, 프로세스를 종료할지는 운영체제가 정합니다.

### 보호 예외

매핑은 있지만 요청한 읽기, 쓰기 또는 실행 권한이 없습니다.

따라서 “TLB 실패는 페이지 폴트입니다” 또는 “페이지 폴트는 항상 디스크 I/O입니다”라는 설명은 맞지 않습니다.

## ASID와 PCID

TLB 항목에 주소 공간 식별자를 붙이면 서로 다른 주소 공간의 같은 VPN을 구분할 수 있습니다.

```text
(ASID A, VPN 0x4) → PFN 12
(ASID B, VPN 0x4) → PFN 91
```

식별자가 없으면 문맥 전환 때 이전 항목을 넓게 비워야 할 수 있습니다. 식별자가 있어도 재사용, 권한 변경과 전역 매핑에는 무효화 규칙이 필요합니다.

## 매핑 변경과 무효화

페이지 테이블의 PFN 또는 권한을 바꿔도 TLB에 이전 항목이 남아 있으면 프로세서는 오래된 변환을 계속 사용할 수 있습니다.

```text
PTE 변경
→ ISA가 요구하는 memory ordering 적용
→ 관련 TLB entry 무효화
→ 새 변환 사용
```

쓰기 권한을 제거했는데 쓰기 가능한 TLB 항목이 남거나, 해제한 프레임을 가리키는 항목이 남으면 프로세스 격리가 깨질 수 있습니다. 무효화는 단순한 성능 최적화가 아닙니다.

여러 코어가 같은 주소 공간을 실행한다면 다른 코어의 TLB도 제거해야 할 수 있습니다. 하드웨어는 필요한 명령과 순서 규칙을 제공하고, 커널은 어느 코어에 어떤 범위의 무효화 요청을 보낼지 결정합니다.

## 큰 페이지와 TLB가 덮는 범위

```text
TLB coverage = entry count × page size
```

64개 항목을 가진 TLB가 4KiB 페이지를 저장하면 256KiB를, 2MiB 페이지를 저장하면 128MiB를 덮습니다. 큰 페이지는 TLB 실패를 줄일 수 있지만 물리 메모리 배치, 단편화와 쓰기 시 복사 비용에 영향을 줍니다.

## 캐시 조회와 주소 변환 겹치기

가장 단순한 순서는 다음과 같습니다.

```text
virtual address → translation → physical address → cache lookup
```

L1 지연 시간을 줄이기 위해 페이지 오프셋으로 세트를 먼저 고르고 TLB가 반환한 물리 태그와 캐시 태그를 함께 비교할 수 있습니다. 캐시 인덱스 비트가 페이지 오프셋 범위를 넘으면 가상 주소 별칭 처리가 복잡해집니다.

실제 캐시의 세트 수, way 수와 페이지 크기로 인덱스 범위를 계산해야 합니다.

## 운영체제와의 구분

이 문서에서는 다음 운영체제 작업의 결과만 입력으로 받습니다.

- 주소 공간 영역 생성과 해제
- 폴트가 발생했을 때 물리 프레임 할당
- 파일 기반 페이지 I/O
- 쓰기 시 복사 처리
- 메모리 부족 상황에서 페이지 회수
- 스왑과 페이지 교체

`processor-model`의 `MAP`과 `UNMAP`은 이런 결정을 내리지 않습니다. 이미 정해진 매핑 변경을 입력으로 받아 TLB 항목이 올바르게 제거되는지만 확인합니다.

## 코드로 확인하기

```sh
cd exercises/processor-model
python3 processor-model.py vm fixtures/vm/config.json fixtures/vm/trace.txt
python3 -m unittest tests.test_processor_model.VirtualMemoryTests -v
```

추적 입력은 다음 상황을 포함합니다.

- 같은 VPN의 TLB 적중
- 매핑 변경 후 무효화
- 실행 권한 부족
- 존재하지 않는 페이지
- `UNMAP` 뒤 이전 주소 접근

## 주소 변환 문제를 푸는 순서

1. 가상 주소 폭과 페이지 크기를 적습니다.
2. 오프셋 비트 수와 VPN을 계산합니다.
3. VPN을 페이지 테이블 단계별 인덱스로 나눕니다.
4. ASID와 TLB 적중 여부를 확인합니다.
5. 실패라면 페이지 테이블 순회와 마지막 PTE를 찾습니다.
6. 접근 종류와 권한을 비교합니다.
7. PFN과 오프셋으로 물리 주소를 만듭니다.
8. 매핑 변경 뒤 필요한 무효화 범위를 확인합니다.
9. 그 뒤 데이터 또는 명령 캐시 접근을 별도로 판단합니다.

2. TLB 적중인데도 보호 예외가 발생할 수 있는 이유를 설명해 보세요.

4. 64개 항목을 가진 TLB에서 4KiB와 2MiB 페이지가 덮는 범위를 계산해 보세요.
5. TLB 실패, 페이지 테이블 순회와 요구 페이징을 서로 다른 작업으로 설명해 보세요.
