# 캐시, 지역성과 AMAT

프로세서가 적재나 저장 명령을 실행할 때마다 DRAM을 기다리면 실행 장치가 대부분 멈춥니다. 캐시는 최근 또는 가까운 주소에서 다시 사용할 가능성이 높은 메모리 블록을 작고 빠른 저장소에 보관합니다. 캐시는 변수 단위가 아니라 캐시 라인 단위로 데이터를 옮기고, 제한된 세트 안에서 교체 대상을 고릅니다.

## 학습 목표

- 캐시 주소를 태그, 세트 인덱스와 블록 오프셋으로 나눕니다.
- 직접 사상, 세트 연관과 완전 연관 캐시를 구분합니다.
- 교체, `write-back`과 쓰기 할당 상태를 추적합니다.
- 최초 접근, 충돌과 용량 실패를 구분합니다.
- 지역성과 AMAT를 실제 실행 시간과 연결하되 같은 값으로 취급하지 않습니다.

## 메모리 계층

대표적인 저장 위치는 다음과 같습니다.

```text
register
↓
L1 cache
↓
L2 cache
↓
shared last-level cache
↓
DRAM
↓
storage
```

위쪽은 작고 빠르며 비트당 비용이 높습니다. 아래쪽은 크고 느립니다. 실제 단계 수, 공유 범위와 지연 시간은 프로세서마다 다릅니다.

같은 적재 명령도 L1 적중, 하위 캐시 실패, TLB 실패 또는 원격 NUMA 메모리 여부에 따라 실행 시간이 달라질 수 있습니다.

## 지역성

### 시간 지역성

최근에 접근한 데이터를 가까운 시점에 다시 접근할 가능성입니다.

- 반복문 계수기
- 스택 프레임
- 자주 호출되는 코드
- 반복 조회하는 표 항목

### 공간 지역성

한 주소에 접근한 뒤 가까운 주소도 접근할 가능성입니다.

- 배열 순차 탐색
- 명령열
- 인접한 구조체 멤버

지역성은 보장이 아닙니다. 큰 연결 자료구조를 무작위로 따라가거나 작업 집합이 캐시보다 크면 효과가 작을 수 있습니다.

## 캐시 라인

캐시는 라인 단위로 데이터를 가져옵니다. 라인 크기가 64바이트라면 주소 `0x1000`을 읽을 때 주변 범위가 함께 들어올 수 있습니다.

```text
[0x1000, 0x103f]
```

라인이 크면 공간 지역성을 더 활용할 수 있지만 다음 비용도 생깁니다.

- 사용하지 않는 바이트 전송
- 같은 캐시 용량에서 라인 수 감소
- 거짓 공유 범위 증가
- 메모리 대역폭 사용 증가

## 주소 분해

32KiB 캐시, 64바이트 라인, 8-way 세트 연관도를 예로 들겠습니다.

```text
line 수 = 32768 / 64 = 512
set 수  = 512 / 8 = 64
```

세트 수와 라인 크기가 2의 거듭제곱이라면 주소를 다음처럼 나눌 수 있습니다.

```text
| tag | set index 6bit | block offset 6bit |
```

- 오프셋은 라인 안의 바이트 위치입니다.
- 세트 인덱스는 확인할 세트를 고릅니다.
- 태그는 해당 way에 어떤 메모리 블록이 들어 있는지 구분합니다.

## 매핑과 연관도

### 직접 사상

세트마다 라인 하나만 있습니다. 조회가 단순하지만 같은 세트로 매핑되는 블록이 서로를 계속 밀어낼 수 있습니다.

### 세트 연관

세트마다 여러 way를 둡니다. 4-way라면 같은 세트 안에서 네 블록까지 보관할 수 있습니다.

### 완전 연관

어느 블록이든 모든 라인에 들어갈 수 있습니다. 충돌 실패는 줄지만 많은 태그를 비교하고 교체 상태를 관리해야 합니다.

연관도를 높이면 항상 빨라지는 것은 아닙니다. 적중 지연 시간, 면적과 전력 사용이 늘 수 있습니다.

## 적중과 실패 처리

읽기 적중에서는 태그와 유효 비트를 확인하고 오프셋으로 데이터를 고릅니다.

읽기 실패에서는 다음 작업이 필요할 수 있습니다.

1. 교체할 way를 고릅니다.
2. 교체 대상이 수정된 상태라면 하위 단계에 씁니다.
3. 요청 블록을 하위 단계에서 가져옵니다.
4. 태그, 유효·수정 비트와 교체 상태를 갱신합니다.
5. 요청한 데이터를 반환합니다.

실제 프로세서가 여러 실패를 동시에 추적하는지, 같은 세트의 요청을 잠시 막는지는 마이크로아키텍처에 따라 다릅니다.

## 교체

대표적인 교체 방법은 다음과 같습니다.

- LRU 또는 LRU 근사
- 유사 LRU
- FIFO
- 무작위
- 재참조 가능성을 예측하는 방식

높은 연관도에서 정확한 LRU 순서를 유지하는 비용은 큽니다. `processor-model`은 이해하기 쉬운 정확한 LRU를 사용하지만 실제 CPU가 같은 방법을 사용한다는 뜻은 아닙니다.

## 쓰기 방식

### `write-through`와 `write-back`

- `write-through`는 캐시 쓰기를 하위 단계에도 바로 전달합니다.
- `write-back`은 라인을 수정된 상태로 표시하고 교체할 때 하위 단계에 반영합니다.

`write-back`은 같은 라인에 대한 여러 쓰기를 합칠 수 있지만 수정된 라인 교체와 일관성 처리가 필요합니다.

### 쓰기 할당과 비할당

쓰기 실패에서 라인을 캐시에 넣을지 정합니다.

- 쓰기 할당은 라인을 가져온 뒤 캐시에 씁니다.
- 쓰기 비할당은 캐시에 넣지 않고 하위 단계로 전달합니다.

`write-back`과 쓰기 할당 조합이 흔하지만 반드시 그렇게 구성되는 것은 아닙니다.

## 3C 실패 분류

### 최초 접근 실패

처음 접근한 블록이므로 아직 캐시에 없습니다.

### 충돌 실패

전체 라인 수는 충분하지만 세트 매핑 때문에 밀려났습니다. 같은 라인 수의 완전 연관 캐시라면 적중했을 접근입니다.

### 용량 실패

완전 연관 캐시를 사용해도 작업 집합이 전체 라인 수를 넘어서 밀려납니다.

캐시 일관성 무효화와 미리 가져오기의 영향은 전통적인 3C 분류에 모두 들어맞지 않습니다. 그래도 데이터 배치 문제를 분석하는 첫 기준으로 사용할 수 있습니다.

```sh
cd exercises/processor-model
python3 processor-model.py cache fixtures/traces/cache.trace \
  --size 16 --block 4 --ways 1
```

세 분류의 합이 전체 실패 수와 같은지 확인합니다.

## AMAT

단일 캐시 수준의 첫 근사는 다음과 같습니다.

```text
AMAT = hit time + miss rate × miss penalty
```

다단계 캐시에서는 다음처럼 중첩할 수 있습니다.

```text
AMAT = L1 hit time
     + L1 miss rate × (L2 hit time + L2 local miss rate × memory penalty)
```

각 실패율의 분모를 확인해야 합니다. L2에 도달한 접근 가운데 실패한 비율과 전체 접근 대비 L2 실패율은 같은 값이 아닙니다.

비순차 코어는 여러 실패의 대기를 겹칠 수 있습니다. 메모리 대역폭이 포화되면 독립적인 실패도 서로 기다립니다. 따라서 AMAT만으로 응용 프로그램의 정지 시간을 정확히 계산할 수는 없습니다.

## 반복문 순서와 지역성

C의 행 우선 2차원 배열을 다음과 같이 읽으면 안쪽 반복문이 연속 주소를 사용합니다.

```c
for (row = 0; row < rows; ++row)
    for (column = 0; column < columns; ++column)
        sum += matrix[row * columns + column];
```

반복문을 뒤집으면 접근 간격이 `columns * element_size`가 됩니다.

```sh
make -C examples/layout-benchmark check
make -C examples/layout-benchmark benchmark
```

두 검사 합계는 같아야 합니다. 시간 비율은 CPU와 입력에 따라 달라지므로 고정 정답으로 사용하지 않습니다.

## 블로킹

행렬 곱셈처럼 같은 데이터를 여러 번 사용하는 작업은 전체 행과 열을 한 번에 처리하기보다 캐시에 들어갈 크기의 타일로 나눌 수 있습니다.

```text
큰 작업
→ 캐시에 들어갈 타일
→ 타일 안에서 반복 사용
→ 다음 타일
```

점근 복잡도 `O(n^3)`이 같아도 메모리 이동량은 달라질 수 있습니다. 타일 크기는 여러 입력·출력 타일, 연관도, 벡터 폭과 반복문 부가 비용을 함께 고려해야 합니다.

## 미리 가져오기

하드웨어 미리 가져오기 장치는 순차 또는 일정한 보폭을 발견해 다음 라인을 먼저 요청할 수 있습니다. 너무 늦으면 지연 시간을 숨기지 못하고, 너무 빠르면 아직 필요한 라인을 밀어내거나 대역폭을 사용합니다.

순차 접근이 빠른 이유를 캐시 적중만으로 단정하지 말고 미리 가져오기의 영향도 고려해야 합니다.

## 데이터 배치

구조체 배열(AoS)은 객체별 필드를 모읍니다.

```text
{x0,y0,z0} {x1,y1,z1} {x2,y2,z2}
```

배열 구조체(SoA)는 필드별로 모읍니다.

```text
x0 x1 x2 ...
y0 y1 y2 ...
z0 z1 z2 ...
```

한 필드만 대량 처리하면 SoA가 캐시 라인 사용과 SIMD 적재에 유리할 수 있습니다. 객체 전체를 함께 사용하면 AoS가 더 단순할 수 있습니다. 배치 변경은 ABI, 직렬화와 갱신 방식도 바꿉니다.
