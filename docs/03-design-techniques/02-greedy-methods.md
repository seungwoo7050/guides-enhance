# 그리디 설계

## 학습 목표

- 각 단계에서 어떤 후보 집합을 대상으로 어떤 기준으로 선택하는지 명확히 적습니다.
- 한 번 선택한 뒤 다음 단계 판단에 필요한 상태가 무엇인지 설명합니다.
- 교환 논리나 문제의 구조적 성질을 사용해 선택의 안전성, 즉 그 선택을 포함하는 최적해가 존재함을 설명합니다.
- 잘못된 greedy 규칙이 실패하는 작은 반례를 만들 수 있습니다.
- 동점 처리 방식이 최적값, 실제 반환 해, 테스트 재현성에 어떤 영향을 주는지 구분합니다.

## 선행지식

최적화 문제의 입력·반환 조건, 최소 반례, [정확성 설명](../01-foundations/04-correctness-and-invariants.md)을 작성할 수 있어야 합니다.

특히 다음 두 개념을 구분할 수 있어야 합니다.

- **실행 가능한 해(feasible solution)**: 문제의 모든 제약을 만족하는 해입니다.
- **최적해(optimal solution)**: 실행 가능한 해 중 목적 함수 값을 가장 좋게 만드는 해입니다.

최댓값 문제에서는 목적 함수 값이 가장 큰 해, 최솟값 문제에서는 가장 작은 해가 최적해입니다.

## 핵심 관점

Greedy 알고리즘은 각 단계에서 현재 기준으로 가장 유리하다고 정한 선택 하나를 확정하고, 일반적으로 그 선택을 나중에 되돌리지 않습니다.

따라서 greedy 설계에는 최소한 다음 세 요소가 필요합니다.

```text
현재 단계에서 선택 가능한 후보 집합
+ 그 후보 중 무엇을 고를지 결정하는 기준
+ 그 선택을 포함하는 최적해가 존재한다는 근거
```

여기서 가장 중요한 것은 마지막 항목입니다. 어떤 선택이 직관적으로 좋아 보이거나 여러 샘플에서 잘 동작한다는 사실만으로는 최적성이 보장되지 않습니다.

Greedy 알고리즘이 맞으려면 보통 다음 형태의 성질을 증명해야 합니다.

```text
현재 greedy 선택 g가 있을 때,
g를 포함하는 최적해가 적어도 하나 존재합니다.
```

이 성질을 **greedy choice property**라고 부를 수 있습니다. 이를 보인 뒤에는 greedy 선택을 확정하고, 남은 문제에 같은 논리를 반복합니다.

## 1. 설계 순서

Greedy 규칙을 떠올린 직후 구현하지 말고 다음 순서로 정리합니다.

1. 입력, 반환값, 목적 함수를 적습니다.
2. 현재 단계에서 선택 가능한 후보 집합을 적습니다.
3. 후보를 어떤 기준으로 비교할지 정합니다.
4. 하나를 선택한 뒤 실행 가능성을 유지하기 위해 어떤 상태가 필요한지 적습니다.
5. 임의의 최적해를 현재 greedy 선택을 포함하도록 바꿀 수 있는지 확인합니다.
6. 선택 뒤 남은 문제가 원래 문제와 같은 구조를 갖는지 확인합니다.
7. 동점인 후보가 여러 개일 때 어떤 순서로 고를지 정합니다.
8. 작은 입력을 완전탐색해 greedy 결과와 비교합니다.

특히 5번이 설명되지 않으면 아직 greedy 알고리즘이 증명된 것이 아닙니다.

## 2. 예제: 최대 구간 선택

반열린 구간 `[start, end)` 중 서로 겹치지 않는 구간을 가장 많이 선택한다고 하겠습니다. 각 구간은 `start < end`를 만족해야 합니다.

반열린 구간을 사용하므로 다음 두 구간은 겹치지 않습니다.

```text
[1, 3), [3, 5)
```

첫 구간은 시각 `3`을 포함하지 않으므로 두 번째 구간이 정확히 `3`에서 시작할 수 있습니다.

### 선택 기준

선택 기준은 **현재 선택 가능한 구간 중 끝나는 시간이 가장 이른 구간**입니다.

구현에서는 전체 구간을 끝 시각 기준으로 정렬한 뒤 한 번 순회할 수 있습니다.

```text
구간을 (end, start) 순서로 정렬합니다.
last_end를 아직 선택한 구간이 없다는 상태로 둡니다.
순서대로 보면서 start >= last_end인 구간을 선택합니다.
선택하면 last_end = end로 갱신합니다.
```

`(end, start)`에서 `start`는 끝 시각이 같은 구간 사이의 결정적 순서를 만들기 위한 동점 규칙입니다. 최대 선택 개수만 구하는 경우에는 끝 시각이 같은 구간 중 어느 것을 먼저 보더라도 최적 개수에는 영향을 주지 않을 수 있지만, 실제 반환 순서와 테스트 재현성에는 영향을 줄 수 있습니다.

### 교환 논리

첫 단계에서 greedy가 고른 구간을 `g`, 어떤 최적해의 첫 구간을 `o`라고 하겠습니다.

`g`는 전체 후보 중 가장 일찍 끝나는 구간이므로 다음이 성립합니다.

```text
g.end <= o.end
```

이제 최적해에서 `o`를 `g`로 바꿉니다.

원래 `o` 뒤에 선택된 모든 구간은 `o.end` 이상에서 시작해야 합니다. 그런데 `g.end <= o.end`이므로 그 구간들은 모두 `g.end` 이상에서도 시작합니다. 따라서 `o`를 `g`로 바꿔도 이후 구간과 충돌하지 않습니다.

즉 다음이 성립합니다.

```text
원래 최적해의 구간 수
= o를 g로 바꾼 해의 구간 수
```

그리고 바꾼 해도 실행 가능합니다. 따라서 `g`를 포함하는 최적해가 존재합니다.

첫 선택을 확정한 뒤에는 `g.end` 이상에서 시작하는 구간만 남습니다. 이 남은 문제도 다시 "서로 겹치지 않는 구간을 최대한 많이 고르기" 문제이므로 같은 논리를 반복할 수 있습니다.

이 증명에서 중요한 부분은 단순히 `g.end`가 작다는 사실이 아니라, **`o`를 `g`로 교체해도 나머지 선택의 실행 가능성이 깨지지 않는다는 점**입니다.

### 잘못된 규칙의 반례

시작 시간이 가장 빠른 구간부터 선택하는 규칙은 일반적으로 최적이 아닙니다.

```text
[(0, 3), (1, 2), (2, 3)]
```

시작 시간 기준은 `(0, 3)`을 먼저 골라 다른 두 구간을 모두 막으므로 1개만 선택합니다.

반면 끝 시간 기준은 다음 두 구간을 선택합니다.

```text
(1, 2), (2, 3)
```

따라서 최적값은 2입니다.

이 반례는 "시작 시간이 빠르다"는 국소 기준이 이후 선택 가능성을 얼마나 남기는지 직접 보장하지 못한다는 점을 보여 줍니다.

## 3. 선택 뒤에 남겨야 할 정보

Greedy 알고리즘은 이미 확정한 모든 선택을 계속 저장할 필요가 없는 경우가 많습니다. 다만 다음 선택의 실행 가능성과 비교 기준을 결정하는 데 필요한 정보는 반드시 남겨야 합니다.

구간 선택에서는 다음 값 하나면 충분합니다.

```text
last_end = 마지막으로 선택한 구간의 끝 시각
```

정렬된 다음 후보 `(start, end)`에 대해 실행 가능성은 다음 조건 하나로 판단됩니다.

```text
start >= last_end
```

이미 선택한 구간의 전체 목록을 다시 검사할 필요가 없는 이유는, 지금까지 선택한 구간들이 서로 겹치지 않고 끝 시각 순으로 선택되었다는 전제 아래 마지막 구간이 가장 늦게 끝나기 때문입니다. 따라서 새 구간이 `last_end` 이후에 시작하면 이전의 모든 구간과도 겹치지 않습니다.

즉 greedy 상태는 단순히 작아야 하는 것이 아니라, **미래의 선택 가능 여부를 결정하기에 충분해야 합니다.**

과거 정보를 버려도 되는 이유를 설명하지 못한다면 상태가 부족할 수 있습니다.

## 4. 교환 논리의 일반 형태

Greedy 증명에서 자주 사용하는 교환 논리는 다음 구조를 가집니다.

```text
1. greedy가 현재 선택한 후보를 g라고 둡니다.
2. 임의의 최적해 O를 하나 잡습니다.
3. O가 이미 g를 포함한다면 그대로 사용합니다.
4. 그렇지 않다면 O의 일부 선택 o를 g로 교체합니다.
5. 교체 뒤에도 모든 제약을 만족함을 보입니다.
6. 교체 뒤 목적 함수 값이 나빠지지 않음을 보입니다.
7. 따라서 g를 포함하는 최적해가 존재합니다.
```

5번과 6번은 별개의 조건입니다.

예를 들어 목적 함수 값이 그대로여도 교체 뒤 제약을 위반하면 올바른 해가 아닙니다. 반대로 실행 가능성은 유지되더라도 목적 함수 값이 악화되면 최적해라고 할 수 없습니다.

교환 논리를 작성할 때는 반드시 다음 두 질문에 답해야 합니다.

```text
교체 뒤에도 실행 가능한가?
교체 뒤 목적 함수 값이 원래 최적값보다 나빠지지 않는가?
```

## 5. MST의 greedy 선택

최소 신장 트리(MST, Minimum Spanning Tree)는 연결된 무방향 가중치 그래프에서 모든 정점을 연결하면서 전체 간선 가중치 합이 최소인 spanning tree입니다.

Kruskal과 Prim은 모두 greedy 알고리즘이지만, "그래프에서 항상 가장 가벼운 간선을 고른다"고 설명하면 부정확합니다. 실제 후보 집합에 제약이 있습니다.

### Kruskal

Kruskal은 간선을 가중치 오름차순으로 보면서 **현재 서로 다른 connected component를 잇는 간선**만 선택합니다.

```text
가벼운 간선부터 확인합니다.
두 끝점이 이미 같은 component에 있으면 건너뜁니다.
서로 다른 component에 있으면 선택하고 두 component를 합칩니다.
```

같은 component 안의 두 정점을 연결하면 이미 존재하는 경로와 새 간선이 cycle을 만들기 때문에 spanning tree의 조건을 깨뜨립니다.

따라서 Kruskal의 후보 집합은 단순히 "아직 보지 않은 간선"이 아니라 다음과 같습니다.

```text
현재 forest에서 서로 다른 component를 연결할 수 있는 간선
```

### Prim

Prim은 하나의 정점에서 시작해 현재 선택된 정점 집합을 하나의 tree로 확장합니다.

각 단계의 후보는 다음 cut을 가로지르는 간선입니다.

```text
선택된 정점 집합 S
선택되지 않은 정점 집합 V - S
```

Prim은 이 두 집합 사이를 잇는 간선 중 가장 가벼운 간선을 선택합니다.

### cut property

두 알고리즘의 안전성을 설명하는 핵심 도구는 **cut property**입니다.

그래프의 정점 집합을 두 부분으로 나누는 것을 cut이라고 합니다. 어떤 MST에 이미 포함시키기로 한 간선들이 이 cut을 가로지르지 않는 상황에서, 그 cut을 가로지르는 최소 가중치 간선 중 하나는 어떤 MST에 안전하게 포함시킬 수 있습니다.

직관적인 교환 형태는 다음과 같습니다.

```text
greedy가 cut을 가로지르는 최소 간선 e를 선택합니다.
어떤 MST T가 e를 포함하지 않는다고 가정합니다.
T에 e를 추가하면 cycle이 하나 생깁니다.
그 cycle에는 같은 cut을 가로지르는 다른 간선 f가 존재합니다.
e의 가중치는 f보다 크지 않습니다.
f를 제거하고 e를 넣어도 spanning tree이며 총가중치는 증가하지 않습니다.
```

따라서 `e`를 포함하는 MST가 존재합니다.

가중치가 작다는 사실만으로는 충분하지 않고, **현재 안전한 cut을 가로지르는 후보 중 최소인가**가 중요합니다.

## 6. Huffman coding

Huffman coding은 symbol 빈도 또는 가중치가 주어졌을 때 가중 평균 코드 길이가 최소인 binary prefix code를 구성하는 greedy 알고리즘입니다.

매 단계에서 현재 남아 있는 symbol tree 중 빈도가 가장 낮은 두 개를 고르고 하나의 부모 아래에 합칩니다.

```text
가장 낮은 빈도 a, b를 선택합니다.
a와 b를 두 자식으로 갖는 새 tree를 만듭니다.
새 tree의 빈도는 a + b입니다.
이를 후보 집합에 다시 넣습니다.
```

여기서 단순히 "작은 수부터 더하면 전체 합이 작다"고 말하는 것만으로는 충분하지 않습니다. Huffman 문제의 목적은 덧셈 횟수 자체가 아니라 각 symbol의 빈도와 코드 깊이가 만드는 weighted path length를 최소화하는 것입니다.

증명의 핵심은 다음 구조입니다.

```text
가장 낮은 두 빈도 symbol을 가장 깊은 sibling leaf로 둘 수 있는 최적 prefix tree가 존재합니다.
```

이 두 leaf를 하나의 가상 symbol로 합치면 문제 크기가 하나 줄어든 동일한 형태의 문제가 됩니다. 축소된 문제의 최적해에 두 leaf를 다시 펼치면 원래 문제의 최적해를 얻을 수 있습니다.

즉 Huffman의 greedy 선택도 "빈도가 작아 보인다"가 아니라, 그 두 symbol을 함께 가장 깊게 배치하는 최적해가 존재한다는 구조적 근거를 필요로 합니다.

## 7. greedy가 실패할 가능성이 큰 경우

다음 특징이 보이면 greedy 규칙을 바로 믿지 말고 반례를 먼저 찾아야 합니다.

- 현재 선택이 이후 가능한 후보 집합을 복잡하게 바꿉니다.
- 지금의 손해를 이후 선택이 보상할 수 있습니다.
- 다른 최적해의 일부를 현재 선택으로 교환하면 제약이 깨집니다.
- 같은 미래 상태에 도달했더라도 지금까지 얻은 가치가 달라 이후 최적 결과가 달라질 수 있습니다.
- 국소적으로 가장 좋은 첫 선택보다 다른 첫 선택이 전체 결과를 더 좋게 만드는 작은 예가 존재합니다.

### 예: 0/1 knapsack

0/1 knapsack에서는 각 물건을 통째로 선택하거나 전혀 선택하지 않아야 합니다.

따라서 가치/무게 비율이 큰 물건부터 선택하는 규칙은 일반적으로 최적이 아닙니다.

예를 들어 capacity가 `50`이고 물건이 다음과 같다고 하겠습니다.

```text
(weight, value)
(10, 60)   ratio = 6
(20, 100)  ratio = 5
(30, 120)  ratio = 4
```

비율 기준 greedy는 `(10, 60)`과 `(20, 100)`을 선택해 가치 `160`을 얻습니다. 남은 capacity가 `20`이라 세 번째 물건은 넣지 못합니다.

하지만 두 번째와 세 번째 물건을 선택하면 무게는 정확히 `50`, 가치는 `220`입니다.

```text
greedy 결과 = 160
최적 결과 = 220
```

반면 물건을 일부만 잘라 선택할 수 있는 **fractional knapsack**에서는 가치/무게 비율 순 greedy가 최적입니다. 실패 여부는 선택 규칙만이 아니라 문제의 제약에 달려 있습니다.

## 8. 동점 처리

Greedy 기준에서 여러 후보가 같은 우선순위를 가질 수 있습니다.

예를 들어 구간 선택에서 끝 시각이 같은 두 구간이 있을 수 있고, Kruskal에서는 같은 가중치의 여러 간선이 있을 수 있습니다.

동점 규칙은 다음 이유로 명시하는 것이 좋습니다.

- 같은 입력에 대해 같은 실제 해를 반환합니다.
- hash table이나 container의 순회 순서에 따라 결과가 달라지는 일을 줄입니다.
- 테스트의 재현성을 높입니다.
- "최적해 중 사전순 최소" 같은 추가 반환 조건을 구현할 수 있습니다.
- 이후 알고리즘 단계가 항상 같은 순서의 입력을 받게 할 수 있습니다.

다만 동점 처리가 어떤 역할을 하는지는 문제마다 구분해야 합니다.

### 최적값에 영향을 주지 않는 동점

최대 구간 선택에서 끝 시각이 같은 후보 중 어느 것을 택하더라도 이후 선택이 시작할 수 있는 가장 이른 시점은 동일합니다. 이런 경우 동점 규칙은 최적 개수보다 반환 결과의 결정성에 더 큰 영향을 줍니다.

### 최적값은 같지만 실제 해가 달라지는 동점

MST에서는 같은 가중치의 간선이 여러 개 있으면 서로 다른 MST가 존재할 수 있습니다. 총가중치는 같아도 선택된 간선 집합은 달라질 수 있습니다.

따라서 테스트가 특정 간선 집합을 요구하지 않는다면 "어떤 MST라도 허용"하도록 검증해야 합니다. 반대로 반환 순서를 명세했다면 구현과 테스트가 동일한 tie-break 규칙을 사용해야 합니다.

## 9. greedy 결과를 검증합니다

Greedy 알고리즘은 작은 입력에서 완전탐색 기준 계산과 비교하기 좋습니다.

검증은 두 부분으로 나눕니다.

```text
1. 반환한 해가 실제로 모든 제약을 만족하는가?
2. 그 실행 가능한 해의 목적 함수 값이 최적인가?
```

두 검사는 서로 대체할 수 없습니다.

### 구간 선택

반환한 구간에 대해 다음을 확인할 수 있습니다.

```text
모든 구간이 원본 입력에 존재합니까?
반환 구간끼리 서로 겹치지 않습니까?
반환 개수가 모든 가능한 실행 가능한 부분집합의 최대 개수와 같습니까?
```

### MST

총가중치만 최솟값과 같다고 해서 반환 결과가 올바른 spanning tree라고 단정할 수는 없습니다.

다음을 각각 확인합니다.

- 선택한 간선 수가 `V-1`입니까?
- 모든 선택 간선이 원본 그래프에 존재합니까?
- 모든 정점을 연결합니까?
- cycle이 없습니까?
- 반환한 총가중치가 실제 선택 간선의 가중치 합과 같습니까?
- 그 총가중치가 가능한 모든 spanning tree 중 최소입니까?

작은 입력에서는 모든 후보 해를 열거한 기준 계산이 greedy 구현의 오류를 찾는 데 특히 유용합니다.

## 10. 반례를 만드는 방법

잘못된 greedy 규칙을 검증할 때는 무작위 테스트만 기다리지 말고 규칙이 무엇을 희생하는지 의도적으로 찾습니다.

예를 들어 다음과 같이 접근할 수 있습니다.

```text
greedy가 첫 단계에서 반드시 고를 후보 g를 만듭니다.
g를 고르면 이후 좋은 후보 여러 개가 막히게 만듭니다.
g 대신 다른 후보 o를 고르면 더 많은 선택 또는 더 좋은 목적값을 얻도록 만듭니다.
```

구간 선택의 시작 시각 기준 반례가 정확히 이 구조입니다.

최소 반례가 유용한 이유는 실패 원인이 적은 요소만으로 드러나기 때문입니다. 입력이 너무 크면 어떤 조건 때문에 실패했는지 설명하기 어렵습니다.

## 연결 구현

[`verified-algorithms`](../../exercises/verified-algorithms/)에서 다음을 확인합니다.

- `[Implementation 5]` `select_intervals`가 `(end, start)` 순서로 정렬합니다.
- 반환한 구간들이 서로 겹치지 않는지 검사합니다.
- 반환한 구간 수를 모든 부분집합에서 구한 최댓값과 비교합니다.
- `[Implementation 9]` `kruskal_mst`가 DSU로 현재 component를 추적하고 cycle을 막습니다.
- 반환한 MST가 실제 spanning tree인지 검사합니다.
- MST의 총가중치를 모든 spanning tree 조합의 최솟값과 비교합니다.

완전탐색 기준 계산은 greedy 구현과 같은 핵심 로직을 공유하지 않아야 합니다. 그렇지 않으면 동일한 버그가 두 구현에 함께 들어가 비교 테스트가 통과할 수 있습니다.

## 완료 기준

- 각 단계의 후보 집합과 선택 기준을 한 문장으로 설명합니다.
- 선택 뒤 다음 판단에 필요한 상태와, 그 정보만으로 충분한 이유를 설명합니다.
- 임의의 최적해를 현재 greedy 선택을 포함하는 최적해로 바꾸는 교환 단계를 적습니다.
- 교환 뒤에도 실행 가능성이 유지되고 목적 함수 값이 나빠지지 않음을 각각 확인합니다.
- 잘못된 greedy 규칙을 깨는 작은 반례를 만듭니다.
- 동점 처리와 반환 순서를 구현과 테스트에 일관되게 적용합니다.
- 최적값뿐 아니라 반환한 실제 해가 문제의 제약을 만족하는지 확인합니다.

## 실패 신호

- 샘플에서 맞는다는 이유만으로 greedy를 선택합니다.
- "가장 작은 값" 또는 "가장 좋은 값"이 어느 후보 집합에서의 최소·최대인지 불명확합니다.
- 교환 뒤에도 실행 가능한 해인지 확인하지 않습니다.
- 교환 뒤 목적 함수 값이 나빠지지 않는다는 설명이 없습니다.
- Kruskal에서 cycle, Prim에서 cut과 같은 현재 선택의 제약을 빠뜨립니다.
- 0/1 knapsack과 fractional knapsack처럼 제약이 다른 문제를 같은 greedy 규칙으로 취급합니다.
- 동점 처리 방식이 구현과 테스트에서 다릅니다.
- 최적값만 비교하고 반환한 실제 해의 유효성을 검사하지 않습니다.
