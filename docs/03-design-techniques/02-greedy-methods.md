# 그리디 설계

## 학습 목표

- 각 단계의 선택 기준과 선택 뒤 남는 정보를 명확히 적습니다.
- 교환 논리나 문제의 성질로 최적성을 설명합니다.
- 잘못된 greedy 규칙이 실패하는 최소 반례를 만듭니다.
- 동점 처리 방식이 반환 결과와 테스트 재현성에 미치는 영향을 설명합니다.

## 선행지식

최적화 문제의 입력·반환 조건, 최소 반례, [정확성 설명](../01-foundations/04-correctness-and-invariants.md)을 작성할 수 있어야 합니다.

## 핵심 관점

Greedy 알고리즘은 각 단계에서 하나의 선택을 확정하고 다시 바꾸지 않습니다.

```text
선택 기준
+ 선택 뒤 남는 문제
+ 이 선택을 포함하는 최적해가 존재한다는 근거
```

국소적으로 좋아 보인다는 이유만으로는 충분하지 않습니다.

## 1. 설계 순서

1. 입력, 반환값, 최적화하려는 값을 적습니다.
2. 후보를 어떤 순서로 볼지 정합니다.
3. 한 번 선택했을 때 이후 선택에 남는 제약을 적습니다.
4. 이 선택을 포함하는 최적해가 항상 존재하는지 설명합니다.
5. 선택 뒤의 문제가 원래 문제와 같은 형태인지 확인합니다.

## 2. 예제: 최대 구간 선택

반열린 구간 `[start, end)` 중 서로 겹치지 않는 구간을 가장 많이 선택합니다. 각 구간은 `start < end`를 만족해야 합니다.

선택 기준은 끝나는 시간이 가장 이른 구간입니다.

```text
구간을 (end, start) 순서로 정렬합니다.
last_end를 아직 선택한 구간이 없다는 값으로 둡니다.
순서대로 보면서 start >= last_end인 구간을 선택합니다.
```

### 교환 논리

임의의 최적해에서 첫 구간을 `o`, greedy가 고른 첫 구간을 `g`라고 하겠습니다.

```text
g.end <= o.end
```

`o`를 `g`로 바꿔도 이후 구간이 시작할 수 있는 시점은 늦어지지 않습니다. 따라서 `g`를 포함하면서 구간 개수가 같은 최적해가 존재합니다. 첫 선택 뒤 남은 구간에도 같은 논리를 적용할 수 있습니다.

반대로 시작 시간이 가장 빠른 구간부터 고르면 긴 구간 하나가 많은 짧은 구간을 막을 수 있습니다.

```text
[(0, 3), (1, 2), (2, 3)]
```

시작 시간 기준은 `(0, 3)` 하나만 고르지만, 끝 시간 기준은 `(1, 2)`, `(2, 3)` 두 개를 고릅니다.

## 3. 선택 뒤에 남겨야 할 정보

구간 선택에서는 마지막으로 고른 구간의 끝 시각만 있으면 다음 구간을 고를 수 있습니다. 이미 선택한 전체 목록은 다음 선택의 가능 여부를 판단하는 데 필요하지 않습니다.

과거 정보를 버려도 되는 이유를 설명하지 못한다면 greedy 상태가 충분하지 않을 수 있습니다.

## 4. MST의 greedy 선택

Kruskal과 Prim은 단순히 가장 가벼운 간선을 고르는 알고리즘이 아닙니다.

- Kruskal: 현재 서로 다른 component를 잇는 간선 중 가장 가벼운 간선을 고릅니다.
- Prim: 현재 tree와 바깥 정점을 가르는 cut의 간선 중 가장 가벼운 간선을 고릅니다.

두 알고리즘 모두 cut property로 선택의 안전성을 설명합니다. 가중치가 작더라도 cycle을 만드는 간선은 선택하지 않습니다.

## 5. Huffman coding

빈도가 가장 낮은 두 symbol tree를 합치는 작업을 반복합니다. 최적 prefix code 중에서 가장 낮은 두 빈도를 sibling leaf로 둘 수 있다는 교환 근거가 필요합니다.

“작은 수부터 더하면 합이 작습니다”라는 직관만으로는 prefix code의 최적성을 충분히 설명하지 못합니다.

## 6. greedy가 실패할 가능성이 큰 경우

- 현재 선택이 이후 가능한 후보를 복잡하게 바꿉니다.
- 지금의 손해를 이후 선택이 보상할 수 있습니다.
- 다른 최적해의 일부를 현재 선택으로 바꿀 때 제약을 위반합니다.
- 같은 상태에 도달한 과거 경로의 가치가 서로 다릅니다.
- 작은 반례에서 다른 첫 선택이 더 좋은 결과를 만듭니다.

0/1 knapsack에서 가치/무게 비율이 큰 물건부터 고르는 방법은 일반적으로 최적이 아닙니다. 물건을 나눌 수 있는 fractional knapsack과 조건이 다릅니다.

## 7. 동점 처리

동점 규칙은 다음 이유로 필요합니다.

- 같은 입력에서 같은 결과를 반환합니다.
- 테스트가 실행 순서나 container 순서에 따라 흔들리지 않습니다.
- 추가로 요구된 사전순 최소 같은 조건을 지킵니다.
- 이후 단계가 같은 순서의 입력을 받습니다.

동점이 최적값에는 영향을 주지 않아도 반환하는 실제 해에는 영향을 줄 수 있습니다.

## 8. greedy 결과를 검증합니다

작은 입력에서는 가능한 답을 모두 열거해 최적값과 비교합니다. 반환값이 실제로 제약을 만족하는지도 따로 검사합니다.

예를 들어 MST는 총가중치만 맞는다고 끝나지 않습니다.

- 선택한 간선 수가 `V-1`입니까?
- 모두 원본에 있는 간선입니까?
- 모든 정점을 연결합니까?
- cycle이 없습니까?
- 반환한 총가중치가 간선 합과 같습니까?

## 연결 구현

[`verified-algorithms`](../../exercises/verified-algorithms/)에서 다음을 확인합니다.

- `[Implementation 5]` `select_intervals`가 `(end, start)` 순서로 정렬합니다.
- 반환한 구간 수를 모든 부분집합에서 구한 최댓값과 비교합니다.
- `[Implementation 9]` `kruskal_mst`가 DSU로 cycle을 막습니다.
- MST의 총가중치를 모든 spanning tree 조합의 최솟값과 비교합니다.

## 완료 기준

- 선택 기준과 선택 뒤 남는 값을 한 문장으로 설명합니다.
- 임의의 최적해를 현재 선택을 포함하는 최적해로 바꾸는 단계를 적습니다.
- 잘못된 greedy 규칙을 깨는 최소 반례를 만듭니다.
- 동점 처리와 반환 순서를 구현과 테스트에 동일하게 적용합니다.
- 최적값뿐 아니라 반환한 실제 해가 제약을 만족하는지 확인합니다.

## 실패 신호

- 샘플에서 맞는다는 이유로 greedy를 선택합니다.
- 교환 뒤에도 실행 가능한 답인지 확인하지 않습니다.
- “가장 작은 값”이 어느 후보 집합에서의 최소인지 불명확합니다.
- cycle, capacity 같은 제약을 선택 기준에서 빠뜨립니다.
- 동점 처리 방식이 구현과 테스트에서 다릅니다.
