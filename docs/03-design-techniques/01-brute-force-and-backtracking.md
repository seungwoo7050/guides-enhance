# 완전탐색과 백트래킹

## 학습 목표

- 가능한 답 전체를 어떤 상태와 선택 순서로 생성할지 정합니다.
- 같은 결과를 중복해서 만들지 않는 방법을 설계합니다.
- pruning이 정답 후보를 제거하지 않는 이유를 설명합니다.
- 작은 입력의 기준 계산과 실제 제출용 구현의 역할을 구분합니다.

## 선행지식

문제의 입력·출력 조건, 재귀 함수의 종료 조건, [정확성 설명](../01-foundations/04-correctness-and-invariants.md)을 작성할 수 있어야 합니다.

## 핵심 관점

완전탐색은 단순히 느린 풀이가 아닙니다. 가능한 답의 범위를 정확히 정의하는 방법입니다.

```text
현재 상태: 지금까지 어떤 선택을 했습니까?
다음 선택: 아직 결정하지 않은 항목에서 무엇을 고를 수 있습니까?
종료: 언제 완성된 후보가 됩니까?
검사: 후보가 입력 조건을 만족합니까?
```

백트래킹은 이 상태 공간에서 정답이 될 수 없는 하위 구간을 안전하게 건너뜁니다.

## 1. 상태 공간 크기부터 계산합니다

대표적인 크기는 다음과 같습니다.

- 부분집합: `2^n`
- 순열: `n!`
- 각 위치마다 `k`개 중 하나를 선택: `k^n`
- 깊이 `d`, 최대 분기 수 `b`인 탐색: 최악 `O(b^d)`

입력 제한을 확인하기 전에 재귀 함수를 작성하지 않습니다. 상태 개수와 각 상태를 검사하는 비용을 곱해 전체 비용을 계산합니다.

## 2. 선택, 재귀 호출, 복구

mutable 상태를 공유하는 전형적인 형태는 다음과 같습니다.

```text
search(state):
    if state가 완성되었다면:
        결과를 검사하거나 저장합니다.
        return

    for choice in 가능한 선택:
        choice를 state에 반영합니다.
        search(state)
        choice를 되돌립니다.
```

복구가 빠지면 다음 sibling branch가 이전 branch의 선택을 그대로 물려받습니다. 상태를 매번 복사할 수도 있지만 복사 비용을 포함해 분석해야 합니다.

## 3. 중복 결과를 제거합니다

같은 값이 여러 번 있을 때 index만 다르게 선택하면 같은 결과가 중복해서 생성될 수 있습니다.

다음 방법을 사용할 수 있습니다.

- 먼저 정렬한 뒤 같은 깊이에서는 같은 값을 한 번만 선택합니다.
- 남은 값의 개수를 `value -> count`로 관리합니다.
- 선택 순서를 canonical order로 고정합니다.

중복 제거 조건이 서로 다른 유효한 답까지 합치지 않는지 확인합니다.

## 4. pruning

### 이미 제약을 위반한 경우

현재까지의 선택이 capacity, 합, 충돌 조건을 이미 위반했고 이후 선택으로 회복할 수 없다면 더 내려가지 않습니다.

예를 들어 모든 weight가 양수인 knapsack에서 현재 무게가 capacity를 넘었다면 이후 물건을 더 골라도 유효해질 수 없습니다.

### 최적값을 넘을 가능성이 없는 경우

현재 값과 남은 항목으로 얻을 수 있는 최대 이득을 더해도 기존 최적값을 넘지 못한다면 중단합니다.

```text
current + optimistic_remaining <= best
```

`optimistic_remaining`은 실제로 얻을 수 있는 최대값보다 작아서는 안 됩니다. 지나치게 큰 값은 느리기만 하지만, 너무 작은 값은 정답 branch를 잘라낼 수 있습니다.

### 대칭인 상태를 하나만 탐색하는 경우

서로 이름만 다르고 이후 가능한 선택이 완전히 같은 상태라면 대표 하나만 탐색할 수 있습니다. 두 상태가 실제로 같은 답 집합을 만드는지 설명할 수 있어야 합니다.

## 5. memoization으로 바꿀 수 있는 조건

서로 다른 선택 경로가 이후 결과가 같은 상태에 도달한다면 결과를 저장해 다시 사용할 수 있습니다.

```text
memo key가 미래 결과를 결정하는 모든 정보를 포함합니까?
```

현재 경로의 일부 값이 이후 가능한 선택에 영향을 주는데 key에서 빠지면 잘못된 결과를 재사용합니다. 상태 사이 의존이 cycle 없이 진행되고 최적 부분 문제가 성립하면 dynamic programming으로 정리할 수 있습니다.

## 6. 작은 기준 계산으로 사용하는 완전탐색

작은 입력에서는 단순한 완전탐색이 최적화 구현보다 더 좋은 기준 계산이 될 수 있습니다.

- 구간 선택: 모든 부분집합 중 서로 겹치지 않는 최대 개수
- knapsack: 모든 물건 부분집합 중 capacity 안의 최대 가치
- MST: `V-1`개 간선 조합 중 spanning tree인 최소 가중치
- 최대 유량: 모든 source-side cut의 최소 capacity
- LCS: 짧은 문자열의 모든 subsequence

기준 계산도 별도 테스트가 필요합니다. 후보 구현과 같은 정렬이나 같은 helper를 사용하지 않습니다.

## 7. 예제: N-Queens

상태를 다음과 같이 둘 수 있습니다.

```text
row: 다음에 queen을 놓을 행
used_columns
used_diag_down: row - column
used_diag_up: row + column
```

유지해야 할 조건은 다음과 같습니다.

```text
[0, row) 범위의 각 행에는 queen이 하나 있습니다.
어떤 두 queen도 같은 열이나 대각선에 있지 않습니다.
```

다음 행에서는 충돌하지 않는 열만 선택합니다. 이미 충돌한 상태를 만들지 않으므로 pruning이 정답을 제거하지 않습니다.

## 8. 반복 구현을 선택할 때

재귀 깊이가 입력 크기와 같고 입력 상한이 크다면 명시적인 stack을 사용합니다. stack 항목에는 다음에 시도할 선택 위치와 복구에 필요한 정보를 넣어야 합니다.

재귀 호출을 반복문으로 바꾸는 것만으로 상태 복구가 자동으로 해결되지는 않습니다.

## 연결 구현

[`verified-algorithms`](../../exercises/verified-algorithms/)의 테스트에서 다음 기준 계산을 확인합니다.

- `brute_knapsack`: 물건의 모든 부분집합을 검사합니다.
- `brute_interval_count`: 모든 구간 부분집합을 검사합니다.
- `brute_mst_weight`: 가능한 `V-1`개 간선 조합을 검사합니다.
- `brute_min_cut`: 모든 source-side 정점 집합을 검사합니다.
- `brute_lcs_length`: 짧은 문자열의 모든 subsequence를 검사합니다.

이 함수들은 작은 입력에서만 실행되며, 실제 알고리즘과 다른 방식으로 결과를 계산합니다.

## 완료 기준

- 선택 수와 깊이로 상태 공간의 상한을 계산합니다.
- 재귀 호출 전후에 mutable 상태가 정확히 복구되는지 손으로 추적합니다.
- 각 pruning 조건이 유효한 답을 제거하지 않는 이유를 적습니다.
- 중복 제거가 서로 다른 답까지 없애지 않는지 확인합니다.
- 기준 계산과 후보 구현이 핵심 상태 전이를 공유하지 않게 합니다.

## 실패 신호

- 상태 공간 크기를 계산하지 않고 재귀부터 작성합니다.
- mutable 상태를 복구하지 않습니다.
- 중복 제거 조건이 서로 다른 답을 합칩니다.
- optimistic bound가 실제 가능한 최대 이득보다 작습니다.
- memo key에서 이후 결과에 필요한 값을 빠뜨립니다.
- 기준 계산이 후보와 같은 알고리즘을 사용합니다.
