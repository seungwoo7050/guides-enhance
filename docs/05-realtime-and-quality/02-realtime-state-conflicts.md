# 실시간 상태와 충돌

두 사용자가 같은 항목을 거의 동시에 바꾸면 모든 메시지가 같은 순서로 도착한다고 가정할 수 없습니다. 서버가 확정한 값과 이동 중인 임시 값, 클라이언트 화면만의 값을 구분하고, 시퀀스와 버전으로 누락과 오래된 쓰기를 찾아야 합니다.

## 목표

- 서버를 확정 상태의 기준으로 둡니다.
- 스냅샷, 패치, 시퀀스와 버전을 구분합니다.
- 드래그 중 좌표와 최종 좌표를 다르게 처리합니다.
- 중복·누락·순서 역전과 오래된 쓰기에서 복구합니다.
- 낙관적 변경이 실패했을 때 사용자 입력을 보존합니다.

## 세 종류의 상태

```text
영속 상태 → 항목 내용·최종 좌표·버전, 데이터베이스 저장
임시 상태 → 커서·드래그 중 좌표, 서버 메모리 저장
화면 상태 → 선택·호버·대화 상자·초안, 브라우저 저장
```

모든 포인터 이동을 데이터베이스에 쓰면 저장과 감사 기록이 지나치게 많아집니다. 최종 좌표까지 메모리에만 두면 서버 재시작 뒤 사라집니다.

## 스냅샷과 패치

스냅샷은 특정 시점의 전체 상태입니다.

```ts
interface BoardSnapshot {
  boardId: string;
  sequence: number;
  version: number;
  items: BoardItem[];
}
```

패치는 그 이후 서버가 확정한 한 변경입니다.

```ts
interface BoardPatch {
  boardId: string;
  sequence: number;
  operationId: string;
  actorId: string;
  operation: ItemCreated | ItemUpdated | ItemMoved;
}
```

클라이언트는 마지막으로 적용한 `sequence`를 기억합니다.

## 시퀀스로 누락 확인

```text
sequence <= lastSequence     → 중복 또는 오래된 패치, 무시
sequence == lastSequence + 1 → 정상 적용
sequence > lastSequence + 1  → 중간 누락, 적용 중단 후 스냅샷 요청
```

시퀀스는 네트워크 도착 순서가 아니라 서버가 확정한 방 전체 변경 순서입니다.

## 버전으로 오래된 쓰기 확인

사용자가 버전 4를 보고 수정했다면 `baseVersion: 4`를 보냅니다.

```sql
update board_items
set x = $1,
    y = $2,
    version = version + 1
where id = $3
  and version = $4
returning *;
```

반환된 행이 없으면 이미 다른 변경이 반영된 것입니다. 마지막으로 도착했다는 이유만으로 덮어쓰지 않고 최신 항목이나 스냅샷을 보냅니다.

- 시퀀스: 방 전체 패치의 누락과 순서 확인
- 버전: 한 항목을 오래된 값으로 수정하는지 확인

## 드래그 중과 완료

```text
pointermove
→ 브라우저가 전송 빈도 제한
→ item.move(final=false)
→ 서버가 좌표 범위 확인
→ 방에 임시 좌표 전송

pointerup
→ item.move(final=true, baseVersion)
→ 조건부 UPDATE와 이벤트 저장
→ 확정 패치 전송
```

임시 좌표는 미리보기만 바꿉니다. 확정 패치가 오면 영속 상태를 갱신하고 미리보기를 제거합니다. 드래그 중 연결이 끊기면 임시 값을 버리고 마지막 확정 좌표를 유지합니다.

## 낙관적 화면 변경

서버 응답 전에 화면을 바꾼다면 작업별 정보를 보관합니다.

```ts
interface PendingOperation {
  operationId: string;
  itemId: string;
  baseVersion: number;
  optimisticValue: unknown;
  previousValue: unknown;
}
```

같은 `operationId`의 확정 패치가 오면 대기 상태를 제거합니다. 거부되면 이전 값 또는 최신 스냅샷으로 복구하고 사용자가 다시 시도할 수 있게 합니다.

사용자의 초안과 서버의 최신 값을 별도로 보관하면 충돌 뒤 입력을 잃지 않습니다.

## 중복 작업

재시도와 재연결로 같은 `operationId`가 다시 올 수 있습니다.

```text
처음 받은 ID             → 처리하고 결과 기록
같은 ID·같은 내용        → 이전 결과 재사용
같은 ID·다른 내용        → 형식 위반 또는 충돌
```

커서처럼 임시 이벤트까지 영구 저장할 필요는 없습니다. 중복 효과가 위험한 작업에만 필요한 기간 동안 기록합니다.

## 재연결 복구

클라이언트가 오프라인인 동안 변경이 발생했다면 다음 중 하나를 사용합니다.

- 마지막 시퀀스 이후 패치 재전송
- 최신 스냅샷 전체 전송

작은 시스템에서는 스냅샷이 단순합니다. 데이터가 커지면 이벤트 보관 기간과 스냅샷 크기를 함께 고려합니다.

## 삭제 뒤 늦은 메시지

항목 삭제 뒤 오래된 수정 메시지가 올 수 있습니다. 서버는 현재 항목 존재 여부와 버전을 확인해 삭제된 항목이 다시 생기지 않게 합니다. 이벤트 재생이 필요하다면 삭제 이벤트를 일정 기간 보관합니다.

## 타임스탬프는 전체 순서가 아닙니다

클라이언트의 `Date.now()`나 서로 다른 서버의 시계만으로 전체 변경 순서를 정하지 않습니다. 시각은 표시와 감사에 사용하고 변경 순서는 서버 시퀀스와 트랜잭션 결과로 정합니다.

## 연결 중 권한 변경

사용자가 `editor`에서 `viewer`로 바뀔 수 있습니다.

- 새 역할을 데이터베이스에 저장합니다.
- 연결된 클라이언트에 새 스냅샷이나 역할 변경을 알립니다.
- 이후 쓰기마다 현재 역할을 다시 확인합니다.
- 이미 화면에 적용한 임시 변경은 되돌립니다.

연결할 때 읽은 역할을 연결이 끝날 때까지 고정하지 않습니다.

## 흔한 실수

- 클라이언트 값을 최종 기준으로 사용합니다.
- 시퀀스와 항목 버전을 같은 값으로 사용합니다.
- 드래그 중 모든 좌표를 데이터베이스에 저장합니다.
- 패치가 누락되었는데 이후 패치를 계속 적용합니다.
- 오래된 쓰기를 마지막 도착 값으로 덮어씁니다.
- 충돌 뒤 사용자 초안을 버립니다.
- 타임스탬프로 전체 순서를 정합니다.

## 완료 기준

- 영속·임시·화면 상태의 저장 위치를 구분합니다.
- 스냅샷, 패치, 시퀀스와 버전의 역할을 설명합니다.
- 누락·중복·오래된 쓰기에서 복구합니다.
- 드래그 미리보기와 최종 저장을 나눕니다.
- 낙관적 변경의 승인·거부·되돌리기를 구현합니다.
