# 프로세스·파일 디스크립터·파이프

`fork`, `exec`, `pipe`, `dup2`를 함께 사용할 때는 각 프로세스가 어떤 파일 디스크립터를 사용하고 언제 닫는지 먼저 정해야 합니다. 출력이 맞는지만 확인하면 작은 입력에서는 우연히 동작하다가 큰 입력이나 EOF에서 멈출 수 있습니다.

## `fork`

```c
pid_t pid = fork();
```

```text
pid > 0   부모, 값은 자식 PID
pid == 0  자식
pid == -1 실패
```

자식은 부모의 주소 공간과 파일 디스크립터 표를 복사한 상태에서 시작합니다. 커널이 관리하는 같은 열린 파일 상태를 참조할 수 있지만, 각 프로세스는 자신의 파일 디스크립터 번호를 직접 닫아야 합니다.

## `exec`

```c
execvp(argv[0], argv);
```

성공하면 현재 프로세스의 프로그램이 새 프로그램으로 바뀌므로 호출 지점으로 돌아오지 않습니다. 반환했다면 실패입니다.

```c
execvp(argv[0], argv);
int saved_errno = errno;
_exit(saved_errno == ENOENT ? 127 : 126);
```

자식에서는 `exit`보다 `_exit`를 사용해 부모에서 복사된 stdio 버퍼를 다시 출력하지 않도록 합니다.

일반적으로 다음 종료 상태를 사용할 수 있습니다.

```text
127  명령을 찾지 못함
126  파일은 찾았지만 실행할 수 없음 또는 그 밖의 `exec` 실패
```

## `waitpid`

부모는 자식의 종료를 회수해야 합니다.

```c
int status;
pid_t result;

do {
    result = waitpid(pid, &status, 0);
} while (result == -1 && errno == EINTR);
```

상태 매크로로 종료 원인을 해석합니다.

```c
if (WIFEXITED(status)) {
    return WEXITSTATUS(status);
}
if (WIFSIGNALED(status)) {
    return 128 + WTERMSIG(status);
}
```

`128 + signal`은 셸에서 흔히 사용하는 공개 표현이지만 POSIX가 모든 프로그램에 강제하는 규칙은 아닙니다. 프로그램이 어떤 값을 반환할지 명시합니다.

## `pipe`

```c
int ends[2];
if (pipe(ends) == -1) {
    return -1;
}
```

```text
ends[0]  읽기 끝
ends[1]  쓰기 끝
```

파이프는 바이트 스트림입니다. 쓰기 끝을 가진 모든 프로세스가 이를 닫아야 읽는 프로세스가 EOF를 확인할 수 있습니다.

## `dup2`

```c
dup2(ends[1], STDOUT_FILENO);
```

왼쪽 명령의 stdout을 파이프 쓰기 끝에 연결할 수 있습니다. 오른쪽 명령은 파이프 읽기 끝을 stdin에 연결합니다.

`source == destination`이면 `dup2`는 성공하지만, 이후 source를 무조건 닫으면 실제 표준 스트림까지 닫을 수 있습니다. 닫혀 있던 표준 FD 번호를 `pipe`가 재사용할 수 있기 때문입니다.

## 두 명령 연결

```text
부모
├── 왼쪽 자식
│   stdin  → 기존 stdin
│   stdout → 파이프 쓰기 끝
└── 오른쪽 자식
    stdin  → 파이프 읽기 끝
    stdout → 기존 stdout
```

### 왼쪽 자식

```text
dup2(write_end, STDOUT_FILENO)
read_end 닫기
복제 후 필요 없는 write_end 닫기
exec
```

### 오른쪽 자식

```text
dup2(read_end, STDIN_FILENO)
write_end 닫기
복제 후 필요 없는 read_end 닫기
exec
```

### 부모

```text
read_end 닫기
write_end 닫기
두 자식 waitpid
```

부모가 쓰기 끝을 계속 열어 두면 오른쪽 자식은 왼쪽 자식이 끝난 뒤에도 EOF를 받지 못할 수 있습니다.

## 두 자식을 시작한 뒤 기다리기

왼쪽 자식이 파이프 용량보다 많은 데이터를 쓰는데 부모가 오른쪽 자식을 만들기 전에 왼쪽을 기다리면 교착 상태가 생길 수 있습니다.

```text
왼쪽 자식: 파이프가 가득 차 write에서 대기
부모: 왼쪽 자식이 끝나기를 대기
오른쪽 자식: 아직 생성되지 않아 pipe를 읽지 못함
```

따라서 두 자식을 모두 생성하고 부모의 파이프 끝을 닫은 뒤 기다립니다.

## 부분 `fork` 실패

왼쪽 자식은 생성했지만 오른쪽 `fork`가 실패할 수 있습니다. 이때 이미 생성한 자식을 남겨 두면 안 됩니다.

```text
부모의 파이프 끝 닫기
→ 왼쪽 자식 종료 요청
→ waitpid로 회수
→ 오류 반환
```

어떤 시그널로 종료할지, 자식이 이미 끝난 경우를 어떻게 처리할지 정합니다.

## 파일 디스크립터 누수 확인

같은 함수를 반복 호출했을 때 열린 파일 디스크립터 수가 늘지 않아야 합니다. Linux의 `/proc`, `fcntl` 반복 검사 또는 leak 검사 도구를 사용할 수 있습니다.

작은 테스트에서는 파일 디스크립터를 여러 번 세어 호출 전후가 같은지 비교할 수 있습니다. 다만 다른 스레드나 라이브러리가 동시에 파일 디스크립터를 열면 이 방법의 전제가 깨집니다.

## 프로세스 그룹

여러 자식에게 하나의 시그널을 전달해야 한다면 프로세스 그룹을 사용할 수 있습니다. 그룹 설정 시점과 부모·자식 중 누가 `setpgid`를 호출하는지 정해야 경쟁을 줄일 수 있습니다.

단순한 두 명령 파이프에서는 필수는 아니지만 대화형 프로그램과 작업 제어을 다룰 때 중요합니다.

## 테스트할 내용

- 파이프 용량보다 큰 데이터
- 빈 출력
- 왼쪽 명령 실패, 오른쪽 명령 성공
- 오른쪽의 일반 종료 상태
- 시그널 종료
- 없는 명령과 실행 권한 없는 파일
- stdin 또는 stdout이 닫혀 FD 0·1이 재사용되는 경우
- 반복 실행 뒤 파일 디스크립터 수
- `NULL` argv와 빈 `argv[0]`

## 완료 기준

1. `fork`의 세 반환 경우를 처리합니다.
2. 자식의 `exec` 실패를 `_exit`로 끝냅니다.
3. 부모와 두 자식이 사용하지 않는 파이프 끝을 닫습니다.
4. 두 자식을 모두 시작한 뒤 기다리는 이유를 설명합니다.
5. `waitpid` 결과를 일반 종료와 시그널 종료로 나눕니다.
6. 두 번째 `fork` 실패 시 첫 자식을 회수합니다.
7. 표준 FD 번호가 재사용되어도 최종 stdin/stdout을 닫지 않습니다.
