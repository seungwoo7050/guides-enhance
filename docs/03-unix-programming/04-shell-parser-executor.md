# 명령 문자열 파싱과 실행

명령 문자열을 실행하려면 먼저 문자열을 `argv` 배열로 바꾸고, 전체 문법이 유효한지 확인한 뒤, 그 결과로 자식 프로세스를 만들어야 합니다. 파싱 도중 바로 `fork`하면 뒤에서 문법 오류가 발견되어도 이미 외부 프로그램의 부수효과가 발생할 수 있습니다.

## 처리 순서

```text
문자 단위로 읽기
→ 단어와 제어 토큰 구분
→ 전체 문법 검사
→ 각 명령의 `argv` 구성
→ 모든 문법이 성공한 뒤 fork/exec
→ 자식 회수
→ argv 메모리 해제
```

## 단어 버퍼

한 단어의 길이를 미리 알 수 없으면 동적 버퍼를 사용합니다.

```c
struct builder {
    char *data;
    size_t length;
    size_t capacity;
};
```

문자를 추가하기 전에 `length + 1`과 마지막 NUL 바이트를 포함한 크기를 검사합니다. `realloc`이 성공한 뒤에만 `data`와 `capacity`를 바꿉니다.

## 따옴표와 escape 처리

지원 규칙을 먼저 정합니다.

```text
인용되지 않은 공백  단어 구분
작은따옴표            닫는 작은따옴표까지 문자 그대로 보존
큰따옴표              닫는 큰따옴표까지 읽음
역슬래시              다음 문자 하나를 일반 문자로 처리
붙어 있는 인용 조각   같은 단어로 연결
'' 또는 ""            길이 0인 인자 생성
```

예시:

```text
one 'two three' "" ab"cd" escaped\ space
```

결과:

```text
one
two three
빈 문자열
abcd
escaped space
```

따옴표가 한 글자도 만들지 않아도 단어가 시작되었다는 상태를 따로 기록해야 빈 인자를 보존할 수 있습니다.

## 제어 토큰

예를 들어 파이프 하나만 지원한다면 인용되지 않은 `|`만 제어 토큰으로 처리합니다.

```text
명령 | 명령
```

인용되거나 escape 처리된 `|`는 일반 문자입니다.

```text
'a|b'
a\|b
```

지원하지 않는 `<`, `>`, `;`, `&`를 조용히 일반 문자로 넘기지 않습니다. 문법 오류로 반환할지, 실제 기능을 구현할지 정합니다.

## 명령 데이터의 메모리 소유권

```c
struct command {
    char **argv;
    size_t argc;
    size_t capacity;
};
```

각 단어를 새로 할당하고 `argv` 배열에서 참조할 수 있습니다. `argv[argc] == NULL`을 항상 유지하면 `execvp`에 바로 전달할 수 있습니다.

정리 함수는 다음을 수행합니다.

```text
argv[0]부터 argv[argc - 1]까지 free
→ argv 배열 free
→ argc와 capacity를 0으로 변경
```

파싱에 실패하면 지금까지 만든 모든 명령 데이터를 정리합니다.

## 전체 파싱 후 반영하기

파서가 출력 구조체를 직접 부분적으로 채우다가 실패하면 호출자가 무엇을 정리해야 하는지 복잡해집니다. 임시 명령 데이터을 만들고 전체 입력이 성공했을 때만 호출자에게 넘기는 방법이 안전합니다.

파싱 실패 시 외부 프로그램을 실행하지 않는다는 조건도 함께 지킵니다.

테스트에서는 파일을 만드는 보조 명령를 문법 오류 입력 앞에 배치하고 표시 파일이 생성되지 않았는지 확인할 수 있습니다.

## 단일 명령 실행

```text
fork
→ 자식: execvp
→ 부모: waitpid
→ exit status 변환
```

없는 명령은 127, 실행할 수 없는 파일은 126, 시그널 종료는 `128 + signal`로 반환하도록 정할 수 있습니다.

## 파이프 실행

파이프가 있으면 두 자식을 모두 생성하고 사용하지 않는 FD를 닫은 뒤 기다립니다. 공개 종료 상태는 마지막 명령의 상태로 정할 수 있습니다.

왼쪽 명령의 실패가 오른쪽 명령의 성공 상태를 덮지 않도록 어떤 자식의 상태를 반환할지 명시합니다.

## 오류 종류 나누기

```text
사용법 오류          → 상태 2
문법 오류            → 상태 2, 외부 명령 실행 안 함
fork/pipe/wait 실패  → 상태 125 같은 내부 실행 오류
exec 대상 없음       → 자식 상태 127
exec 권한·형식 오류  → 자식 상태 126
일반 명령 종료       → 해당 종료 상태
시그널 종료          → 128 + signal
```

프로그램이 사용할 값은 다를 수 있지만 서로 다른 실패를 구분할 수 있어야 합니다.

## 긴 파이프와 FD 재사용

파이프 용량보다 큰 데이터를 전달해 교착 상태가 없는지 확인합니다. 또한 stdin이나 stdout을 닫은 자식에서 `pipe`가 FD 0 또는 1을 반환하는 경우를 테스트합니다.

`dup2` 원본과 대상이 같을 때 원본을 다시 닫지 않아야 합니다.

## 범위 제한하기

작은 명령 실행기는 다음 기능을 의도적으로 제외할 수 있습니다.

- 환경 변수 확장
- 명령 치환
- glob 패턴 확장
- 입출력 재지정
- 논리 연산자
- 여러 개의 파이프
- 작업 제어
- 대화형 프롬프트

지원하지 않는 기능을 애매하게 일부 처리하지 않고 명시적으로 거부합니다.

## 테스트할 내용

- 작은따옴표, 큰따옴표와 escape
- 따옴표로 만든 빈 인자
- 붙어 있는 인용 구간
- 인용된 제어 문자
- 열린 따옴표와 끝의 역슬래시
- 빈 명령과 빈 파이프 양쪽
- 지원하지 않는 연산자
- 문법 오류 뒤 외부 부수효과가 없는지
- 일반·126·127·시그널 종료 상태
- 파이프 용량보다 큰 데이터
- 표준 FD 0·1 재사용

## 완료 기준

1. 빈 인자를 보존하면서 단어를 나눕니다.
2. 인용된 제어 문자를 일반 문자로 전달합니다.
3. 전체 문법이 성공하기 전에 자식을 만들지 않습니다.
4. 명령 객체가 각 단어와 `argv` 배열을 정리합니다.
5. 단일 명령과 파이프의 종료 상태를 반환합니다.
6. 지원하지 않는 문법을 명시적으로 거부합니다.
