HTTP 상태 코드는 요청 결과를 짧게 전달하지만, 숫자 하나만으로 사용자에게 보여 줄 문장이나 재시도 여부가 자동으로 결정되지는 않습니다. 호출하는 코드가 상태 범위와 응답 본문을 함께 해석해야 합니다.

## 실패 종류를 먼저 나눕니다

- `400` 계열은 요청 내용, 인증 상태 또는 권한을 다시 확인합니다.
- `404`는 자원이 없다는 뜻이며, 같은 요청을 반복해도 해결되지 않는 경우가 많습니다.
- `409`는 현재 서버 상태와 요청이 충돌했음을 나타냅니다. 최신 값을 다시 읽고 사용자의 입력을 보존해야 할 수 있습니다.
- `429`는 요청 빈도를 줄이거나 `Retry-After`를 확인합니다.
- `500` 계열은 서버가 요청을 처리하지 못한 경우입니다. 안전한 요청이라면 제한된 횟수로 재시도할 수 있습니다.

## 재시도 조건을 확인합니다

`GET`처럼 같은 요청을 반복해도 서버 상태를 바꾸지 않는 요청은 비교적 안전하게 재시도할 수 있습니다. 반면 결제나 생성 요청은 서버가 idempotency key를 지원하는지 먼저 확인해야 합니다.

```text
상태 코드 확인
→ 응답 본문 형식 확인
→ 사용자의 다음 행동 결정
→ 재시도 가능 여부 결정
```

## 화면에 남길 값을 정합니다

목록을 다시 불러오는 요청이 실패했다고 마지막 정상 목록까지 지울 필요는 없습니다. 오류를 알리되 사용자가 보던 데이터와 입력값을 유지하면 재시도하거나 조건을 고칠 수 있습니다.
